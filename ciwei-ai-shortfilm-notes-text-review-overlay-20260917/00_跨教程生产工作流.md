# 从 13 篇技巧到一条能交接的生产流程

> 本文件是本次综合设计，不是原教程逐字内容，也不是经过实片生产验证的软件系统。它的目的，是避免不同教程里的局部技巧彼此打架。

## 一条镜头真正需要的链路

**批准故事→镜头任务→必要资产与状态→输入模式及参考分工→起始画面／空间预演→行动与声音→生成试验→可用区间→剪辑、颜色和声音验收。**

不要求每个镜头都跑一遍复杂流程。固定单人镜头可以跳过三维预演；无对白镜头不需要 TTS；不参与剧情的背景物件不必单独建资产。复杂度由需要解决的问题决定。

## 1. 从信息与情绪开始，不从模型开始

先写“观众在这一镜之后知道了什么、感受到什么变化”。区分必须讲明的事实与允许保持模糊的部分。没有镜头任务，就无法判断低机位、辉光、风铃或额外道具是在帮助还是干扰。

故事与台词一旦批准，后续环节只实现这版，不擅自新编。发现不可行时提出最小修改，说明影响，再更新批准版本。不把一个生成模型临时补出的动作自动当成新的剧情事实。

## 2. 资产库保存依据，当次请求只拿必要信息

身份、造型、状态、声音、场景布局、关键道具分开保存。镜头记录引用批准版本，不重新写出一套“差不多”的人物描述。库里可以存在探索候选，但执行输入只含当前方案。

如果当前工具没有引用 ID 的功能，就把 ID 当成内部索引，在提交前映射到实际文件。没有被上传或正确绑定的资产，不算已经进入生成。

## 3. 先处理输入冲突，再写漂亮提示词

首帧图、身份参考、场景参考、动作／运镜视频和风格参考的职责不同。根据工具支持的模式实际设置它们。首帧已经包含某个姿态或光线时，要求立即变成另一种姿态／重打光，可能是在增加额外重建任务，应有意识地选择。

多图中有不同服装、不同房间或同一编号多重含义时，先撤下冲突素材。不存在能用一句“保持一致”修复一切矛盾的万能开头。

## 4. 给行动留弹性，但锁住关键因果

把人物行动写成起点、主要变化、结果。人物心理负责说明为什么，动作负责让它可见。主要动作之外的衣料跟随和呼吸，不必按每一帧安排。

涉及拿取、交换、碰撞、背负、物件变湿或被破坏时，明确对象、接触和最终状态。这些不是“过度防御”；真正多余的是对普通走路的每块肌肉写一套规则，却没说明交接的信到底在谁手里。

## 5. 摄影、美术、灯光、声音共同服务一个目标

摄影决定观看位置和揭示顺序，美术提供可见世界，灯光引导注意与体积，表演呈现人物选择，声音提供触发、关系和空间。它们不能各自追求最强效果。

例如：一个人物压住情绪的镜头，可以使用固定平视、干净光线和极少声音；另一个主观慌乱镜头可以需要较强运动。两者都可能成立，不能用“低角度＋晃动＋微表情＋轮廓光＋风铃”作为统一完成标志。

## 6. 先做最难局部，再扩大长度与资产量

挑最容易失败且最影响叙事的一段：换信、手部近景、人物背负、走出遮挡、前后摄视点切换等。验证输入与动作是否足够，再生成完整段落或扩展更多镜头。

一次只修改最可能相关的变量，并记录其他条件。不同工具没有同等控制条件时，承认比较并非完全等价。不要挑不同场景的最好结果，宣称某个单词或模型永远更好。

## 7. 素材终态以实际输出为准

目标是“人物拿到信”不等于实际素材已经拍到拿信。镜头生成后，检查可用区间的最终姿态、道具归属、位置与可见信息。下一镜接的是实际批准素材，不是失败请求中的愿望。

发现结尾不符合下一镜时，选择重新生成、修改下一镜方案或重新剪辑；不要让下游默默重判剧情，从而形成两套终态。可用片段也要保留合理的前后余量和音频衔接。

## 8. 成片验收，而不是关键词验收

最终检查：事件能否看懂、身份是否连续、物件数量和归属是否正确、空间与光线是否合理、声音是否准确、剪口是否保留因果、产品和文字是否达到交付要求。美感目标依据项目风格判断，不等于越真实越好或越华丽越好。

## 常见“技巧冲突”的正确解决

| 表面冲突 | 解决方式 |
| --- | --- |
| 自动发挥动作 vs 精细描述物理过程 | 普通细节允许弹性，剧情关键接触与结果明确写出 |
| 多角度资产库 vs 少量参考输入 | 完整准备、按镜头选择；不一次上传全部历史版本 |
| 固定平视 vs 低机位手持 | 按观看关系与事件选择，不建立优劣等级 |
| 生活化手机质感 vs 电影摄影风格 | 两种观看约定，各自服务内容，不用“实拍感”吞掉全部风格 |
| 反向表演 vs 外放情绪 | 按人物目标和类型选择，克制并非万能 |
| 图像启发小剧情 vs 统一剧本 | 探索产生候选，批准后执行；不给下游持续改编权 |
| 原生音频 vs 后期配音 | 按工具与镜头任务分工；台词、时间、环境最后统一验收 |
| 颜色／焦距／秒数写进文字 vs 实际参数 | 可见描述与界面／请求参数分别落实，冲突时先修正而非双重下令 |
| 素材有瑕疵 vs 剪掉破绽 | 可裁掉非必要区间，不能裁掉剧情关键事件还称通过 |

## 最小镜头卡〔内部制作记录〕

```text
shot_id: [镜头编号]
story_version: [批准故事版本]
viewer_change: [观众需要知道／感受到的变化]
start_state: [实际起点]
end_state_required: [剧情要求的终点]
references: [实际文件、批准版本、每份用途]
generation_mode: [实际工具与模式]
action: [主动作、关键接触、必要的次级动态]
camera_and_light: [本镜头必要的观看与照明约束]
audio: [批准台词、环境、音效、配乐安排]
output_settings: [实际支持的画幅、时长、分辨率等]
acceptance: [镜头特有的可检查条件]
```

执行后记录实际模型版本、请求设置、素材位置、投入与可用区间，以及批准素材的实际终态。只记你真正取得的数据，不推算截图中的额度为制作成本，不把模板字段存在当成已执行。

这张卡不要求整张复制给模型。提示词使用必要的描述；工具配置使用真实参数；编辑和 QC 使用同一任务与批准依据。没有消费者的字段不必添加，已知事实不在每个环节复制成互相矛盾的多份文本。
