# 技术依据与术语校正

资料访问日期：2026-09-17。这里只列本次用于校准关键技术说法的第一方资料。它们支持明确、有限的结论，不用于证明全部教程的结果有效。链接内容以后可能更新，本包不承诺包含网页的固定快照。

## T01｜图生视频中，起始图与文本职责不同

[Runway：Image to Video Prompting Guide](https://help.runwayml.com/hc/en-us/articles/48324313115155-Image-to-Video-Prompting-Guide)

官方指南将输入图作为视觉起点，文本主要描述运动与变化，并建议从关键要素开始迭代。可据此反对“参考图可以完全忽略构图、光线，文本总能覆盖一切”的泛化。

**边界**：这是 Runway 的相关指南，不是 Seedance、Kling 或所有多模态参考模式的通用参数合同。本包据此提出“确认真实模式、参考职责与起始图冲突”的制作建议，不移植其具体容量、时长或引用语法。

## T02｜参考媒体需要按模型和模式绑定

[Runway：Using reference media to guide your generations](https://help.runwayml.com/hc/en-us/articles/52963720640275-Using-reference-media-to-guide-your-generations)

该页面说明不同模型支持不同的参考媒体与用法。它支持“实际绑定比仅写一个角色 ID 更重要”的使用提醒，不证明多个参考一定不会冲突，也不保证引用后逐像素一致。

## T03｜配音停顿不是跨模型统一语法

[ElevenLabs：How can I add pauses?](https://elevenlabs.io/docs/help-center/product/core-capabilities/text-to-speech/how-can-i-add-pauses)

[ElevenLabs：Do pauses and SSML phoneme tags work with the API?](https://elevenlabs.io/docs/help-center/technical/do-pauses-and-ssml-phoneme-tags-work-with-the-api)

资料区分 Eleven v3 的音频标签，与支持 SSML break 的其他相关模型；也指出标点控制较不稳定、声音选择会影响结果。因此第 02 组不把省略号当成精确秒点，也不提供“所有 TTS 通用”的 break 指令。

**边界**：这不是其他供应商的能力说明。正式任务要核对实际 TTS 产品、模型、语言与输入字段，精准落点还要检查生成音频。

## T04｜灯光强度、尺寸与阴影软硬不是一回事

[Blender Manual：Light Objects，英文 3.3 版](https://docs.blender.org/manual/en/3.3/render/lights/light_object.html)

[Blender Manual：Light Objects，5.2 版页面](https://docs.blender.org/manual/id/5.2/render/lights/light_object.html)

手册分别说明光源功率、半径和不同灯光类型；较大的发光尺寸对应较柔和阴影。它也区分聚光光束边缘与物体阴影软硬。这里引用稳定的照明概念，不要求用户使用这些特定软件版本。

由此校正第 13 组“硬光必须穿过遮挡物”的说法：百叶窗决定阴影图案，不是硬光成立的必要条件。几何、距离和表观光源大小等关系仍需考虑，不能只靠一个“强”字。

**边界**：Blender 的照明模型并不证明视频生成器内部执行同样的物理计算。本包的光线提示词描述期望的可见结果，仍需检查成片。

## T05｜Kodak 500T 不宜简化标成“日光胶片”

[Kodak：VISION3 500T Color Negative Film 5219/7219](https://www.kodak.com/en/motion/product/camera-films/500t-5219-7219/)

官方产品页标明 500T，并单列日光使用的色彩平衡滤镜建议。第 06 组 OCR 中的“500T 日光胶片”不能原样作为准确产品分类。在提示词里使用胶片名字也不代表素材真正经历该胶片的曝光、冲洗或扫描。

本次没有测量任何生成画面的胶片特征，也没有用胶片型号推定画面已经具有某种色彩科学。

## T06｜Codex 的职责是辅助执行代码工作

[OpenAI：Codex CLI](https://developers.openai.com/codex/cli/)

官方文档说明 Codex CLI 可以在项目中检查、修改代码并运行命令。第 01 组据此把它定位为预演制作的编程助手，而不是视频模型的确定性运镜接口。实际权限、软件依赖、可运行命令与输出文件要在使用环境中检查。

本包没有安装或运行 Codex／Blender 的预演工程，没有给出经执行验证的脚本，不将教程界面上的模型显示当成当前最佳型号推荐。

## 本次主动撤下的“伪精确”说法

| 说法 | 处理 |
| --- | --- |
| 词元按顺序输出，因此人物动作一定先于后写的摄影机指令 | 缺少适用于所述视频系统的机制证据，不作为原理 |
| 图片在所有系统中的权重最高 | 缺少统一权重定义，不泛化 |
| 模型害怕阴影，因为训练图都提亮过 | 没有相关训练数据证据，不保留因果结论 |
| 当前某模型永远负责审美、某模型永远负责精修 | 未做当前任务的统一测试，仅记录教程偏好 |
| 秒数、镜头品牌、色值写出就会精确实现 | 区分创作目标、可见描述、原生参数与实际测量 |
| 一张截图能证明声音自然或运镜无穿帮 | 截图不包含完整时间／声音信息；本次更未读取像素 |
| 未核实的摄影师引言可以作为技术依据 | 不采用署名背书，保留疑点 |

## 证据的阅读顺序

确认教程说了什么，优先回到固定版本原材料与对应截图／音频；确认产品怎么用，查该产品第一方文档；评价方法是否适合项目，做清楚边界的实际试验。三者不能互相替代。

这些校正之外的镜头卡、状态交接、道具占手、对照测试和剪辑建议属于本次综合设计。它们有明确的工作逻辑，但没有在本次任务中获得实片成功率数据，不能对外宣称已实测最优。
