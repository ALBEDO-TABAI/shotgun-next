# 02 · 子 agent、角色与 skill

最后更新：R3（2026-09-17）
本轮变化：新增"上下文区隔与对齐"原则；导演一行加入合并裁决节点（D-18）；资源库的取用角色（D-17）；待定项更新。

## 基本关系

- **[用户]** 应用需要的是**多个子 agent**，每个子 agent 有各自的 skill 与工作任务。现有的 9 个 skill 是已按真实角色做过的 skill 化工作，是起点，不是全集；真实创作过程还需要更多 skill、数据库、数据内容。
- **[建议]** 术语：
  - **角色（role）**：一个工种身份（编剧、导演…）。
  - **节点（node）**：工作流里某个角色在某个阶段的一次工作单元，拥有一个 agent 会话与一份或多份工件。同一角色可能在不同阶段出现多个节点（如声音：初稿 / 按时间轴定稿）。
  - **skill**：角色加载的方法包（SKILL.md + references + assets + scripts），一个角色可加载多个 skill。
  - **子 agent**：节点背后运行的会话实例。

## 上下文区隔与对齐（原则）

- **[用户 R3]** 各子 agent 的上下文是**区隔**的。只有一开始对齐了用户的初步需求，每个子 agent 的初步工作才有一个粗略方向，事情才能往同一个方向发展。
- **[建议]** 由此得出两条设计约束：
  1. **对齐靠工件，不靠共享聊天。** 子 agent 之间不互相读聊天记录；它们读的是第一张纸上的工种任务单、上游 ready 工件、项目资源库、项目风格档案。这四样是"共同语言"。
  2. **任务单是每个节点的开场输入。** 节点 thawing 时，agent 拿到的是：自己的任务单 + `depends_on` 的 ready 工件 + 资源库索引 + 风格档案；不拿别人的聊天。

## 制片的重定义

- **[用户]** 原 skill 偏真实影视制作；AI 制片流程里没有资源与排期。预算按 **token 开销、生图、生音乐、生视频** 做成本核算与估算。
- **[建议]** 制片节点在 shotgun 中的职责：
  1. 维护**价格表**（按 provider / 模型 / 单位计价，带日期）。
  2. fire 前按生成清单给**估算**（镜头数 × 单元时长 × 单价 + 参考图生成 + 音乐）。
  3. 运行中汇总**实际开销**（agent token 用量 + 生成调用），按节点归因。
  4. 提示**取舍**：例如某镜头返工第 3 次时提示累计成本；或建议先低质量草稿生成再高质量。
- **[建议]** 现有 vvf-producer skill 中"资源拆解 / 排期 / 试验与取舍"的方法论大部分不再适用，需要写一个面向 AI 生成的制片 skill（或大幅裁剪）。列入缺口。

## Critic 归属

- **[用户]** 每个分支 agent 的 critic 由对应 agent 自己完成；后续可能设计独立的 critic skills。
- **[建议]** 风险：模型给自己打分偏宽松（R1 已提，旧 dossier 也强调）。在"同一 agent 承担"的前提下可以做的最小隔离：
  - critic 作为**独立的一轮**运行，加载 critic skill、不带"我刚写的很好"的惯性；
  - 如果运行时支持 fork（codex `thread/fork` 支持，见 06），critic 在 fork 出来的分支里跑，输出结论后合并回主线，主线只看到结论不看到 critic 的推理；
  - critic 结论用固定格式（可观察症状 → 影响 → 修法 → 验收条件），与导演 skill 的质量审阅 / 生成审片格式一致。
- 独立 critic skill 的设计列入缺口。
