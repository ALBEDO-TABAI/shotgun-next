# 04 · 交互与界面

最后更新：R3（2026-09-17）
本轮变化：主界面加入引导注入素材（D-17）；第一张纸的内容定为工种任务单（D-16）；扳机后的图里加入合并裁决节点（D-18）；待定项更新。

## 视觉语言

- **[用户]** 整个界面是灰白色渐变空间；空中悬浮一张展开的纸；聊天框是液态玻璃质感；文件夹是液态磨砂玻璃质感。
- **[R1 建议，未被反对]** **文档永远是不透明的纸，玻璃只用于 chrome**（聊天框、文件夹、按钮、HUD）。避免玻璃叠玻璃叠文字。
- **[建议]** 玻璃的磨砂程度承担语义：磨砂 = frozen，透明 = ready，霜层消退 = thawing（见 03 状态机）。
- **[建议]** 同屏 backdrop blur 层数上限（Web 渲染时）个位数；见 06 平台。

## 空间模型

- **[用户 R1]** 选文件夹 → 界面左移 → 文件夹平展 → 再点确认 → 再左移并向右射线展开子文档。
- **[用户 R2]** 类似 ComfyUI 节点式工作流，但自动展开，不手动连线。
- **[建议]** 底层是 **阶段（横轴）× 工种（纵轴）的有向图**；"向右射线"是节点之间的边，"左移"是视口沿横轴推进。ComfyUI 的对照：
  - 相同：节点有输入输出、有边、有执行状态、可局部重跑。
  - 不同：边由工作流模板决定，用户不拖线；节点内容是纸（文档）+ 聊天，不是参数面板；执行由用户逐节点确认推进，不是一键全跑。
- **[建议]** 视口行为：当前 active 节点居中偏左；上游节点缩小靠左成一列；同阶段其他节点在纵向排列；下游 frozen 节点在右侧磨砂。回退时视口沿横轴左移，不重排。

## 主界面（第 1 步）

- **[用户]** 左侧一列历史任务；中间一个 agent 对话框（液态玻璃）。
- **[建议]** 历史任务项 = 一次完整工作流（含分支树），显示：标题、缩略帧（有成片时）、进度（几个节点 passed）、分支数、最近更新。
- **[用户 R3]** 初步沟通时就**引导用户注入**参考图与品牌素材，存入项目资源库。
- **[建议]** 落法：对话框下缘常驻一条投放区（拖入即登记到资源库，缩略图排开）；首轮 agent 的开场问题里包含"有没有参考片 / 品牌规范 / 产品图"；用户没给时 agent 在确认需求卡片的 assumptions 里写明"无参考素材，将按文字描述推断风格"。资源库在任何节点都能从纸的边栏打开。

## 第一张纸（第 2 步）

- **[用户]** 输入需求 → agent 初步思考 → 对话框向四周蔓延（不到边）变成一份初步计划文档，右侧有 pull the trigger 按钮。
- **[R1 建议]** 变形语义统一为"纸从聊天框里长出来，聊天框缩回角落"；聊天始终是独立面板。
- **[用户 R3 → D-16]** 纸上的"9 行"是**工种任务单**，不是 9 个创意方向。目的：先对齐用户初步需求，让每个子 agent 在上下文区隔的前提下有一个粗略方向。
- **[建议]** 纸的内容 = 最小需求记录（导演 skill brief-and-modes）+ 短导演构想与必要关键镜头 + 每个工种一行任务单。任务单字段：**做什么 / 依赖谁的什么工件 / 预计产出与格式 / 本工种要特别守住的用户锁定项**。制片与场记两行也在纸上（它们的"任务"是价格表与台账基线），保持 9 行完整。
- **[建议]** 这张纸本身也是一个节点，也走确认需求工具：agent 认为需求够清楚时弹卡片，用户 yes 后扳机才可扣。用户对某一行任务单不满意可以直接在纸上点那一行进入聊天修改，不必推翻整张纸。

## 扳机与文件夹（第 3 步）

- **[用户]** 点按钮 → 向右射出 9 根细线 → 末端出现液态磨砂玻璃文件夹。
- **[修正后]** 射出的线连到 **7 个创作工种文件夹**；制片与场记不作为文件夹（见 02）。所有文件夹同时出现，只有上游满足的（编剧）是透明可进入，其余磨砂。
- **[R3 新增]** 美术 / 角色 / 摄影三个文件夹的右侧汇聚到一个**合并裁决**节点（D-18），再连到编译节点。视觉上它是导演文件夹的"第二次出场"，可以用同一个导演图标但不同形态（例如一枚印章 / 一张裁决单），与创作文件夹区分。被退回问题的工种文件夹会重新变为半磨砂并带"有退回"标记。
- **[建议]** 磨砂文件夹 hover 显示等待条件；解冻时播放霜层消退 + 进度事件。

## 节点内部（第 4 步）

- **[用户 R1]** 左侧子文档，右侧悬浮对应 agent 聊天框；聊天过程中右侧延展成文档（实际是聊天记录）。
- **[用户 R2]** 文档右上角一个"展开聊天"按钮，在画面右侧拉出聊天区看对应历史记录。
- **[建议]** 合并：默认进入节点时纸居中、聊天面板从右侧滑入（`active`）；hold 时聊天收起，纸占满，右上角保留展开按钮；随时可再拉出。聊天面板内是该节点 agent 的完整记录（含确认需求卡片、critic 结论）。
- **[建议]** 纸的边栏显示：`based_on` 上游版本、当前 revision、status、critic 结论摘要、成本（本节点 token）、**资源库入口**（本节点引用了哪些参考素材）。

## 确认需求卡片

- **[用户]** yes / no / input。
- **[建议]** 卡片浮在聊天面板与纸之间；显示 agent 的概括与假设；三个动作。yes 之后卡片折叠进聊天记录留痕。

## hold / move on 按钮

- **[用户 R1]** 聊天框上缘。
- **[建议]** 移到纸的顶部边缘更稳定（聊天可能被收起）。move on 前置条件见 03。

## 进度条（场记层）

- **[用户 R1]** 界面最下方可左右滑动的进度条。
- **[R1 建议]** 进度条 = 场记的时间轴。横轴为阶段，每个阶段下有工种状态点（frozen / ready / passed / stale…）。点击状态点跳转视口；展开进度条抽屉可见该阶段的三本台账（连续性 / 提示词版本 / Take）与项目风格档案。

## 制片 HUD

- **[建议]** 右上角常驻小卡片：本任务累计 token 成本、生成成本、fire 前估算。点开看按节点 / 按 provider 的明细与价格表日期。

## 历史文档位置的分支按钮

- **[用户 R2]** 回到前面步骤时，在历史文档位置给按钮选择 branch 或从当前节点开始刷新覆盖。
- **[建议]** 进入一个 `passed` 节点时，纸是只读态，顶部出现两枚按钮：**Branch**（fork）/ **Revise here**（刷新覆盖）。语义见 03。选择 Branch 后视口右侧展开一套新的 frozen 下游，进度条上出现分叉。

## sort → 生成清单 → fire（第 6 步前半）

- **[用户 R1]** 所有子流程做完后右半侧出现 sort 按钮，收回子文档到文件夹，文件夹一起向右延伸线连到一个节点，产生 final brief，确认 fire。
- **[R1 修正]** 连到的节点是**提示词编译节点**，产物是**生成清单**（镜头 × 生成单元 × 参考资产 × 检查门状态），不是 brief。`validate_prompt.py` 通过 + 制片估算显示 → fire 可用；fire 可分批。
- **[建议]** sort 动画：各文件夹合拢、线汇聚。清单页是一张更宽的纸，右侧 fire 按钮下方有估算金额。

## 生成、审看与组装（第 6 步后半）

- **[用户 R1]** 进入类似达芬奇 / PR 精简版的生成与剪辑界面；素材逐个生成并出现在时间线上；全部完成后解冻供审阅输出。
- **[用户 R2]** 查开源方案（hyperframe、remotion 等）；基础剪辑 + 部分图形制作即可；专业调色导出工程给 PR / 达芬奇。
- **[R1 建议]** 每个 Take 落地即可审，不等全部完成；槽位带审片结论徽标；重试的 Take v2 落同一槽位。
- **[建议]** 界面：上半预览，下半时间线（按剪辑方案预排，槽位 = 镜头），左侧 Take 库（按镜头分组，含结论），右侧审片面板（导演 skill 生成审片格式）。工具：换 Take、in/out、简单转场、字幕 / 标题图形、音乐轨。导出：mp4 + OTIO / FCPXML / xmeml。引擎选型见 06。
