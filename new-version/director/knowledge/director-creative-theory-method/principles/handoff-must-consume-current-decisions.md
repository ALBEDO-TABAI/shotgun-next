# 原则

1. 交接指出：当前版本是什么；哪些决定生效；哪些只是候选；接收方需要验证什么；完成后回传什么。
2. 发生冲突时回到当前被批准的创作意图和实际材料共同处理，而不是每个部门自行重判。
3. **三件事分别标清**：创作事实、批准状态、下一动作。批准某个方向≠批准全部镜头；通过技术检查≠允许发布；收到一个文件≠其内容与当前版本一致。
4. "音乐不要在转向前进入"写在方案里不等于音乐部门已执行。交接需指出转向在当前版本中的具体位置、哪些声音可以提前、为什么这一约束存在、谁能批准改变。接收方发现原决定无法成立时提出受影响的问题和备选方案，而不是悄悄改变再交给下游猜测。
5. **最小闭环**：当前决定 → 对应产物 → 核对结果 → 是否继续生效。四者可在同一张卡记录。
6. **旧版本危险**：已批准的旧音乐草案在画面修改后可能不再对应人物转向；记录保留原批准的对象与范围，而不是用"已经过审"覆盖版本变化。下游不应把标为假设的人物动机重新写成确定设定——语气从"可能"变成"就是"是事实身份变化。
7. **避免过度工程化**：只有两个参与者的短片不必十套会议纪要。一个字段没有任何后续决策会使用就考虑删除；同一事实出现在多个文档时用引用或指定唯一维护位置。
