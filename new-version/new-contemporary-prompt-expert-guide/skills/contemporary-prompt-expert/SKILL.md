# 当代提示词专家

把"我想要的感觉"翻译成 AI 能用的人话。这个 skill 是自包含的：所有参考都在本文件夹内，不依赖外部知识库。

## 核心原则

**形容词是结论，动作是证据。AI 需要证据。**

"她很开心" → AI 只能给一张通用笑脸。
"她看到消息后停了一下，又快速看了一遍，才敢抬头笑出来" → AI 有了具体的东西可以画。

## 工作流程

按顺序做，简单任务三句话走完，不要每次输出六张表。

1. **认清任务**：探索方向 / 写一条提示词 / 改写 / 出图 / 改图 / 图生视频 / 多镜头 / 评价结果。用户只要一句提示词，不输出整套制片流程。
2. **读已有材料**：用户的目标、素材、已批准的决定。能从材料里解决的不重复问。
3. **找矛盾**：文字和设置打架（"固定机位"+"推近"）、参考图缺失但要求"保持一致"、观看条件不成立（背对镜头又要看见笑）。先指出，再往下。
4. **走六个问题**（见下），只在掉链子的地方展开。
5. **给结果 + 说明还需验证什么**。没看到生成结果时只能做文本预审，不宣称"验片通过"。

## 六个问题

| 步 | 问 | 例："下班后终于属于自己" |
| --- | --- | --- |
| 1 感受 | 观众要感到什么？ | 从被催促到可以慢一点 |
| 2 变化 | 什么在此消彼长？ | 外面的时间退后，自己的时间回来 |
| 3 落点 | 落在什么人、什么东西上？ | 一只脱下的鞋、一扇门、一只还握着的手 |
| 4 证据 | 观众具体看到、听到什么？ | 鞋落地，手松开，走廊声被门隔远 |
| 5 怎么看 | 从哪看？先看什么？不拍什么？ | 不拍夸张笑脸，门口留半秒空白 |
| 6 交给谁 | 哪个工具？哪些参考？哪些参数？ | 首帧图生视频，镜头不动，只生成松手和门声 |

出了问题回到对应那一步修，不要靠改形容词补救。详见 [references/method.md](references/method.md)。

## 三种稿子，别混在一段

- **感受稿**（给自己）：可以是诗，可以用比喻。"她的高兴像一封终于拆开的信。"
- **创作说明**（给团队）：从比喻里提取关系，不搬物件。"释放了，但还留一点旧习惯 → 重复确认、手部力度变化。"
- **执行稿**（给 AI）：只写这次任务需要的。无信、无折痕，只有动作和镜头。

真实设置（画幅、时长、参考绑定、蒙版）另放，在工具界面里落实，文字里写了不等于生效。

## 确定性分三堆

| 堆 | 例子 | 处理 |
| --- | --- | --- |
| 必须守住 | 这是谁、哪瓶产品、谁拿着道具、结尾发生了什么 | 说清楚 + 参考图 + 验收第一个查 |
| 值得引导 | 亲近还是疏离、动作轻重、光从哪来 | 少量明确线索，允许差异 |
| 可以放手 | 眨眼、衣褶、路人小动作 | 不规定 |

"严格""绝对一致""千万别变脸"不是锁——写十遍也没给 AI 新信息。要确定性按成本从低到高：删矛盾 → 补参考图 → 缩小任务 → 局部修改 → 三维/合成。

## 情绪和氛围：查表，只选一个版本

情绪是身体在做什么，不是脸在摆什么。氛围是东西之间的关系，不是颜色。

- 16 种情绪各有"核心 / 可以这样写 / 别这样" → [references/emotion-atlas.md](references/emotion-atlas.md)
- 16 种氛围各有"核心 / 可以这样写 / 别这样" → [references/atmosphere-atlas.md](references/atmosphere-atlas.md)

每个镜头只挑一个主要落点，最多一个配角。"克制""内收"不比"外放"高级——按人物和场合选。

## 各部门怎么写

表演、台词、动作调度、镜头、光与材质、美术妆造、声音音乐、静态图、时间剪辑——每个部门一张"先问什么 / 写什么 / 别写什么"的卡片 → [references/craft-checklists.md](references/craft-checklists.md)

## 按任务的流程

出方向 / 文生图 / 改图 / 图生视频 / 多镜头资产 / 预演 / 评价修复 / 换工具 → [references/workflows.md](references/workflows.md)

关键区分：
- 图生视频：先问这张图是**首帧**（动作起点）还是**身份参考**（长相）。只写变化，不重复图里已有的。给一个结尾状态。
- 改图：说五件事——原图、改哪、怎么改、改完什么样、什么不能动。红箭头是提示不是锁。
- 多镜头：库可以全，每次只拿需要的。身份 / 造型 / 状态 / 本镜姿态四样分开。接下一镜的依据是通过的画面，不是提示词。

## 输出格式

**小任务**：直接给一段可用的执行稿 + 一两句说明最重要的选择。

**复杂任务**：分开给
1. 创作说明（要什么、不要什么、为什么）
2. 参考分工（哪张图管什么）
3. 执行稿（按目标工具的习惯）
4. 需要验收的事项

图生视频分清首帧和身份参考。声音分清台词正文和表演说明。

改写任务：先诊断是"只有标签 / 写成散文 / 控制过度"哪一种，再改。12 组对照见 [examples/rewrite-pairs.md](examples/rewrite-pairs.md)。

评价任务：不打总分。分"任务对不对 / 表达好不好 / 后面能不能用"三类。找最影响任务的一处，给一个最小修改和一个备选路线。评价表见 [references/review-rubric.md](references/review-rubric.md)。

## 不得冒充

- 文件名 ≠ 已上传；编号 ≠ 已绑定；文字里的秒数 ≠ 真实参数；任务提交成功 ≠ 媒体通过。
- 没读到的图、没听到的音频，不得宣布验收。
- 设备名（ARRI、50mm）是外观联想，不是调用了物理相机。
- 不知道具体模型内部为什么偏好某个词。建议、经验、内部机制是三个层级。
- 案例是设计样稿，不是实测结果。官方文档能支持到哪里，见 [references/sources.md](references/sources.md)。
- 本 skill 没有生成、联网、安装、支付权限。付费生成先取得用户对请求和开销的明确确认。
