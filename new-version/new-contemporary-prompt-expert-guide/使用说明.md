**让感觉有落点，让 AI 有方向。**

第二版，2026-09-18。相对第一版，全部正文重写成高中生也能读懂的人话，新增"十分钟上手"和"术语表"，附带的 skill 重做为自包含的标准格式。知识点、案例、来源、章节编号和文件名保持不变，方便对照。

## 从这里开始

双击根目录的 **`开始阅读.html`**。它自带全部正文、目录和全文搜索，不需要服务器、账号、联网或安装任何东西。

- 只有十分钟：读[00｜十分钟上手](knowledge/contemporary-prompting/foundations/00-ten-minute-start.md)。
- 只有一小时：00 → 02 六个问题 → 06 通感 → 11 改写诊所 → 29 品牌片案例。
- 读到不认识的词：查[术语表](knowledge/contemporary-prompting/references/glossary.md)。
- 直接按你的问题进：总目录 `knowledge/contemporary-prompting/index.md` 开头有"按你现在的问题进"。

左侧可按章节浏览，也可搜索"首帧""表演""清爽"等词，多个词用空格分开。顶部可切换全书模式、打印、深浅色。提示词样稿旁有复制按钮。窄屏用"目录"按钮打开导航。

## 安装 skill

`skills/contemporary-prompt-expert/` 是一个**自包含**的 Cursor Agent Skill：

```text
skills/contemporary-prompt-expert/
├── SKILL.md              入口：核心原则、工作流程、六个问题、输出格式、路由
├── references/           按需读取的参考（方法 / 两张图谱 / 各部门卡片 / 流程 / 模板 / 评价表 / 来源）
└── examples/             改写对照 12 组 + 三个完整案例
```

所有内部链接都是相对路径，**整个文件夹复制到哪里都能用**，不依赖 `knowledge/` 目录。

**安装方式**（任选）：

```bash
# 个人 skill，所有项目可用
cp -R skills/contemporary-prompt-expert ~/.cursor/skills/

# 项目 skill，随仓库共享
cp -R skills/contemporary-prompt-expert <你的项目>/.cursor/skills/
```

安装后，当你在 Cursor 里要求写或改 AI 生图 / 生视频 / 配音的提示词时，Agent 会自动加载它。如果只想手动调用，在 `SKILL.md` 的 frontmatter 加一行 `disable-model-invocation: true`。

**skill 和知识包的关系**：skill 里的 `references/` 是知识包的精简版（约 1/3 篇幅），够 Agent 干活；`knowledge/` 是给人读的完整版。两者内容一致，改一处时记得同步另一处。

## 给 Agent 用（不装 skill 的情况）

`knowledge/contemporary-prompting/` 里的 Markdown 是内容源，按 OKF v0.1 组织。每个知识单元有 `type`、`title`、`description`、`tags`、`source`，并用包根相对链接（以 `/` 开头）互相引用。普通 Markdown 编辑器未必懂这个约定；离线 HTML 已把它们转成正确的章内跳转。

按任务取用，不要每次把 49 篇全塞进上下文。见[40｜给 AI 助手和团队的用法](knowledge/contemporary-prompting/practice/04-agent-use.md)。

## 老实说

这本书读的是 13 组 AI 影视教程的**文字**复审稿，没有重新看原视频、听原音轨。技术事实按有限的官方文档校准（访问日期 2026-09-17）。六个问题、两张图谱、八个案例是综合设计的，**没有跑过生成实验**。案例里的时长、角色、参考代称都是设计条件，不是已存在的媒体。

详见[这本书依据什么写成](knowledge/contemporary-prompting/references/corpus.md)和[借用了哪些理论](knowledge/contemporary-prompting/references/theory.md)。

## 编辑、重建、校验

只读不需要依赖。维护时在 Python 虚拟环境装 `requirements.txt`。脚本不联网、不调用生成服务、不改来源 ZIP。

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt

# 检查原样收到的包：结构、链接、阅读器同步、输入摘要、交付摘要
.venv/bin/python scripts/verify.py

# OKF 校验器（用户上传 skill 附带的原版，未改动）
.venv/bin/python scripts/okf_tools.py validate knowledge/contemporary-prompting --verbose

# 改了 Markdown 之后：重建阅读器，跳过旧摘要做内容检查
.venv/bin/python scripts/build_reader.py
.venv/bin/python scripts/verify.py --skip-checksums

# 解压位置变化后：刷新本地工作区索引
.venv/bin/python scripts/refresh_index.py

# 正式再发行时：重新生成摘要清单
find . -type f ! -name SHA256SUMS.txt ! -path '*/__pycache__/*' ! -name '.DS_Store' | sed 's|^\./||' | sort | xargs shasum -a 256 > SHA256SUMS.txt
```

`SHA256SUMS.txt` 记录的是**这次交付快照**。编辑正文、重建 HTML、刷新索引都会让相关摘要失效，这是正常的。自用编辑后用 `--skip-checksums` 检查内容；正式再发行时重新生成清单。

`qa/` 里：`scope_manifest.json` 是输入范围与摘要；`file_check.json` 是最终打包前的结构检查；`browser_check.json` 是阅读器在 Chromium 内核浏览器里的 26 项界面检查（路由、搜索、深色、全书模式、移动端抽屉、无外部请求）；`okf_validation.txt` 是校验器输出；`authoring_catalog.json` 是全部知识单元的元数据清单。它们都不代表生成质量实测。
