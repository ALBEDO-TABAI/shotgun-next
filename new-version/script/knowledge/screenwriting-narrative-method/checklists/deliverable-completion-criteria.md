# 要点

| 交付物 | 完成标准 | 常见失效 |
|---|---|---|
| 概念说明 | 说得出具体题材、问题、主导形式、独特处境、最大未知项；让下一位读者知道还在探索什么 | 只有"真实、温暖、年轻、有力量"这类方向词，不足以区分候选；未决定被误当已确认 |
| 梗概 | 压缩过程而不抹掉机制；依赖信息揭示的作品可分写"世界里发生什么"与"观众如何逐步得知" | 时间顺序梗概抹平独特叙述方式；意象联想组织的故事被硬编人物目标 |
| 大纲与场景卡 | 允许低成本重排、合并、删除；每张卡补一句"这段为什么要由观众经历" | 过早写成舍不得改的精美散文；卡上只有"双方和解"这种结果，没有可经历的过程；等待或关系观察类场景没有描述 |
| 剧本 | 关键表达在页内成立；区分观看所必需的事实与只帮助作者/演员找行为的材料 | 人物选择只有读完小传才成立；或把所有内部解释都变成台词 |
| 制作说明 | 保护**意义关系**（信息限制、关系动作、变化尺度）；方案无法执行时说明等价在哪一层、不等价在哪一层 | 给每个镜头指定固定焦距式的锁死手段；以为保住每个字就保住场景功能 |
| 修改记录 | 记录改变了什么、基于什么证据、谁需要更新、当前版本是什么；旧方案保留研究价值但不再是执行依据 | 文件越多越"成熟"的错觉——小团队一页即可，只有使用者、更新频率或权限确实不同才拆分 |

## 制作说明的三个层面示例
- "观众此刻不能认出信的署名" → 保护信息限制
- "父亲需要让出门内位置" → 保护关系动作
- "城市声不应突然全部消失" → 保护变化尺度

# 适用边界 / 不应自动做什么
- 未决定不是失败；未决定却被误当成已确认才造成生产冲突。
- 不要求所有项目维持两套庞大梗概文件。
