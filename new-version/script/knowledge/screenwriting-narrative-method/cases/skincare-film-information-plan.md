# 信息表

| 信息 | 要求 | 候选载体 |
|---|---|---|
| 她已经开始自己的晚间动作 | 必须清楚 | 产品已打开，动作被打断 |
| 请求不是必须即时完成 | 必须有足够依据 | "明天下午讨论的文件" |
| 她原本准备道歉解释 | 必须可辨到程度 | 屏幕草稿与停顿 |
| 她换成明确安排 | 必须清楚 | "我明早看"已发送 |
| 她恢复刚才动作 | 必须清楚 | 同一空间与动作连续性 |
| 同事是否善意 | 可以开放 | 不额外加负面提示 |
| 人物完整经历 | 本版本不需要 | 不补童年、加班史 |
| 产品让她获得边界感 | 不应成立为功效因果 | 动作顺序、文案和声音共同检查 |

# 为什么新增期限信息

- 原来只有"现在方便看一眼吗"，可能被读成急事。新增期限信息是**修正条件**，不是装饰。
- 代价：两条消息增加读取负担。候选处理：合并为"明天下午讨论的文件，现在方便先看一眼吗"，或换用字数更少的真实情境。
- 候选需要比较，**不以更短自动更好**。

# 说明性信息的立场

说明性信息有时应直接承担必要理解，不必全部隐喻化。编剧对谈关于"说明"的启发在这里仅用于承认直接交代的合理性，**不保证这句字数与时长适配**。
