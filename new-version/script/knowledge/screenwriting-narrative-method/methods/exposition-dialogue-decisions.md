# 要点

解释可以合理地发生于：初次接触、专业分工不同、核对步骤、协商条件、纠正误解、重新争论旧事，或用已知事实实施新的关系行动。

例："我们结婚十年了"若只是互报背景可能生硬；"十年了，你还是替我点这道我不吃的菜"把共同事实用于当下指责。是否写得好还要看风格，但**不能因为双方都知道就自动删除**。

# 操作：三个决定

| 决定 | 问题 | 反例 |
|---|---|---|
| 1. 范围 | 观众此刻只需要知道哪一部分 | 一口气讲完全部设定 |
| 2. 说话者 | 谁合理地知道、又有理由说 | 为了让主角提问而抹掉他已建立的专业能力 |
| 3. 接收 | 接收后改变什么：对方尝试操作、纠正、怀疑或改变计划 | 解释说完即止，不属于场景 |

公开说明本来就可以是形式：教学、演示、交接、共同核对，不必伪装成意外提起。**隐藏得越深不等于越好。**

# 多通道同时说明可能争抢

高速对白、小字屏幕和关键表情同时出现，作者可能以为三项都交代了，实际能否获得需要测试。没有一个可以随意套用的"每秒信息容量"公式。应明确主要任务，必要时错开载体。

# 适用边界 / 不应自动做什么

- 不把"说明性"当成缺陷标签一律删除；也不把说明藏进不合理的意外提起。
- 是否被观众获得只能靠测试，不能由剧本"观众看到"保证。
