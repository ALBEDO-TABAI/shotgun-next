# 要点

Design Council 的双钻石把过程分为发现、定义、发展、交付，并承认过程可以回返。迁移到编剧，它提醒**区分理解问题与生产方案**，而不是声称它验证了最佳编剧顺序。

## 三条操作规则

| 动作 | 要求 | 反面 |
|---|---|---|
| 发散 | 版本之间要改变实质变量：人物位置、时间范围、主导组织、信息顺序 | 同一个故事换三种色调 |
| 收敛 | 说明所选方案与资料、任务、媒介、限制如何相合，以及最大风险 | 只写"综合判断最优" |
| 返回 | 回到具体层级：试读暴露期限不清→回信息安排；真实工作不允许延迟→回前提；只是小字不易读→先修载体 | 每次推翻全项目，或指望下游加技巧拯救上游错误 |

## 比较多少方案

由当前不确定性与成本决定。明确的改编或小改稿不必重开全部可能性，也不机械规定"总要十个创意"。

# 适用边界 / 不应自动做什么

- 双钻石是设计领域框架，向编剧迁移是本包的方法类比，不是已验证的编剧标准。
- 不把发散、收敛做成固定仪式；阶段划分见 [阶段A](/methods/stage-a-problem-material-boundary.md) 至 [阶段G](/methods/stage-g-production-protection.md)。
