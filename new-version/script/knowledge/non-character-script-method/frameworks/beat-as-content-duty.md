# 要点

**定义。** 本包将节拍定义为「在一段时间内完成一个主要内容职责的单位」。

**何时另起节拍。** 看以下四项是否改变：主要对象、作用关系、观看任务、形式规则。

| 情形 | 处理 |
|---|---|
| 手接近按钮、按下、灯亮 | 放在一个「启动关系」节拍里，不必拆成三个卖点 |
| 灯亮后，书页表面与空间关系成为观看中心 | 另起一个「阅读空间」节拍 |
| 一个固定镜头能清楚呈现全部内容 | 一个镜头可以覆盖两个节拍 |
| 一个「识别接口」的节拍需要两个镜头 | 可以，只要它们继续承担同一个理解任务 |

**节拍编号是内容引用，不是镜头订单。**

# Schema

建议的精简节拍字段：

```text
节拍 ID／暂定时间
初始状态 → 本段动作或披露 → 结束状态
本段的主要观看职责
与上一段的连接依据
必须保持的对象身份与关系
必要的文字／声音责任
待设计或待验证的条件
```

- 静态陈列可以没有实体动作，此时填写披露、比较或停留职责。
- 纯形式片可以没有产品事实，此时填写规则与变化变量。

# 适用边界

- 节拍定义与字段是本包工作约定，不是电影叙事学条目或事件分割研究给出的统一标准，见 [切镜头、事件与知觉不是同一件事](/principles/cut-event-perception-are-distinct.md)。
- 节拍数量不是门禁；不把镜头数量等同节拍数量。
