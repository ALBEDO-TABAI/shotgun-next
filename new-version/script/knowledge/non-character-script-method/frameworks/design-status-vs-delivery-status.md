# 要点

## 四种需求状态

| 状态 | 含义 |
|---|---|
| 引用现有 | 已有可用资源可直接引用 |
| 需要新设计 | 尚无对应设计，需下游提出方案 |
| 需要补充状态／接口 | 主体已有，但缺某个状态、视角或接口 |
| 需要资料或针对性验证 | 缺事实依据，或需一次定向验证 |

状态**只说明工作进展，不替代用户确认**。

## 两个方向的误判

- **高估：** 已有一张准确产品正面图，可引用外观，但不能自动标记开盖内侧、按钮动作和所有视角已可用。
- **低估：** 缺少完整三维不等于不能继续；只要拟采用的观察与动作能由足够资源支持，就可以开展设计。

## 对真实工作流的建议

- 同时明确**由谁接手**和**下一步是什么**；
- 没有消费者的字段——删除；
- 没有下一行动的待办——重写；
- 已批准的内容不由下游再次随意解释。

# 适用边界

- 四种状态是本包建议的工作标记，不是来源文献中的标准分类。
- 它描述设计需求的进展；「初步剧本完成」「最终生产」「用户确认」「受众效果」是另外几种不同状态，不能互相冒充。
