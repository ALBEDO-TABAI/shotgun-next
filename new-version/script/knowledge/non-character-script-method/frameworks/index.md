# 框架 · Frameworks

概念区分、分层模型、分类轴与对照表：传播任务、真实性层级、三线编排、披露、时间、连接、变更分类等。

# 01 能力定位与连续创作路径

* [四种真实性层级：正在呈现哪一种世界](authenticity-levels.md) - 真实行为、机制简化、感官类比、自主抽象四种工作标记，是作者与下游共享的内容判断，不是画面字幕；按表达本身寻找依据。
* [六种传播任务：本版结束时要得到什么](communication-tasks.md) - 识别、理解、感受、联结、选择、持续观看六种任务各自的终点写法与常见误置；初稿应指出主任务与可让位任务。
* [任务模型修正：剧本组织的是可展开的内容](expandable-content-task-model.md) - 无人物不等于无事件；初步剧本不是缩小版分镜。前置的是使表达成立的关系，而不是无差别前置技术参数。
* [四层 brief 路由：用途、生产方式、体验风格、组织方式](four-layer-brief-routing.md) - 「什么类型的广告」不是足够精确的路由条件。先把四层描述分开，再写一句带主次的判断，排除无关探索。
* [组织依据与连接词测试：推进力来自哪里](organizing-bases-and-connective-test.md) - 事件、演示、分类、比较、类比、形式六种组织依据各自依赖什么；删去「然后」，看能否换成更明确的连接词。
* [项目规模与三种工作模式：快速草案、标准初稿、高依赖](project-scale-work-modes.md) - 三种模式共享同一工作逻辑，改变的是证据与展开程度；不要让六秒循环负担与完整系统说明片相同的流程。

# 02 对象、信息与时间体验编排

* [节拍是内容职责单位，不是镜头订单](beat-as-content-duty.md) - 节拍＝在一段时间内完成一个主要内容职责的单位；按主要对象、作用关系、观看任务或形式规则是否改变来另起节拍，并附精简节拍字段。
* [八种段落连接及其选择时机](eight-segment-connections.md) - 因果、理解前提、时间相继、对照、类比、形式延续、分类、有意断裂：作者在内部要知道每个连接负责什么；共享方向不等于共享因果。
* [披露的四种写法：累积、修正、定位、重新分类](four-disclosure-modes.md) - 把披露写成可操作的差异：每种写法有自己的核心问题、内容胚与应避免的写法；披露位置不默认放在结尾。
* [四类时间：建立、变化、辨认、停留](four-kinds-of-time.md) - 一段内容占用的时间分属四种不同职责；它们可以部分重叠，但不能假定同时完成，检查重点是任务是否竞争同一注意对象。
* [状态变化的四种来源](four-sources-of-state-change.md) - 对象自身变化、对象间关系变化、呈现范围变化、符号或解释变化；后两类是认知与披露变化，不应被误写成世界里的魔法变形。
* [四种时间性格：先稳定再改变、先密集再澄清、均匀变奏、停顿与响应](four-temporal-characters.md) - 四种整体时间组织候选及各自适合的内容；它们是编排候选，不是情绪效果定律。
* [信息增量与「身份锚点—变化变量」配对](information-gain-and-identity-anchors.md) - 每段结束后问观众比之前多了什么依据；在复杂变化中明确观众追踪什么，并用冗余锚点而不是单靠颜色保持身份。
* [对象的五类状态：从对象清单走到关系模型](object-state-types.md) - 几何、材料行为、连接与接触、使用、可见五类状态；不必每个对象填满五列，只抓本段依赖的变化。
* [声音与文字的内容职责：同步、先行、滞后、独立](sound-and-text-duties.md) - 初稿先给声音与文字分配职责，而不抢占最终制作；四种声画关系的操作例，以及文字加入时重新决定谁是观看中心。
* [三线联合编排：世界线、信息线、时间体验线](three-line-orchestration.md) - 把初步剧本的编排任务拆成三条线——世界里发生什么、观众获得什么、这一段如何占用时间——并要求三条线留在同一内容版本里。

# 03 创意生成与可见过程构造

* [意图—关系—可见过程：创意的中间层](intent-relation-process-translation.md) - 把抽象体验意图先拆成可感知的关系，再构造让关系被看见的过程；素材词典不能替代这层转换。「机制」只指一条内容如何成立。
* [机制选择矩阵：卡片不能当任意菜单](mechanism-selection-matrix.md) - 按当前最重要的任务给出优先探索的主机制、常见辅助机制和暂缓的高负担选择；主机制完成主任务，辅助机制必须解决一个具体问题。

# 04 一手案例研究与方法迁移

* [九例横向比较：每例教会哪一个操作](nine-case-operation-comparison.md) - 一张对照表：九个一手案例各自的公开入口、本包提取的操作、主要设计依赖，以及最容易误借的东西。

# 05 初步剧本写作与设计需求交接

* [主责之外的三个接口：摄影、声音、制作各需要什么](camera-sound-production-interfaces.md) - 镜头端需要看见与暂不看见的约定，声音端需要段落职责，制作与工具端需要当前版本与关系条件；工具输入不能创造新剧情，付费测试另列并由用户授权。
* [设计状态与交付状态：不要让「已列出」冒充「已可用」](design-status-vs-delivery-status.md) - 四种需求状态——引用现有、需要新设计、需要补充状态或接口、需要资料或针对性验证——只说明工作进展，不替代用户确认；同时写明接手人与下一步。
* [三种文本层级：正文、节拍表、实现描述](three-text-levels.md) - 正文让人读懂一条片，节拍表让专业分配工作，实现描述在下游形成；三者是同一内容的不同视图，不能成为互相矛盾的多套事实。

# 06 创意优化、验证与多 Agent 回修

* [四种回修工作：修错、澄清、提升、改任务](four-kinds-of-revision-work.md) - 改稿前先区分修错、澄清、提升与改任务四种性质不同的工作，并分开记录；只做其中一种都会出问题。
* [多 agent 回修：一个现行内容源，多种专业判断](multi-agent-revision-single-content-source.md) - 当前剧本是唯一内容源；编剧、导演、美术、镜头与时序、用户各自负责不同类型的判断；只把改变内容含义、事实或用户选择的项提升处理。
* [质量评价：分维度记录，不用一张综合分数隐藏问题](quality-evaluation-without-composite-score.md) - 分别记录事实与关系完整性、理解可接触性、表达集中度、产品联系、时间性格、设计可交接性、候选多样性七个维度，用明确、待改、待验证加理由，而不是加权成一个分数。
* [三类变更：实现内调整、内容关系变化、事实或任务变化](three-change-classes.md) - 按改动改变了什么（而不是改了多少字）把变更分为三类，并规定各自的处理方式：专业端直接执行、回到编剧与导演、先核验事实或确认新任务。
* [不同问题需要不同证据：验证方法对照表](validation-by-question-type.md) - 七类验证问题各自适用的材料与方法、能得到什么、不能得到什么：从内部一致性、消费演练、状态代理、粗时序，到受众开放提问、候选比较与真实投放。
