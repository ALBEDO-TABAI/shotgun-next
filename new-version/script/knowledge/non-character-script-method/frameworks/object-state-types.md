# 要点

一个对象至少可能涉及五类状态：

| 状态类型 | 记录什么 | 来源中的例子 |
|---|---|---|
| 几何状态 | 形状、姿态、位置 | 灯头由收拢进入横向展开 |
| 材料行为状态 | 受作用时的响应 | 软质材料受压、恢复 |
| 连接与接触状态 | 谁与谁相接、固定点在哪 | 两个部件由分离变为相接 |
| 使用状态 | 开关、权限、可否操作 | 阅读灯「形状相同但开关状态不同」；模块「位置相同但权限从不可操作变为可操作」 |
| 可见状态 | 哪些表面当前可被看见 | 盒子「库存未变但内侧从不可见变为可见」 |

**取舍规则。** 并不是每个对象都要填五列，关键是抓住本段依赖的变化：

- 一只保持静止的瓶子，只需身份和可见关系；
- 承担折叠演示的灯头，则需要固定点、转动范围和关键中间态。

# 适用边界

- 五类状态是写作用的检查维度，不是强制表单；过度填写会把初稿变成文书负担。
- 只记录位置和颜色，会漏掉使用状态与可见状态这类「外形没变、关系变了」的内容。
