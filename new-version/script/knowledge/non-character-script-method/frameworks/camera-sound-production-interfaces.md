# 要点

| 接口 | 需要从初稿得到 | 不需要 / 不应该 |
|---|---|---|
| **摄影／镜头端** | 必须看见与暂不看见什么；局部属于哪里；动作如何连贯；哪些空间参照要保持 | 不需要编剧擅自写出全套焦距才能工作 |
| **声音端** | 何种声音承担事件识别、空间延续、形式计时或情绪职责；静音版保留哪些任务 | 不要只写「梦幻音乐」而没有段落责任；也不要把暂无声轨当成文本阶段无法结束 |
| **制作／工具端** | 当前版本、批准内容、主资产引用、动作与关系条件、可调整实现方式 | 工具输入不能在这一层创造新的剧情。模型没做到单铰链，不意味着产品事实可以改成双铰链 |

## 付费测试

当某个实现方案已明确需要付费测试，另列**试验问题、范围和预期费用**，由用户按约定授权。来源知识包本身没有执行视频生成或付费调用。

# 适用边界

- 三个接口是对「主责（编剧—美术）之外」协作方的最小约定，不是完整岗位说明。
- 脚本、设计、动画与声音分工又协作的依据，是一家动态创作公司的公开流程自述 [2]；它不是全行业唯一分工，也不是纯 AI 流程标准。
