# 要点

| 层级 | 负责什么 | 不应做什么 |
|---|---|---|
| **正文** | 事件与观看过程；可以写时间性格、声音职责和空间关系。不发声、不讲人、没有对白的片子同样可以有完整正文 | 不只是旁白；不应只剩「氛围清新、质感高级」 |
| **节拍表** | 把正文拆成可引用的职责、状态与条件，供各专业分配工作 | 不新造正文没有的情节；不成为第二套独立事实。详略可以不同，但同一内容不能一处说产品触发、另一处说只是并置 |
| **实现描述** | 分镜、动作代理、灯光方案、精确构图、工具提示词——对当前内容的实现，在下游形成 | 会反过来揭示问题，但不能自行更换主张与因果 |

## 什么应当前置到初稿

必须前置的是**表达约束**，例如「接口要看清」「整体暂不揭示」；不是模型参数。

## 小项目的合并

小项目可以把正文和节拍合并在一个文档里。没有必要为强调结构化，强迫一条六秒循环生成三份高度重复的文本。

# 适用边界

- 层级划分是本包的工作格式，不是行业标准。
- 节拍是内容职责单位而非镜头订单，定义见第 02 篇 [节拍作为内容职责单位](/frameworks/beat-as-content-duty.md)。
