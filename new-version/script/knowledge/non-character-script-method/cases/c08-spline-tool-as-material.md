# 公开依据

- 工作室说明学习 Spline 并使用它制作介绍该工具的品牌片；页面另列脚本职责；**类型标签包含角色**。来源镜像见 [C08 参考条目](/references/c08-ordinary-folk-spline.md)。
- 查验范围：项目文字与署名。不引用其历史宣传语作为当前价格或功能保证，也不把它归为严格无人物作品。

# 可提取的方法（本包提取，不是原团队用语）

- 当产品本身是创作工具，作品可以展示由该工具支持的结果。初步剧本的核心不必是「软件按键教程」，也可以是作品如何形成、如何被探索或如何进入另一种状态。
- 作品漂亮，不等于产品独立完成了所有环节。必须知道哪些是工具内能力，哪些是团队制作与外部支持。
- 对 AI 团队：不能把自己多工具完成的结果描述为单一产品的一键功能。

# 原创迁移：虚构排版工具介绍

事实仅确认三项：调整网格、替换文字、导出画面。

| 路线 | 做法 | 成立条件 |
|---|---|---|
| 甲 | 同一内容在网格变化下形成不同版式 | 内容身份保持 |
| 乙 | 先让人接触三种结果，再回到同一规则如何生成它们 | 前段必须保留共同文字与结构锚点，否则只看到三个不相关设计，无法接回工具 |
| 丙 | 用一条作品发展过程串联三项实际操作 | 不能因叙述便利增加自动写稿、自动选图等未确认能力 |

# 回修与分叉

- 设计与写作一起工作：需要样例内容、准确界面或抽象界面协议、状态变体、导出结果和文字层。
- 可以先制作极小的真实操作样例，看所选关系是否成立；这项试验只证明具体关系，不证明整个工具介绍片的传播效果。
- 不具备实际工具访问时，可写成「待工具核验的候选」，但不能在脚本里声称已经用它完成。技术证据不足时，外观与品牌表达仍可继续构想。

# 迁移要点

产品参与生成作品可以成为内容关系，但要保持贡献与能力描述准确。

# 最容易误借的东西

「一键完成」的夸大表述。
