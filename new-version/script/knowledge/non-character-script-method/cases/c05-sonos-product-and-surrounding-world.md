# 公开依据

- 工作室说明与相关电影权利方合作，将《Dune》的世界引入家庭环境，创作主影片和关键视觉，并开展模拟研发，以呈现沉浸式声音体验。来源镜像见 [C05 参考条目](/references/c05-futuredeluxe-sonos-arc-ultra.md)。
- 查验范围：项目目标、合作及模拟研发说明。这不是声学性能的独立测量；公开案例也**不授权复用第三方 IP**。

# 可提取的方法（本包提取，不是原团队用语）

- 一些体验不是单看产品表面就能表达，而是依赖产品与周边空间的关系。初步剧本可以先决定「环境如何被感知」，再安排产品如何留在这个经验中。
- 必须区分**体验可视化**与**技术解释**：空间中有艺术性波动，不自动证明真实声波按同样几何传播；环境变成电影世界，也不是产品真的改造物理房间。

# 原创迁移：无第三方 IP 的空间声音片（虚构项目）

任务是建立包围与空间展开的感受；产品外形已确认，不给具体声学测量结论。

- 构想：从真实产品与普通室内关系开始；逐渐增加独立的空间层级，近处、侧面与远处出现同一节律的不同响应；产品继续保持可辨位置；最后环境回到稳定关系。
- 设计的是一种艺术听觉经验，不是传播路径图。

为什么比「粒子从音箱喷出」更可控：喷射路径强烈强调产品作为物理发射源，可能把任务变成技术机制说明。独立环境响应允许不同关系，但仍需检查实际观感是否产生具体误读；**不能只因为没有画箭头就断言没有主张**。

# 回修与分叉

- 若任务确实是解释扬声器原理：另用准确技术资料，转成条件—作用—结果或结构关系脚本；不能把艺术环境当教材。
- 设计交接需要：真实产品、室内锚点、艺术环境层、前后及距离关系、声音职责、环境变化状态。产品自身不应因模拟方便而变成能发光、长出结构的另一个物件。
- 先用少量代理检查「始终知道产品在哪里吗」「环境是否抢走产品」，再决定需不需要复杂模拟。
- 若体验只能在声音开启时成立：明确标注有声主版本，另写静音版本的任务，而不是承诺同一片无条件成立。

# 迁移要点

用周围世界承载体验，但要清楚它是在比喻、演绎还是解释。

# 最容易误借的东西

未授权的电影 IP。
