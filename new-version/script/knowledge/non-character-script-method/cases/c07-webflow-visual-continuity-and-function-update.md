# 公开依据

- 官方页面说明新项目延续先前 No-Code 影片的视觉语言，尝试以新方式展示功能，并**明确列有 Script 职能**。来源镜像见 [C07 参考条目](/references/c07-ordinary-folk-webflow.md)。
- 页面年份为 2022，正文同时提及 2021 的活动；二者分开记录，不据此推断发布日期，也不核验当前功能。
- 查验范围：项目文字、类型及职能署名。

# 可提取的方法（本包提取，不是原团队用语）

- 续作或系列片不一定要从零发明一个世界。初步剧本可以保留既有语法：对象怎样进入、模块怎样组合、文字怎样命名；同时重新分配新内容的职责。**复用视觉系统不等于重复旧剧本。**
- 形式鲜明的软件片同样可以有明确脚本工作。不要把「没有传统人物情节」误解成「只能交给美术自由发挥」。

# 原创迁移：某平台季度更新片（虚构项目）

教学输入：一套既有卡片视觉语言与三项已确认功能。

- 先把功能**按任务分组**，而不是按发布文档的随机顺序排列。
- 保留同一资料卡作为身份；分别显示其在创建、协作、发布中的不同状态；最后回到整套工作关系。
- 三项功能互相独立时，采用分类陈列，每段用共同语法，不强行说前一项必然引发后一项；确实存在工作依赖时，按依赖展开。

新旧关系卡：

| 类别 | 内容 |
|---|---|
| 保留项 | 资料卡身份、模块进入方式、品牌字形与基础语法 |
| 更新项 | 功能内容、状态、交互条件、文字与版本 |
| 待验证项 | 旧转场是否会让新功能看起来拥有并不存在的自动化关系 |

可交接片段（要点）：同一资料卡先以空白模板进入；用户提供内容后卡片填充；随后出现第二个被授权视图，评论只以独立层叠加；最后进入发布状态，准确说明已确认的发布范围。三段共享卡片身份，**不暗示系统自动生成内容或自动批准发布**。

# 回修与分叉

- 美术能够复用形式，编剧仍对新的信息与含义负责。
- AI 团队不必复制一套「第二季专用事实」，而应明确现行功能资料与旧视觉系统各自的作用。

# 迁移要点

系列的创造性可以来自新内容与旧语法之间的重新组织，不必每次改造全部外观。

# 最容易误借的东西

旧版功能或旧事实。
