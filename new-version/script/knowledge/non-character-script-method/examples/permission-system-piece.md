# 要点

> 原创虚构任务：「展示一份资料可以由拥有不同权限的两个成员协作处理。」已设定的功能只有**查看、评论、提交**，不含自动审批。

**粗稿。** 「数据流进入云端，连接多个设备，团队高效协作。」——没有对象身份，没有权限差别，也不知道谁做了什么。

**重写为四段。**

1. 建立同一张资料卡及其编号。
2. 在两个视图中保持同一编号，分别显示查看与评论权限。
3. 评论者添加一个标记，资料卡内容本体不被自动改写。
4. 提交者完成提交，状态标签改变，另一个视图显示相同状态。

**推进力**来自身份、权限与状态，不是光线飞行。

**设计需求**：资料卡、权限标签、状态、交互位置、两个视图的对应关系。

**事实约束**：若实际产品不具备某功能，该段不能因「系统片通常这样」而保留。

**时序提示**：避免同时改变颜色、编号、位置、内容和标签，否则对象同一性容易变得无法解释。

# 适用边界

- 「避免同时改变多项特征」是工作启发，**不是本包测得的用户识别阈值**。
- 功能集合是教学设定；真实项目以已确认的产品功能为准。
