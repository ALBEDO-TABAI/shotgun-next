# 要点

> 原创虚构教学项目；D02 的定义见 [V1 设计需求清单](/examples/yiye-lamp-v1-design-requirements.md)。

| 栏目 | 内容 |
|---|---|
| **需求用途** | 让 B02 看清同一灯头相对固定立柱的转动，支持收拢与工作姿态的对照 |
| **必须提供的内容条件** | 可辨识固定点；两个连接件在中间态保持相连；灯头长度不变；底座不随转动漂移；操作手存在可接触位置 |
| **可采用的表现资源** | 准确状态图、简单几何代理、足够清楚的已授权参考动作，或能够保持一致的其他资产表达——**不是默认必须完整三维建模** |
| **不在本阶段指定** | 精确渲染器、最终灯位、材质贴图分辨率、关节机械内部构造、每一帧速度。若它们决定内容是否成立，再定向增加 |
| **验收问题** | 下游是否能说清哪里固定、哪里转动？起中终是否同一产品？所需中间态是否会被手完全挡住？当前资料支持的是外部动作还是内部原理？ |
| **允许的回修提案** | 采用另一侧观察；调整手的进入位置；缩小操作幅度但保留关键关系；改为两个清楚观察 |
| **不等价的改动** | 改成柔性弯曲或多个关节——已改变事实，不可作为等价方案 |

## 这张详单示范了什么

- 一条需求可以同时说明「为什么存在」（用途）、「谁使用」（B02）、「怎样判断可用」（验收问题）。
- 把**可回修的实现**与**不可改的事实**分开写，美术才知道提案空间在哪里。

# 适用边界

- 详单不必为每条需求都写；只对承担关键动作或关键关系的需求展开。
- 验收问题检查的是交接可用性，不是最终画面质量。
