# 要点

## 两个方向的失败

| 失败方向 | 典型样子 | 缺什么 / 造成什么 |
|---|---|---|
| 印象过粗 | 「一个精美盒子打开，内部世界舒展」 | 盒子多大、哪个部件打开、产品在哪里、世界是盒内机构还是艺术空间、先前的物体是否保持身份，全部没有说明；能给人印象，不足以制作 |
| 实现过细 | 初稿直接规定每个焦距、每帧动作和完整生成提示词 | 美术没有提出更好载体的空间；用户稍改需求就要重写所有文本 |

## 本篇提出的中间层

写清三件事，其余不提前指定：

1. **必须发生的内容**；
2. **必须保持的关系**；
3. **下游需要解决的设计条件**。

「可被设计」不是「所有设计已完成」，而是**每个关键表达都有可接手的问题**。

## 自查问题

- 这句描述里，对象的尺度、打开的部件、产品位置是否可以被回答？
- 「世界」属于真实机构、独立装置，还是艺术空间？（见 [盒子打开的三种版本](/examples/box-opens-inner-space-unfolds.md)）
- 先前出现的物体是否保持身份？
- 初稿是否写了只有下游才该决定的焦距、帧级动作或工具提示词？
- 用户改一处需求时，需要重写的是内容，还是一整套实现文本？

# 适用边界

- 本篇的交付格式是面向当前 AI 团队的建议，不是行业统一剧本标准。
- 中间层并不否定细化；当某个观看条件本身就是表达机制（如「接口要看清」「整体暂不揭示」），它应当前置，见 [三种文本层级](/frameworks/three-text-levels.md)。
