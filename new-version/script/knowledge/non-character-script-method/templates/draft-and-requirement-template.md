# 要点

以下为来源提供的可直接填写模板（本包自有工具）：

```text
项目／本轮版本／状态：
传播主任务与体验意图：
已确认事实与来源：
创意假设：
不承担的任务：
当前表达命题与主机制：

初步剧本正文：
按段落写对象、变化、关系、披露与结束状态。
声音和文字只写当前有内容责任的部分。

节拍表：
ID｜时间｜正文对应｜主要职责｜进入/离开状态｜关键关系｜设计引用

设计需求：
ID｜对象/状态/关系/文字/声音类型｜使用节拍｜必须条件｜可设计自由
所需状态或接口｜最小可用性判断｜当前资料状态｜下一责任人

待回修事项：
原内容｜提出的新方案｜改变的关系｜是否需要内容确认｜受影响位置

交付说明：
可以开始的设计工作：
仍需确认但不阻塞其他工作的事项：
确实阻塞某段的事项：
```

## 各区块对应的方法

| 区块 | 填写依据 |
|---|---|
| 任务、事实、假设、不承担 | 第 01 篇 [任务与路线卡](/templates/task-and-route-card.md)、[brief 解包](/methods/brief-unpacking.md) |
| 表达命题与主机制 | 第 03 篇 [路线比较卡](/templates/route-comparison-card.md)、[机制选择矩阵](/frameworks/mechanism-selection-matrix.md) |
| 正文 | [可写句法](/methods/writable-sentence-syntax.md) |
| 节拍表 | 第 02 篇 [编排工作表](/templates/orchestration-worksheet.md)、[节拍作为内容职责单位](/frameworks/beat-as-content-duty.md) |
| 设计需求 | [八步提取法](/methods/eight-step-design-requirement-extraction.md)；「当前资料状态」用 [四种需求状态](/frameworks/design-status-vs-delivery-status.md) |
| 待回修事项 | 第 06 篇 [三类变更](/frameworks/three-change-classes.md)、[变更消费与更新回执](/methods/change-consumption-and-update-receipt.md) |
| 交付说明 | 只阻塞依赖未知事实的部分，其余可先开工 |

# 适用边界

- 小项目可以把正文与节拍合并，见 [三种文本层级](/frameworks/three-text-levels.md)；不要为一条六秒循环填出三份重复文本。
- 没有消费者的字段应删除，而不是为了完整而填写。
