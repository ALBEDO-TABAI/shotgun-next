# 本篇回答什么问题

对应原六点中的第六点：**优化不应只剩纠错，还要能够提升表达力。** 具体回答：

1. 一次改稿到底是在修错、澄清、提升，还是改任务？
2. 内容已经正确之后，怎样从内容层（而不是形容词层）提升表达？
3. 长短版本、竖版、静音版、无手版应如何改写，而不是缩速或换规格？
4. 不同的不确定性各需要什么证据？怎样问人而不诱导？
5. 多个 agent 参与回修时，怎样保证只有一个现行内容源，且被采纳的变更真正进入下游？

# 输入与产物

- **输入**：已有初稿（第 05 篇 V1）、设计需求、反馈或新的版本要求。
- **产物**：修订稿与改动说明、版本改写（含放弃项）、验证方案与记录、变更提案与消费表、下一行动。
- **状态声明**：改稿、测试方案、评估题库与 agent 协议均为原创综合；**没有实际投放、受众实验或 agent 运行成绩**。

# 核心主张

1. 修错、澄清、提升、改任务要分开记录；把改任务当纠错会导致无休止返工。
2. 「更高级」「更丝滑」不是诊断；反馈要落到哪一段、希望什么变化、为什么影响任务。
3. 提升来自内容关系的改变：母题、重新理解、产品参与、时间性格、作用来源、对照等；创意升级不以改产品规格为代价。
4. 短版是重新分配任务并写明放弃项，不是无损压缩；竖版改可见关系，静音版改信息职责，无手版可能改表达性质。
5. 不同问题需要不同证据；内部一致性、消费演练、粗代理、受众开放提问与真实投放各自只能回答各自的问题。
6. 多个 agent 同意不等于多个真实受众；没有测试就如实写「未进行人类观看测试」。
7. 变更按改变了什么（实现、内容关系、事实或任务）分类，而不是按字数；被采纳的变更要更新正文、时间、需求用途与下游引用，并让旧任务失效。
8. 内容 ID、版本、自检通过、导演认可、用户确认、资产可用、生成成功互不替代，也都不等于传播效果已验证。
