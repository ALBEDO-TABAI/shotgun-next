# 要点

## 四类输入

| 类别 | 是什么 | 处理规则 |
|---|---|---|
| 事实 | 外观、组件、允许动作、批准文案、品牌资产等已有依据 | 写出处，或写「用户提供」。「这个材质很高级」不是产品工程事实；「只有一个铰链」可以是结构事实 |
| 意图 | 希望观众理解、感受或联想到什么 | 需要进一步转译；不能伪装成已经测到的受众结果 |
| 偏好 | 喜欢某种色彩、某个参考、某种运动方式 | 可帮助选择，但不天然优先于传播任务；**用户明确要求时属于项目约束**，agent 不应私自「优化掉」 |
| 交付条件 | 时长、画幅、是否有声、观看场景、版本数量、可调用资产、费用授权 | 不全是后期问题：任意进入的循环与有明确开头的广告，需要不同内容结构 |

## 输入修复示例

原始需求：「做得像某高端科技片，轻、精密、有高级感，最好有水和金属，不要人。」

- **不应立即得到**：「银色产品漂浮，水流环绕，机械爆炸图。」
- **应该先拆成**：
  - 主任务尚未明确；
  - 「轻」可能指物理重量、操作轻松或视觉轻盈；
  - 「精密」可能指真实配合或秩序感；
  - 水与金属是**载体偏好**；
  - 「不要人」需区分不讲人物故事与不出现任何人体。

## 只提出会改变路线的问题

1. 本版更需要看懂操作，还是主要建立品牌感受？
2. 不出现人物故事，但出现一次局部操作手是否可接受？
3. 「轻」是可以宣传的实际特性，还是视觉感受？

背景是冷灰还是暖灰，可以在不影响结构时留给美术。

# 适用边界

- 解包是轻量动作，不是长篇问卷；把创作责任包装成几十个问题是反例（见下方清单的反例三）。
- 没有真实调研时，不为目标观众虚构年龄、心理或偏好共识。
