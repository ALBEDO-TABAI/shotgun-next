# 要点

| 目标 | 做法 | 能宣称什么 |
|---|---|---|
| **得到可用片段**（现实创作优化） | 可以一次修复一组相互依赖的问题；记录组合改动与结果 | 「这组改动之后问题消失了」 |
| **建立可迁移规律**（因果判断） | 尽量控制其他变量，设计更受控的比较 | 某个因素在该条件下的影响 |

两者不要混淆。

**例**：为修清楚一个铰链，可能同时调整手位置和观察方向。这可以是合理的设计回修，但不能随后宣称「已证明只要把手移开就提高理解」。

**工作规则**：优先改变「足以解决问题的最小相关组」——不机械限制为一个字，也不毫无记录地重做全片。

# 适用边界

- 这是方法论上的提醒，不是实验规范；本包没有运行任何受控比较。
- 「最小相关组」由内容依赖决定：如果改动触及披露顺序、作用来源或产品事实，它已不是局部回修，应按 [三类变更](/frameworks/three-change-classes.md) 上移。
