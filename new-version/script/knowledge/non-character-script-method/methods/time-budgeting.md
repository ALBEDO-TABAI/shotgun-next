# 要点

## 1. 先列不可消失的观察任务

- 每段写一句「必须有机会看见……」：同一铰链、按钮接触、书页归属、产品名。
- 再列可共享的窗口：完整产品可以同时承担名称识别；按钮动作和亮灯结果可以紧邻。
- 新机构、长字卡与复杂形变同时发生时，不应默认三项都被读取。

## 2. 用粗排暴露冲突

- 不需要先制作正式动画。
- 将节拍正文按暂定秒数顺读，或以已有图像和中间态草图做简单排布。
- 记录：哪个信息总要补口头解释；哪个动作一说完时间就用尽。
- 粗排检验的是时间与任务，**不证明**最终材质魅力，也不证明生成模型能精确完成动作。

## 3. 超时时，先减任务竞争，再动速度

可选动作：合并身份与落版；删掉重复局部；把一个复杂关系改为两个清楚状态；让短版放弃非核心过程。

- 若机制本体就是持续观察，不宜通过粗暴提速解决。
- 若瓶型早已被认出，也不需要每次出现都重新给同样的辨认窗口。

## 4. 以范围而非假精确工作

- 初稿可写：「此处大约需要 4–6 秒，取决于接口是否能在一个观察中看清」。
- 正式交付某一版本时，应给**可加总的当前预算**，并标明不确定位置。
- 不能一方面承诺 30 秒，另一方面六段各写随意范围而从不核算。

# 适用边界

- 本法不提供固定阅读速度、注意阈值或最佳比例；所有秒数都是项目内待检验的写作预算。
- 粗排是低成本检查，不是受众测试。
