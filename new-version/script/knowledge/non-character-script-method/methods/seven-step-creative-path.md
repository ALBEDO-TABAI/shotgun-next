# 要点

| 步骤 | 做什么 | 产物 |
|---|---|---|
| 一、压缩任务，不压缩理解 | 写三句：必须得到什么；允许联想到什么；不能误认为何种事实。再写本版明确不承担的任务。压缩不是删除用户需求，而是显式安排主次，必要时提出不同版本分担 | 任务卡（不是长篇消费者画像；无真实调研时不虚构观众年龄、心理或偏好共识） |
| 二、寻找表达锚点 | 从产品本身、使用关系、品牌资产、活动任务四处找锚点。锚点不是「唯一卖点」；重要的是知道内容为什么与本项目有关 | 两至四个候选关系，如「固定与转动」「分离与连接」「局部与整体」「密集与留白」 |
| 三、生成不同机制，不先决定风格外壳 | 每条路线用同样格式回答：对象、核心变化、观众要做哪种理解、产品如何参与、最困难的设计条件 | 机制路线卡，每条约一段正文，不展开几十镜 |
| 四、以关系选择路线 | 比较任务贴合、表达特异性、理解负担、设计负担、短版可保留性、核心不确定性；写理由，不用无测量依据的分数 | 已选路线、舍弃理由、保留的替代方案 |
| 五、将路线变为内容骨架 | 先写进入状态、关键作用、被重新理解的关系和结束状态；不必沿用三幕结构 | 表达节拍草案（四至七个只是常见教学尺度，不是数量门禁） |
| 六、写正文并提取设计问题 | 正文让人追踪「发生了什么」；设计问题让美术知道「哪些条件尚待提出」。此时允许美术提出材质和载体、时序提出更清楚的观看路径 | 正文 + 设计问题 |
| 七、只回退到必要层级 | 材质难辨认→换材质；镜头看不清接口→改观察；命题与产品无关→回到路线；用户改变主任务→回到任务卡 | 初步剧本、设计需求、局部待确认及下一行动 |

## 步骤五的骨架不必是三幕

- 演示片：条件—作用—结果
- 系列陈列：总类—分组—选择
- 循环：规则—变奏—延续

## 步骤七的两条诚实性规则

- 未完成的生成测试不能被写成「已证实可生成」；
- 也不能因此否认文本阶段已经完成。

# 适用边界

- 证据骨架：Design Council 的过程框架只支持「可以区分理解问题、定义问题和发展方案，并允许迭代」[2]；并行原型研究只支持「在图形网页广告设计任务中并行原型有积极结果」[3]。来源明确声明：这些依据**并没有直接验证本包的七步流程是最优 AI 影视流程**，它是在当前团队需求下提出的可检验方案。
- 不是每次都要重跑完整流程：按输入形态与项目规模调整，见下方关系。
