# 要点

## 做法

让一个**未参与编写**的人或 agent，只凭初稿与设计表回答：

1. 要设计哪些对象？
2. 哪些只是同一对象的状态？
3. 最早何时允许看全产品？
4. 关键动作的固定点是什么？
5. 可以自由改变什么？
6. 卡住时应该向谁提出什么问题？

## 怎样读结果

| 接手者的情况 | 说明 |
|---|---|
| 需要重新发明核心因果 | 交接不足 |
| 只缺桌面细节或镜头选择 | 可以进入专业创作 |

## 接手者的纪律

- 不要「补全自己认为缺少的剧情」；
- 把无法判断的条件**返回内容源**，或在允许的自由范围内提出载体方案。

好的交接既减少猜测，也保留专业创造空间。

# 适用边界

- 这**不是受众测试**，而是生产交接检查；它不说明观众能否看懂或喜欢。
- 来源包没有声称已用真实下游 agent 跑过该演练。
