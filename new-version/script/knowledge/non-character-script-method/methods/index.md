# 方法 · Methods

可执行的工作法：Brief 解包、七步创作路径、依赖排序、时间预算、需求提取、提升操作、变更消费等。

# 01 能力定位与连续创作路径

* [brief 解包：事实、意图、偏好、交付条件](brief-unpacking.md) - 收到 brief 后先做一次轻量解包，把输入拆成四类，再只提出会改变路线的问题，而不是直接复述客户原话或立即给画面。
* [三种输入入口：一句需求、已有初稿、参考片反推](entry-modes-by-input.md) - 不能每次重跑完整流程：只有一句需求时做解包与有限发散；已有创意时先保留有效内容再诊断断点；给参考片时先记录可观察内容并标明推断。
* [机制路线的发散与选择：以关系选路线，并写出牺牲](mechanism-route-divergence-and-selection.md) - 用同一格式生成少量机制不同的路线，按六个维度写理由比较，选定后写出舍弃理由、保留的辅助机制与本版牺牲项。
* [七步连续创作法](seven-step-creative-path.md) - 从任务压缩到只回退必要层级的七个步骤，每一步都要留下能继续工作的产物；它是可检验的工作方案，不是已验证的最优流程。

# 02 对象、信息与时间体验编排

* [依赖排序：用理解前提写顺序](dependency-ordering.md) - 先写最终要被理解的判断，再反问它需要哪些前提；用 →、≈、∥ 三个写作记号区分必须保护的顺序与只是当前选择的顺序。
* [关键中间态判断：删去它还能区分吗](key-intermediate-state-test.md) - 判断一个中间态是否必要，不看动作长短，而看删去后能否区分同一对象变化与换了一件东西、真实作用与无依据结果。
* [时间预算工作法：观察任务、粗排、减竞争、用范围工作](time-budgeting.md) - 先列不可消失的观察任务，用粗排暴露冲突；超时先减任务竞争再动速度；初稿可写范围，但交付版本必须给可加总的当前预算。

# 03 创意生成与可见过程构造

* [体验词转译：候选关系表与转译句式](experience-word-translation.md) - 为清透、轻盈、精密等十个意图词各给两个候选关系和需要警惕的相反感受，并用一条固定句式把体验、对象、关系变化、锚点与产品联系写到一起。是原创构思候选，不是心理学映射表。
* [五个起笔入口：不一定从形容词开始](five-starting-entries.md) - 从真实产品关系、材料行为、空间关系、品牌或文字的形式、不可直接拍到的关系五处起笔；每个入口给出要问的问题、示例与限制。
* [六个创意操作：改变关系，不只是换颜色](six-creative-operations.md) - 替换承载者、倒置披露、限制变量、改变尺度层级、转换关系类型、保留规则并扰动一次；外加防止「穷举机器」的三问筛选。

# 04 一手案例研究与方法迁移

* [五层案例阅读法：先事实，再关系，最后移植](five-layer-case-reading.md) - 把一个真实项目读成可用方法的五层：公开任务、创作者明确描述的做法、本包提取的关系、移植条件、原创内容胚与回修；第三层以后是方法综合。
* [建立真正可用的参考库：按操作检索，而不是按品牌和风格](usable-reference-library.md) - 案例库每条记录任务、可确认内容、证据类型、可迁移操作、必要前提、不能迁移项、原创适配胚与查验范围；检索先问关系，再查品牌。

# 05 初步剧本写作与设计需求交接

* [交接前的消费演练](consumption-rehearsal.md) - 让未参与编写的人或 agent 只凭初稿与设计表回答六个问题；这是生产交接检查而不是受众测试，接手者不补剧情，只返回无法判断的条件或在自由范围内提案。
* [从正文提取设计需求的八步操作](eight-step-design-requirement-extraction.md) - 圈名词、圈动词补条件、建立对象身份、区分状态／动作／关系条件、写清下游自由、写最小可用性判断、双向回看、保留待解决项。
* [可写句法：主语、动作、关系、结果](writable-sentence-syntax.md) - 把形容词句改写为含对象身份、动作方向、空间关系、披露与结果的句子；用动词暴露设计任务，用关系性限制保护内容而不替代创作。

# 06 创意优化、验证与多 Agent 回修

* [变更如何真正被消费：从提案到更新回执](change-consumption-and-update-receipt.md) - 一项被采纳的内容变更要经过：指出原版本与受影响位置、编剧与导演决定、生成新版本、更新时间与需求用途、下游确认转向新版本、旧任务停止或标记失效；附最小提案格式。
* [内容降级与实现降级：失败后怎样保住创意](content-vs-implementation-downgrade.md) - 生成或实现失败时，先尝试保住同一关键动作的实现调整；不得不改内容时承认任务已变并更新；避免一失败就改产品事实，或为求稳定把一切降成静帧。
* [从反馈到改稿：改变足以解决问题的最小相关组](feedback-to-revision.md) - 区分受控因果比较与现实创作优化：可以一次修复一组相互依赖的问题，但不能随后宣称证明了其中某个单一因素的效果；优先改最小相关组并记录。
* [竖版、静音版、无手版的改写：不是简单输出规格](format-variant-rewrites.md) - 竖版改的是可见关系，静音版改的是信息职责，无手版可能改变表达性质；三者都要回到内容层检查，而不是只换输出参数。
* [非诱导式观看提问：先开放，再针对，最后谈体验](non-leading-audience-questions.md) - 向观看者提问的顺序与禁忌：先问看到了什么变化和因果，再问不确定点，最后才讨论体验及其依据；不预先讲解隐喻，不把小样本当总体比例。
* [十二种提升操作：从内容层产生增益](twelve-uplift-operations.md) - 在内容已正确且清楚之后，用母题、重新理解、产品参与、时间性格、作用来源、对照、装饰任务化、声画分工、复杂度位置、有理由的缺省、结尾回响与替代路线十二种操作提升表达。
