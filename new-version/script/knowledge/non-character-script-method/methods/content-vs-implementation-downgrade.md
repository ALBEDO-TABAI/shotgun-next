# 要点

## 顺序：先实现，后内容；先保主任务与核心关系

| 情境 | 先尝试（实现降级） | 再考虑（内容降级） | 必须同步做的事 |
|---|---|---|---|
| 连续折叠生成不稳定 | 同一关键动作的更清楚观察、较少同时运动、可辨的起中终状态、局部重做 | 改成状态对照 | 承认已从过程说明变成姿态展示，并更新任务 |
| 艺术液体铺展始终造成错误含义 | 保留液体，但改变它与产品的连接 | 换独立图形，保持「路径形成」的关系 | 把损失告诉内容负责人：前者可能损失连续视觉，后者可能损失触感 |

## 两种应避免的极端

- 工具一失败就**改产品事实**，让结果「合法化」。
- 为了绝对稳定，把一切**降成静帧**。

规则：先保护主任务和核心关系，再比较实现与内容的不同调整；每种调整都是取舍，应交给对该决定负责的人。

# 适用边界

- 本包没有执行实际视频生成；上述情境是推演，不是工具能力报告。未完成的生成测试不能写成已证实可生成，也不能因此否认文本阶段已经完成。
- 内容降级等于 [三类变更](/frameworks/three-change-classes.md) 中的内容关系或任务变化，需要走变更流程，而不是由实现端悄悄完成。
