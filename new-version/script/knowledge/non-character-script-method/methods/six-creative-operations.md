# 要点

| 操作 | 做法 | 需要注意 |
|---|---|---|
| 替换承载者 | 同一个“展开”，由产品、独立装置、空间边界或图形承担；先写关系不变，再比较载体差异 | 不同载体带来不同的事实要求与风格自由 |
| 倒置披露 | 先整体后局部，或先结果后作用，改变观看体验 | 倒置不是无条件成立，必须补足新的定位条件 |
| 限制变量 | 暂时只允许一个对象、一种动作、一处关系改变，看能否讲清任务 | 这是产生集中表达的方法，不是要求所有项目极简 |
| 改变尺度层级 | 让局部在新层级下获得意义，例如织纹成为产品局部 | 不是任意放大；不应突然变成没有解释的城市 |
| 转换关系类型 | 把“产品导致环境变化”换成“产品与环境在同一规则下并置”，或把“解释机制”改成“建立感受” | 这会改变内容，应明确记录，不能当成镜头优化 |
| 保留规则、扰动一次 | 先建立重复，再改一个重要变量 | 改变可以带来惊喜，也可以只是让结构更可辨；没有必要每片都安排激烈反转 |

## 避免穷举机器：三问筛选
把对象、动作、时间、关系列成组合表可以帮助发现候选，但随机拼完不叫创意。每个组合必须通过：

1. 它是否服务主任务？
2. 产品与它有何联系？
3. 它是否产生可写的过程？

过不了三问，宁可丢弃。

# 适用边界

- 六个操作与三问是本包原创工作工具，来源未给出其效果验证。
- “转换关系类型”属于内容变更而非实现调整，回修时按 [三类变更](/frameworks/three-change-classes.md) 处理，并回到内容源，见 [主责与内容源](/principles/decision-ownership-and-content-source.md)。
