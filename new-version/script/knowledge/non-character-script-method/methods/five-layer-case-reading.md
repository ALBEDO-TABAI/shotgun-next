# 要点

## 选案例的标准（不是热度）

1. 官方文字是否说明任务与做法；
2. 是否能提取与初步剧本有关的关系；
3. 是否能看到它需要哪些设计条件；
4. 是否能帮助解释不同片型，而不是重复同一种奢侈品微距。

本篇九例覆盖触感、产品揭示、香氛概念、系统信息、空间声音、抽象声画、软件发布、工具自证，以及带角色的形式表达边界。前六个来自上一版的案例入口（本轮重新查验并扩展应用），后三个为新增对照。

## 五层

| 层 | 写什么 | 性质 |
|---|---|---|
| 1 | 公开任务 | 可确认事实 |
| 2 | 创作者明确描述的做法 | 创作者公开自述 |
| 3 | 本包提取的关系 | 方法综合 |
| 4 | 移植到新项目需要的条件 | 方法综合 |
| 5 | 原创内容胚和回修 | 原创教学内容 |

第三层以后不能写成「原导演就是按这个模板创作」。

## 工作提示

- 「不知道内部流程」不妨碍提出有用的新方案：未知的是历史还原，不是今天的创作能力。只要明确区分，就可以把真实案例发展成教学工具，而不虚构来源。
- 研究单位可以小于一支片：一个触觉实验、一种披露策略、一条声画规则，都可以成为可迁移的操作。不必为了「讲完整」而编出原片的开头、中段和结尾。
- 每例落成两张卡，见 [事实卡与迁移卡](/templates/fact-card-and-transfer-card.md)。

# 适用边界

- 成果的定位是「有一手创作意图依据的机制研究与迁移练习」，不是完整的成片逆向工程；限制详见 [案例证据的限度](/principles/case-evidence-limits.md)。
- 要做镜头级分析，应取得可访问视频，另记录时间码与可观察证据。
