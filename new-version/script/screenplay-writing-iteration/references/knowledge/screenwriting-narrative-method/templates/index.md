# 模板 · Templates

可套用的记录格式：交接卡、信息表、证据账、报告结构、决策记录。


# topic-02
* [最小交接卡](minimal-handoff-card.md) - 一场戏交给执行部门时的最小 YAML 说明：必须建立什么、允许开放什么、主要载体、受保护关系、可灵活项、改动后需重查项、证据状态与下一次测试。

# topic-06
* [对白交接给执行：保护行动关系，不固定每个停顿](dialogue-handoff-to-execution.md) - 对白模块向导演、演员交接时的输入依赖与保护清单：人物策略来自第四篇、场景任务来自第五篇、信息时机来自第七篇；改词可接受，但改变承诺或方案的改动必须回到条件检查。

# topic-07
* [信息表：只管理关键依赖，不穷尽世界](information-dependency-table.md) - 为会影响行动、误会、揭示和改编的少数事实建一张状态表（命题、世界状态、呈现位置、各方知识前后、推断依据、未确立项、复查依赖）。

# topic-08
* [评审决策记录](decision-record.md) - 把评审意见列表转成决策记录的最小字段：采用的修改、解决的问题、依据、接受的损失、验证方式，以及未采用的重要意见及原因。

# topic-09
* [跨版本交接：保留关系，不要求复制每个镜头](cross-version-handoff.md) - 跨媒介／跨版本交接的四类内容分级与三项成果（当前事实与关键关系说明、版本任务表、每版样稿），附单幅平面资产的 YAML 交接示例。

# topic-11
* [分析报告结构：先描述成立机制，再给诊断](analysis-report-structure.md) - 分析报告的七个部分与反馈句式：材料范围、形式档案、结构与信息简图、有效机制及依赖、关键问题与竞争解释、最小修改候选及代价、测试与未确定事项。
* [诊断报告卡（issue card）](diagnostic-report-card.md) - 单个问题的 YAML 报告卡：范围、观察、假设、替代解释、需保护机制、候选修改、代价、验证方式与状态，使每条诊断意见可回看、可替换、可验证。
* [证据账：让每个重要判断回到具体材料](evidence-ledger.md) - 把可见事实、人物理解、机制假设、意图自述、实际效果五层分别记录，每条证据注明直接可见、支持判断、不充分支持与需要补查，作为分析的证据台账。
