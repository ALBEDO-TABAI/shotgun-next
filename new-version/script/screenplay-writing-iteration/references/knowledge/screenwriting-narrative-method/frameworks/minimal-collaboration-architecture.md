# 要点

## 1. "单一事实"只用于该统一的事项

需要一致的：实际版本、已确认世界条件、执行状态、下一动作。
不应被强行归成唯一真相的：人物动机的有意多解、开放结尾、竞争主题解释。

## 2. 三类文件足以启动

| 文件 | 内容 |
|---|---|
| 当前作品稿 | 正在执行的版本 |
| 关键事实、约束与决定 | 必须一致的事项 |
| 反馈和变更记录 | 谁提出、谁接受、是否执行、是否验证 |

使用者和更新节奏不同时再拆分，不为显得系统化生产重复账本。

## 3. 一项决定需要四个状态

| 状态 | 含义 |
|---|---|
| proposal 提议 | 有人提出 |
| current 已选为当前执行 | 被选中并有适用范围 |
| consumed 已被相关执行者使用 | 下游理解并实际使用 |
| checked 已在实际结果中检查 | 成果被检查 |

某项写出不等于被消费，被消费不等于效果通过。

## 4. 交接允许回述

接收方简要说明理解的关系、拟用载体、遇到的限制和需确认部分。共同理解理论把反馈视为协作建立理解的重要内容；这里迁移为**关键交接**检查，不要求每个普通事项都长篇回述。

## 5. 旧版本可保存，不再自动生效

保留历史以便追溯与回退，但当前入口必须明确。旧反馈修复后标注状态，旧示意图不能无提示混进新执行。

# 适用边界 / 不应自动做什么

- 版本协调不用行政字段决定唯一艺术意义。
- 不生成无人消费的层层报告和重复审批。
