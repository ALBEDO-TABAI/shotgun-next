# 标准内容、格式与时间预算

## “标准”指任务需要的内容，不冒称全球唯一格式

广告、品牌短片、短视频默认采用**视听脚本**；较长剧情默认采用**分场文学剧本**。用户有内部模板、行业格式或指定表格时优先遵循。不要为了机器检查把正式交付变成工程日志；必要机器标识可以保持轻量。

两种格式都应让读者不依赖提示词版理解完整作品。标准稿不塞提示词关键字、模型参数、参考图魔法代号、无关镜头设备或未获批准的生成方案。

## 视听脚本最小内容

标题、版本、用途与目标时长、简要核心内容/体验、必要人物和世界/品牌事实、场次/段落序列、时间预算、可见动作、对白/旁白/屏幕文字、关键声音/转场、结尾。存在可替代执行方式时，用简短“必须保留/允许变化”区分；不强制每列都有内容。

场景较少时逐场写，超过一定量可先给概览表再写关键段落。不把“要拍什么”误作“观众必然懂了什么”；创作目的另列，实际表现写正文。

## 文学剧本最小内容

片名与版本、必要人物表、场景标题（内/外、地点、时段）、现在时可呈现动作、说话者与对白、必要画外/旁白标注、关键声音和屏幕文字。心理背景可以放创作说明，但决定性理解须有作品内的载体。

不默认插镜头型号、机位运动和每秒节拍，除非它决定叙事信息或用户明确要求。长片可分序列/幕组织，但不将它强制为特定幕数。

## 轻量、可机验的 Markdown 约定

正式采用本包模板时：场次主标题形如 `## SC001｜内景·门厅·傍晚`，跨版本保持 ID；重新排序不必重命名。B 保留同一主场次顺序，新增生成拆分仅用三级标题。

精确语言行写为：

```text
**对白 D001｜阿宁**：明早我再答复你。
**旁白 V001｜叙述者**：后来，她记住了那个停顿。
**屏幕文字 T001｜手机消息**：明早 09:00
```

一条正文占一行，需要换行的屏幕文字可在同一行用 `<br>` 明示；A/B 使用完全相同表示。对白、旁白与屏幕文字共用全片唯一的不同 ID；不得把同一行在多个场景重复记录来凑覆盖。B 的表演说明另写，不改标签行。

这是本 Skill 的交换约定，不是行业强制排版。用户需要其他格式时仍保留稳定场次、完整文本及手工对照；可额外制作同内容的机器副本用于检查，但它不得成为新的内容权威。未采用约定时不得宣称本包静态程序已经验证了语言一致性。

## 三种时间

**动作完成时间**：物件拿取、走位、对话等的执行；**信息识别时间**：认人、认道具、读字；**体验形成时间**：接受回应、等待和情绪落点。三者有时重叠，有时不能。

段落时长用目标区间或预估值，并注明依据。镜头/画面段的非重叠时长之和才是视觉时间线；旁白、音乐重叠不重复相加。转场重叠也不能算两次。需要表格时给入点、出点、计划时长、必要阅读/动作、可缩项；未实测时不给逐帧精度。

对白粗估可设本项目语速假设 `字数 ÷ 暂定每秒字数 + 停顿`，但必须标“估算”并记录假设；不同语言、语体、表演和读字环境差异很大。不得把固定字/秒、每页一分钟或某个钩子秒数当普遍定律。重要对白的试读/配音实测优先。

## 超时怎么修

优先减少该段必须传达的信息/事件、去重复、改变分段或调整总长。不能只写“加速自然完成”，不能删一条关键信息却保留后续依赖。用户锁定总时长时必须在该预算内重新分配；无法同时满足的硬要求明确提出冲突。

精确文字看得见还要来得及读懂；静音/竖屏/裁切/短版是新的观看条件，需要查关系损失，不声称所有版本同等完整。
