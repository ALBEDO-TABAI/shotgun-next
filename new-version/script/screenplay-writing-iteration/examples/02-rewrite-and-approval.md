# 润色范围与批准不能漂移

## 只润色，不代替作者换故事
虚构用户给原句：“你总这么说，可我已经不等了。”要求保留剧情、角色立场和结尾，只使口吻更接近日常。

可交：原句／候选“你每次都这么说。我不等了。”／变化说明。检查分句后是否加重指责或决绝，是否仍在用户允许范围。不能因为“更有戏”擅自添加摔杯、拥抱、哭泣、离家和解。

局部替换还不是完整当前稿。用户最终确认前，必须将替换整合到完整版本，复查前后依赖。已经提供可用稿件时，不先索要冗长人物档案阻挡工作。

## “改完就最终”怎么处理
用户：“把结尾改成她接受邀请，就定稿吧。”当前展示的是 v005 的“她未接受”。

应修改并展示 v006 候选，指出这改变结局及前文承诺。没有已展示 v006 的具体确认，不把旧稿批准自动套给新稿。可以尽量一次给完改好内容及影响说明，但不声称用户已审读 v006，不输出已批准名义的 B。

## 用户已批准现有上传稿
用户上传完整剧本，并明确：“附件就是我确认的最终版，不要改内容，直接给两版。”

应读取实际附件并绑定该快照；不存在无法读取或版本矛盾时，直接做 A/B，无需又问一次“是否确认”。若标题叫 final、正文却与其明确指定版本冲突，先报告冲突并完成不依赖冲突的部分。

## 同一结局不等于同一剧本
A：甲主动把钥匙留在桌上，乙未接收。
错误 B：乙伸手抢走钥匙。
即使钥匙最终离开甲，两者改变主动权、人物关系和事件性质，必须判不等价。

A：观众先看到密信，主角后发现。
错误 B：主角先发现密信，观众跟随得知。
即使对白完全一致，信息视点和悬念机制不同，不能由哈希/台词检查替代语义复核。
