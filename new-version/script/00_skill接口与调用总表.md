# skill接口与调用总表

## 定位

本包提供理论与知识、操作方法和接口范例，**不是可直接安装执行的技能实现**。模块名称用于说明分工，不宣称存在这些已运行工具。

同一人可以使用多个模块；同一模块也可由多人协作。不要为了对应名称就建立十一位Agent，或要求每个物料经过全部流程。

## 统一输入

```yaml
material:
  artifact: 当前作品或创作材料
  version: 当前版本
  scope: 全片、序列、场景或单图
  completeness: 完整或明确缺失项
request:
  mode: analyze
  question: 当前要解决的具体问题
context:
  purpose: 已知或明确未知
  form_profile: 现有或待建立
  facts: 有来源的事实
  assumptions: 明确标记的创作假设
  constraints: 实际要求与资源条件
```

输入不完整时，优先判断缺失是否影响当前问题。能局部回答就限定范围，不能回答就给出需要获取的材料，不擅自补全。

## 模块边界

| 篇目 | 启动条件 | 核心输出 | 不应自动做什么 |
|---|---|---|---|
| 02 | 工作或贡献不清 | 工作项、来源、转化、实现与消费者 | 无证据裁定署名或占比 |
| 03 | 起点抽象或方向未定 | 具体问题、材料状态、形式候选 | 把个人经验升级成人群洞察 |
| 04 | 行为或世界条件不成立 | 人物依据、双向关系、规则 | 给现实人物诊断或补人生档案 |
| 05 | 场景、连接或节奏问题 | 状态、连接、时间、节奏诊断 | 用固定幕结构检查所有形式 |
| 06 | 语言与互动不成立 | 话语行动、回应、场景稿 | 把每句都改成潜台词或金句 |
| 07 | 误读、留白、揭示问题 | 信息状态、路径、载体与风险 | 以作者知道代替观众可获得 |
| 08 | 评价混乱或标准冲突 | 分项判断、取舍与测试 | 生成艺术总分或统一审美 |
| 09 | 媒介／用途改变 | 各版任务、关键损失、适配方案 | 声称短版完整保留全部长版作用 |
| 10 | 需要综合练习 | 完整护肤片候选与检查示范 | 当作真实品牌方案或验证结果 |
| 11 | 分析现成材料 | 证据报告、竞争解释、最小修改 | 默默从分析跳到重写 |
| 12 | 创作迭代或交接失序 | 当前依据、阶段结果与下一验证 | 无人消费的层层报告和重复审批 |

## 统一输出

```yaml
result:
  scope: 结论适用范围
  observation: 实际材料
  interpretation: 机制假设与竞争解释
  intention_evidence: 来源或未知
  reception_evidence: 实测或未测
  decision: 当前选择及理由
  protected_relations: 不能无说明破坏的关系
  flexible_execution: 可替换的具体方式
  tradeoffs: 获得与损失
  next_validation: 对象、方法与条件
  consumers: 谁需要实际使用
  status: proposal
```

**状态必须来自实际工作**：proposal是提议；current是已选当前执行；consumed是相关使用者已理解并使用；checked是实际成果已经检查。字段写了不等于状态发生，原型检查通过不等于受众效果普遍成立。

## 三类不可合并的信息

一是世界或产品的事实与人物的信念；二是作者意图、形式机制和实际效果；三是必须一致的执行状态与允许多解的艺术意义。

一份当前事实记录不应变成唯一主题解释；允许开放也不应掩盖执行中的矛盾。

## 最小运行闭环

当前问题 → 相关材料 → 适当模块 → 有证据的候选 → 明确决定 → 实际使用 → 检查结果 → 必要时回到对应层级。

不用每次从头运行全部体系。信息读取失败回到载体，前提失实回到问题；一处界面错误不必重写整个人物，整体目的改变也不能只靠局部补丁。

## 人工与AI协作的保留条件

事实检索必须回来源；模型补写要标构造；角色模拟不是内心真相；模拟观众不是受众数据；多人或多模型一致不是独立实验证明。最终方向、事实性承诺与真实发布责任需要相应人类决策。
