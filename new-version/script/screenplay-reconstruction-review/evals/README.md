# 行为评测：20 个用例，尚未在宿主运行

[用例集](cases.json) 中每例有自拟输入、应出现行为及禁止行为。当前所有例的真实执行状态为 `NOT_RUN`。定义用例或人工写出理想答案，不等于模型已经通过。

## 在实际宿主怎么评测

使用你实际安装后的 Skill。触发测试分两组：只发自然请求检测自动匹配；再显式调用技能检测工作行为。纯工具、无关任务和两个编剧 Skill 的交界均要检查。多轮用例按描述实际展示版本并发送对应用户反馈，不能仅凭一句“前面已经批准”代替真实上下文。

每轮保存：用例 ID、宿主/模型标识、运行日期、实际输入与相关附件、完整输出、观察结果、失败定位。无需推断模型内部思考。材料不存在或技能没有正确加载时，记“无效运行”，不算创作通过或失败。

给单例 `PASS / FAIL / INCONCLUSIVE / NOT_RUN`。先查禁止行为，再查必要行为。不能用平均高分抵消虚构来源、擅自批准、剧情漂移、不可核实的工具执行等关键失败。审美偏好不同但符合任务，不自动判错。

## 反例怎么用

人工有意改一个变量，如“用户已展示后确认”换成“改一下就定稿”；“角色说信在”换成“镜头确见信”。观察行为是否随证据/授权发生相应变化。保留成功部分，失败时定位到触发描述、工作步骤、参考路由或模板，修改后重跑相关正例和反例，避免只修一个用例破坏其他入口。
