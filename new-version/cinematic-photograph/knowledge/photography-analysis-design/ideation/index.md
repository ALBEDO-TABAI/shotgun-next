# 05 正向构想：从观看任务到拍摄方案

不要从参数开始，从观众要获得的经验开始。

# 定义
* [摄影构想的定义与四种不可互替的产物](four-products-of-ideation.md) - 构想是在目的、对象和资源条件下提出观众与对象的关系并展开为规则、实施候选和检查；概念、视觉规则、制作方案、测试证据不能互相替代。

# 从 brief 到命题
* [拆 brief：任务、不可牺牲项、目标、偏好与未知](brief-decomposition.md) - 把 brief 拆成四类条目分别处理，并识别真正冲突的目标；任务不是“要拍哪些镜头”的同义词。
* [把感受词展开为候选观看关系](feeling-words-to-viewing-relations.md) - 用提问表把“亲密、可信、清爽、压迫、梦幻、克制”等感受词展开为多个可测试的观看关系，而非固定情绪配方。
* [摄影命题：不含器材的观看关系陈述，附“禁止误解”与“允许歧义”](photographic-proposition.md) - 用固定句式写出观众从何种关系开始、何时转变、最终保留什么，作为设计空间、清晰度与时间的共同依据。

# 方案与规则
* [设计两到三个有实质差异的并行候选](parallel-candidates.md) - 候选应改变观看距离、信息顺序或对象与环境关系，而非只换色调；比较设计承诺而非渲染完成度。
* [五层规则展开：任务、观看关系、形式规则、实现、检查](five-layer-rule-expansion.md) - 把摄影命题展开为五层并写出稳定项、变化项和触发条件，而不是立即锁死全部参数；检查互斥的物理要求。
* [镜头状态说明：把镜头写成状态和转折](shot-state-description.md) - 用九项字段描述镜头任务、进入与结束的信息状态、触发变化与剪辑条件；不把每个镜头设计成小高潮；平面把时间分配转成版本与关系分配。

# 测试、风险与反馈
* [测试阶梯与最小测试卡](test-ladder-and-test-card.md) - 关系草图、替代物、真实对象、短段落、目标情境五级测试各回答不同问题；用最小测试卡预先写明判断依据；探索性比较与因果检验分开。
* [按失败代价排序与降级路径](risk-ordering-and-fallbacks.md) - 优先测试一旦失败就使大量镜头重做的未知；区分脆弱方案与不可行方案；为关键风险预留最小备用而非无穷备用。
* [反馈回到正确层级：任务、关系、实现、呈现、证据](feedback-routing-layers.md) - 把反馈路由到五个层级，避免每次修改都重写整个方案；这一分层在 05、06、07 模块共同使用。
