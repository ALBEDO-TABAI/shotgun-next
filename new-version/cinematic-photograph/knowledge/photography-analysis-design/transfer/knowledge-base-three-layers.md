# 三层

| 层 | 内容 |
|---|---|
| **来源层** | 原图、片段、原始说明及其版本 |
| **分析层** | 观察、解释、候选机制和引用位置 |
| **使用层** | 新项目采用了什么、怎样修改、实际检查结果 |

- 不把分析层推测写回来源层，变成“作者就是这样想的”；
- 不因使用层成功一次，就回头把原规则改写为普遍定律。

理论依据：[来源模型 PROV](/theories/provenance-model.md) 的实体、活动、使用、生成、推导、修订 [1]；本包的简化格式**不宣称符合完整 PROV 标准**。

# 轻量目录即可起步

```text
photography-knowledge/
  cases/       每个案例的材料位置、范围和分析
  rules/       条件规则、适用范围、反例与版本
  tests/       实际测试的条件、结果和结论
  index.md     按任务与关系组织的入口
```

示例目录，不是已运行的知识系统。小项目可以把三层写在同一个 Markdown 中用标题区分，不需要先建数据库和多个 agent。

# 版本记录以解释变化为目标

规则 v1→v2 说明改了哪条条件、依据哪个新案例、旧结论哪里不再适用。保留历史不是让多个版本同时成为当前指令；当前使用应明确指向哪个版本。有版本号不自动具备可靠性。

# 信息只保留到有消费者的程度

不影响检索、执行、检查或修订的字段不必默认填写；焦距未知但对迁移不关键，记录未知即可。相反，任务前提、对象版本与实际测试范围往往影响使用，不能省略。见 [文档只在有消费者时保留](/principles/documents-need-consumers.md)。
