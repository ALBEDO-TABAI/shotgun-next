# 功能接口

| 模块 | 提供 | Skill |
|---|---|---|
| 01 风格 | 风格规则的基本概念 | [风格分析](/skills/style-analysis-skill.md) |
| 02 摄影工作 | 规则由哪些工作实现和交接 | [摄影工作分析](/skills/photography-work-skill.md) |
| 03 摄影拆解 | 机制分析 | [摄影拆解](/skills/breakdown-skill.md) |
| 04 出发点推断 | 限定推断 | [出发点推断](/skills/inference-skill.md) |
| 05 正向构想 | 形成新方案 | [正向构想](/skills/ideation-skill.md) |
| 06 评价 | 检查结果 | [摄影评价](/skills/evaluation-skill.md) |
| 07 规则迁移 | 把结果沉淀并重新投入使用 | [案例到条件规则](/skills/case-to-rule-skill.md) |

这些是**功能接口，不要求七个独立 agent**。小任务可由一个流程完成，只要不同类型的结论不互相冒充；复杂协作再按实际需要分工，避免为理论章节数量机械创造同数量的部门。

# 三条阅读／使用路径

| 目标 | 路径 |
|---|---|
| **分析已有作品** | 01 识别风格结构 → 03 拆画面 → 04 控制推断 → 06 评价；需理解制作协作时加入 02；最后用 07 保存可迁移规则 |
| **构想新项目** | 05 从任务和命题开始 → 03 检查机制与条件 → 02 明确协作与交接 → 06 设计检查 → 07 记录本次实际经验 |
| **整理 agent skill** | 阅读各模块的输入、执行、输出、降级和质量要求，再用 07 整合 |

这里提供的是知识与规范草案，不是已安装或通过自动化测试的技能实现；不要求每次局部提问都机械运行所有章节，只启用相关分析并保留必要的证据边界（[最小输出原则](/principles/minimum-output-principle.md)）。
