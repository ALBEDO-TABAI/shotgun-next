# 输入

最小输入：作品／制作任务、当前阶段、实际可用材料、已确认要求。团队规模、既有权限、交付画幅若未知先标未知；只有它们会改变当前结论时才进一步询问。

# 步骤

1. 界定当前问题是**职责分析**、**方案分解**还是**交接检查**；
2. 把任务映射到视觉决策（[六种必须分开的东西](/work/six-things-to-separate.md)），找出各决策依赖的对象、材料和上游确认；
3. 检查每项决策的实现活动、产物与消费者（[摄影的六类工作](/work/six-kinds-of-photography-work.md)、[按制作阶段检查](/work/stage-by-stage-checks.md)）；
4. 报告未被分配的工作和互相冲突的要求（[协作边界](/work/decision-centered-collaboration.md)、[冲突解决](/work/conflict-resolution-not-averaging.md)）。

不把整套流程机械应用到局部咨询：用户只问“摄影为什么需要参与标签测试”，就聚焦表面、机位、识别要求的依赖。

# 输出模板

```text
分析范围／制作阶段：
任务与不可牺牲项：
当前视觉决策及依据：
实现活动与参与功能：
已确认权限／仍需确认权限：
交付对象、版本与接收端：
接收端必须执行的下一动作：
已检查的关系与证据：
未检查／有冲突的关系：
最小必要修改及其影响范围：
```

# 质量检查

- 报告必须能回答“这个任务由谁使用哪个结果继续工作”；
- 每个声称完成的检查指向实际材料；纯计划标为待执行；
- 职位名称不替代具体活动，器材不替代视觉目的，**发送成功不替代接收成功**（[最小交接单元](/work/minimum-handoff-unit.md)）；
- 无幕后资料时可完成视觉工作类型分析，**不得完成个人贡献裁定**（[摄影贡献归属](/work/attributing-photographic-contribution.md)）；
- 无明确需求时可识别候选任务，不得认定其中一种为客户已确认。

# 练习与自检

1. 选一张自己做过的图，找一个成立的关系（如主体与背景分离），写出任务、实现、依赖与验证方式；检查是否把后期或美术的工作误算成摄影独立贡献。
2. 选一个失败交接：丢失的是素材、版本、意图、允许调整范围，还是接收动作？只修改一个真正有消费者的字段，看是否足以避免误解。
3. 把同一工作卡交给熟悉项目与不了解项目的人，让他们复述下一步和不能改的地方——复述差异是接口问题，不自动说明谁能力不足。
