# 变更、交付与接续

制作协调需要准确传递进度、成本和交付资料。[P2](sources.md#p2) 本页只保留能帮助下一步行动的信息。

## 变更先分类

- 目标改变：新受众、新结局、新产品或片长；可能改变结构与资源。
- 表达改变：同目标换风格、机位或声音；检查专业依赖和已完成资产。
- 修复偏差：现有结果未达到已定要求；定位当前缺陷，防止借修复增加新需求。
- 交付改变：横竖版、字幕、语言、字幕安全区域、无字版、分轨；计入制作与检查。

只写一个变更记录：当前版本、变化、原因、影响的场景 / 镜头 / 资产、增减成本与时间、可复用部分、决定与责任人。没有发生变化就不制造每日重写的长状态报告。

## 接续最小信息

已完成并可使用的工件；正在执行的准确任务；未结费用或承诺；下一步的实际输入与条件；当前阻塞及解除动作。状态按证据描述，例如“文字已检查，未制作素材”“成片已导出，未在接收方播放器验证”。

“文件存在”“模型说完成”“页面显示成功”都不足以替代本次交付检查。但不要求计划阶段凭空提交成片。

## 交付矩阵

| 项 | 确认内容 | 检查依据 |
|---|---|---|
| 主片 | 时长、画幅、帧率、音频、语言 | 用户规格与实际文件信息 |
| 衍生版 | 裁切 / 重排、文字、结尾、声音不同项 | 对应版本完整播放 |
| 配套 | 字幕、无字版、音频分轨、封面、文案 | 用户实际请求；不自动扩范围 |
| 工程 / 素材 | 可重新打开、引用齐全、版权说明 | 交接范围和本次可用文件 |
| 接收 | 接收方式、命名、验收者、截止 | 正确对象、实际文件与读回 |

发行平台参数会变；只在本次要正式交付时查当前接收规格。未指定平台就写目标规格待确认，不把某平台惯例当所有视频标准。

## 跨岗责任

制片可指出“六个地点无法在两天拍完”，并给“合并到两地点”的方案与代价；不默改剧本。导演选择后，编剧 / 美术 / 摄影按各自责任修订。剪辑版本改变后，及时通知声音、字幕、合成，避免旧成果覆盖新版本。

VVF 共同头部仅在需要时启用：`project_id / artifact_id / revision / based_on / owner / status / open_questions / changes`。`ready` 是规划可用，不是已预订、已支付、已获使用权或已拍摄。对外联系、采购、发送与发布需来自用户真实授权，任务表本身不授予权限。
