# 版本、竖屏与交付

平台、观看条件和未来再编辑用途会影响剪辑；交付应按接收方规格与实际文件验证。[E1](sources.md#e1)、[E3](sources.md#e3)

## 先定义版本差异

同故事换画幅、不同语言、不同字幕、短版、无字版、音乐替换版不是同一种变化。保持一个版本列表，记录来源版本与真正差异；不以“最终最终”充当身份。

只在需要跨岗时用 VVF 头部：`project_id / artifact_id / revision / based_on / owner / status / open_questions / changes`。`ready` 是方案检查，不代表媒体已导出。实际成片应另说明导出、播放和交付状态。

## 竖屏 / 多画幅

逐镜检查人物关系、动作接触点、地标、视线目标、产品 / 关键文字，而非自动跟脸居中。双人横向关系硬裁后只剩一个人时，可用另一条素材、重排切点、合理分屏或保留留边；每种方案都说明对叙事的影响。

9:16是成片画幅，不自动意味着每段源素材必须满屏硬裁。用户未禁止留边或分屏时，可以直接把它们作为满足原需求的方案，不虚构一条“必须满屏”限制再请求放宽；只有用户明确锁定的呈现方式与必要信息冲突时，才列为需改变的要求。

字幕位置与平台界面有关，按当前目标界面和实际播放核查。未知平台不捏造固定安全区域。手机尺寸完整观看，检查字可读、必要动作没被界面遮挡、无声观看时需理解的信息是否有替代；并非所有片都必须静音完全等价。

## 时间与素材管理

稳定素材标识，注明源范围与成片范围、时间单位、帧率与变速。源 in/out 与时间线 in/out 必须区分；在精确编辑中说明出点是否包含该帧。没有实际素材只给相对时间和动作锚点。

保存原始素材与可重连引用，不默认覆盖。字幕、无字背景、声音分轨等只按交付范围保留，避免过度打包；需要未来换语言时提前保留对应可编辑材料。[E3](sources.md#e3)

## 实际交付检查

1. 规格：时长、尺寸、画幅、帧率、编码、音频和字幕按本次要求。
2. 内容：完整播放当前导出，留意首尾、切点残帧、黑帧、跳音、同步、字幕、色彩与构图。
3. 版本：当前画面、声音、字幕和图形一致；旧声音不因文件名相同覆盖新剪辑。
4. 接收：在目标或等效播放器打开，必要时上传后读回；未做则明确未验证。

没有素材或工具时，交付可执行剪辑表与明确验证计划即可，不伪装已完成以上媒体检查。

## 返修收敛

把反馈绑定具体版本、时间与期望变化。一次先解决能验证的目标，保留正确部分。新意见改变原 brief 时记录范围变化；不把所有新喜好混称上一版错误。检查已通过且无新问题时停止，不持续追加无目的快切、转场和调色。
