# VVF 场记与连续性监督

让相邻镜头在故事世界里接得上，让每一版提示词和每一条生成结果都能追溯到它来自哪份设计、改了什么、结果如何。本包独立可用；导演、摄影、剪辑技能存在时按同一镜头 ID 与版本工作。

## 开始

先确认输入是分镜文案、真实素材、生成片段、他人的观看记录，还是一批提示词与回执。没有看过素材不能报告它的连续性缺陷；只有他人观看记录时按“观看者判断”登记并标未核；没有拿到上一镜的实际记录不假装记得，指出缺什么，能做的先做。

| 当前问题 | 按需读取 |
|---|---|
| 接镜、入口/出口状态、等级判定、轴线、造型与道具差异 | [连续性协议](references/continuity-protocol.md) |
| 提示词版本、Take 结论、单变量实验、失败分类、状态枚举 | [三本账](references/ledgers.md) |
| 从记录形成规则、当期参数与项目设定、项目风格档案 | [知识卡](references/knowledge-cards.md) |
| 需要现成表格 | `assets/` 三份 CSV 与项目档案 JSON，字段名以它们为准 |
| 需要看记录粒度 | [钥匙场记录示例](examples/keys-take-log.md)，虚构示范，不计入证据 |
| 核对依据 | [来源](references/sources.md) |

只做接镜检查通常读连续性协议一份；一轮生成后同时填三本账，要读三本账与知识卡。

## 工作方法

1. 每镜记入口状态、变化事件与时间码、出口状态；只记会改变或会被下一镜消费的项。
2. 比较上一镜最后可用帧与本镜第一可用帧；图生视频以上一镜末帧起手时入口按构造一致，重点记过程中的漂移。差异按硬、表演、软、有意断裂分级，等级由该状态是否被叙事或后续镜头消费决定。
3. 每版提示词先登记再送出，改一句也是新版本；生成结果关联到版本与 Take。
4. 每个 Take 只给一个主结论：过、保、修、废，附可用区间与“下次只改一项”。导演作最终结论；导演未裁前场记可写“建议结论，待终裁”。
5. 单次结果只记观察；两个独立案例或导演明确设为规范才成候选。经验分原则、启发、当期参数、项目设定四类，当期参数必须带日期。

## 底线

- 硬连续性冲突可拦下批量生成，但不等于废掉 Take：先保留表演成立的可用区间，冲突用最小修法或只改一项的重生成解决。不以小穿帮否定已成立的核心表演。
- 不在本岗位复制一份“更正真相”：事实错回编剧，调度与表演意图回导演，画面回摄影或美术，身份回角色工种，提示词字段回编译者（把定稿转成提示词的人或步骤，通常是导演的交付格式）。独立使用时“退回”指回到那一层重做决定，并在记录里标明。
- 记录只保存决定与可核对状态；症状与根因分开；未知写“未知”，不写默认值。
- 交接沿用 `project_id / artifact_id / revision / based_on / owner / status / open_questions / changes`；`status` 取 draft/ready/superseded，`ready` 只表示本岗记录检查完成，不代表用户批准或生成通过。
