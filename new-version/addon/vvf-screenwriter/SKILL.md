# VVF 编剧

交付让下一位创作者知道“发生什么、谁为什么行动、哪些事实不能改”的文本。篇幅服从任务；成熟剧本只修指定问题，不重新走全流程。

先判定原创 / 改编 / 纪实 / 修订，确认目标长度、观众、媒介和不可更改项。已有材料优先；影响结局、人物身份或事实真实性的缺失不能偷偷补成事实。其他缺项用明确假设推进。

最小工作法：提炼作品问题与人物行动 → 选择合适的结构 → 写可见动作与可听台词 → 检查因果、信息与时长 → 交付当前版本及剩余依赖。一个短场景可直接写，不强制先交大纲。

| 当前问题 | 只读对应资料 |
|---|---|
| 想法有了但故事不成立；长片、短片、系列结构 | [故事架构](references/story-architecture.md) |
| 人物空、台词直白、场景没有推进 | [行为与对白](references/scene-behavior-dialogue.md) |
| 广告、纪实、教学、喜剧、动画等该怎样区别 | [内容模式](references/mode-routing.md) |
| 从原作、采访或真实事件改编 | [改编与证据](references/adaptation-evidence.md) |
| 连续修订、转交导演、输出格式 | [修订与交接](references/revision-handoff.md) |
| 需要完整输出标尺 | [《先别关灯》案例](examples/last-light.md) |
| 核对来源和方法边界 | [来源](references/sources.md) |

不要默认全读。首次通常入口加一个问题模块；遇到相邻缺口再补。停止条件是本次故事文本可用、检查没有未处理矛盾；不为补齐分类扩写。

守住三条：创作建议不是普遍定律；纪实不虚构证词与因果；未经委托不替导演定全部机位、不替角色设计重写身份外观。用户同时委托这些工作时可以继续，但分清哪些已决定、哪些是建议。

只在跨角色或持续编辑时使用共同头部：`project_id / artifact_id / revision / based_on / owner / status / open_questions / changes`。`status` 为 `draft / ready / superseded`；`ready` 仅表示本角色文本检查完成。正文不必 JSON 化；不依赖其他技能或联网才能使用。
