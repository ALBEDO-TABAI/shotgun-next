交付版本：2026-09-18。正文按创作任务重组，不是旧13篇笔记的同名覆盖包。

## 从这里开始

解压整个压缩包，双击根目录的 **`开始阅读.html`**，用桌面浏览器阅读。阅读器自带全部正文、目录与全文搜索，不需要服务器、账号、联网或安装Python。外部来源链接只有主动点击时才需要网络。

左侧可按章节浏览，也可搜索“清爽”“后摄”“微表情”等词；多个词以空格分开。顶部切换分章或全书模式。提示样稿旁有复制按钮；浏览器限制剪贴板时，可以直接选中文字复制。桌面版可以打印当前章节或全书；打印前会展开来源说明。窄屏用“目录”按钮打开导航，宽表格可在表格内部横向滑动。

本次在Chromium中对生成HTML做了桌面与窄屏渲染、全部56个页面入口、搜索、复制反馈、主题与全书模式检查。运行环境的浏览器策略禁止`file://`跳转，因此界面检查采用读取同一个本地HTML后注入浏览器的方式；未声称完成所有系统、浏览器与手机文件管理器的兼容测试。普通桌面浏览器可直接读取这个不依赖外部资源的单文件；受管设备可能限制本地脚本，此时可直接读Markdown。

## 一本书的三种读法

**先建立方法**：从“六层转译”读到“三种稿子”，再看通感与联想。你会把“希望观众得到什么”与“怎样实现”分开，而不是一上来寻找高级形容词。

**带着任务查**：生图、改图、图生视频、多镜头、复杂调度分别有流程；表演、摄影、美术、光线、声音和剪辑分别有专业章节。只调用需要的部分，不要求每个小任务走完整套流程。

**通过案例练**：先读《留一点空隙》品牌片，再对照餐桌对话、外放喜悦、手机Vlog、空走廊、超现实香水、喜剧和道具交接。每个案例给出设计取舍、执行样稿与验收/修复方向；最后用十二项练习建立自己的实例库。

## 给Agent使用

`knowledge/contemporary-prompting/`中的Markdown是内容源，遵循上传skill所要求的OKF v0.1。每个知识单元有类型、主题、标签、来源与相关概念链接；根目录建立了独立工作区索引。

`skills/contemporary-prompt-expert/SKILL.md`是本指南的轻量消费入口：让助手先判断任务，再读取相关知识，而不是把整本书一次塞入上下文。保持该文件与`knowledge/`的相对目录；单独复制SKILL文件不构成完整安装。**没有自动安装到任何应用、修改GitHub或写入持久Library，也不附带生成、支付和外部写入权限。**

包内以`/`开头的Markdown链接，按OKF语义相对于知识包根目录解析；普通Markdown编辑器未必懂这个约定。离线HTML已把它们转换成正确的章内跳转；用其他知识工具时需按包根解析。

## 来源与作品边界

本指南读取的是上一轮13组教程的文字复审包，其中29份Markdown被作为直接输入。保留同字节ZIP副本与SHA-256范围记录，但**没有把这次工作描述成原视频、音轨或全部截图的逐项核验**。

第一方资料用于校正工具输入、提示习惯和技术术语。六层转译、三稿分工、图谱与案例是本次系统提炼或原创设计，不是已建立的统一学术定律。理论参考明确说明它们支持的有限结论。

**所有案例均为设计样稿，未进行生图、生视频、配音或音乐生成。** 案例中的人物、产品、时长与参考代称是设计条件；并不代表已附对应媒体。实际制作仍需核对工具能力、素材、授权与结果。诗意与通感是构思方法，不是把比喻逐字变成画面的命令。

## 编辑、重建和校验

只读不需依赖。维护时建议在Python虚拟环境中安装`requirements.txt`所列依赖。脚本不联网、不调用生成服务、不改来源ZIP。

在交付根目录运行：

```bash
# 检查原样收到的包：结构、链接、阅读器同步、输入摘要、交付文件摘要
python scripts/verify.py

# 使用上传skill附带的原始OKF校验器
python scripts/okf_tools.py validate knowledge/contemporary-prompting --verbose

# 修改Markdown之后，重建阅读器并检查内容；跳过旧版本交付摘要
python scripts/build_reader.py
python scripts/verify.py --skip-checksums

# 解压位置变化或内容更新后，刷新本地工作区索引
python scripts/refresh_index.py
```

原校验器按绝对路径保存索引登记；`refresh_index.py`负责把本包人工维护的母题、状态和说明迁到解压后的实际路径。它会写入本地`OKF-INDEX.md`，不会写入任何外部工作区。

`SHA256SUMS.txt`记录的是**这次交付快照**。编辑正文、重建HTML、刷新索引或写入新检查报告，都会使相关交付摘要失效，这是正常的，不是内容自动损坏。自用编辑后用`--skip-checksums`检查内容，正式再发行时重新建立自己的摘要清单与版本记录，不要把旧检查报告当成新版本结果。

`qa/file_check.json`为最终打包前的内容检查；最终快照摘要另由`SHA256SUMS.txt`验证，避免报告为记录自己的摘要而不断变化。`qa/browser_check.json`记录实际界面检查与加载方式，均不代表生成质量实测。
