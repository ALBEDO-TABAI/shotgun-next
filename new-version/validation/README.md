## 试用后修正

按“修真正拥有问题的文件，不为每个案例加铁律”处理，逐项见 `../CHANGELOG.md` 的“两轮独立试用后的修订”。最影响结果的几处：

1. **提交单位**：试用 A 因为技能没说字数上限按整包还是按每次调用，把 1771 字压到 1481。现在编译文件区分整包与逐单元提交，脚本加 `--per-shot`；同一份提示按逐单元计算是 711、746、794 字，压缩本不必要。
2. **编译时的假设边界**：编译文件“不新增创作决定”与入口“可撤回假设”看似冲突。现在写明执行细节可假设并标“本次新增”，改变事实、观看任务、产品事实的才退回。
3. **资产表缺产品或道具类、只有一侧手部参考、首帧图占名额、连续性帧的两段式回填**：均已补。
4. **场记 addon 的枚举与字段**：状态、知识类型、候选字段名在参考与 CSV 里各不相同，CSV 行模型不清，示例的版本账与 Take 账互指不成立；已统一并重写示例。
5. **等级谁定**：门、茶杯、光线这类状态以前不在任何等级里；现在由“是否被后续镜头消费”决定，不确定时暂定硬并标待确认。

修正后重跑：结构校验 0 错误；两份试用提示均通过校验。试用者的作品保留原样，不按修正后的技能改写。

## 复查方法

在上级目录用带 PyYAML 与 markdown-it-py 的 Python 运行：

```bash
python tools/validate_bundle.py new-version --report new-version/validation/structure.json
python3 new-version/director-skill/vvf-director-skill/scripts/validate_prompt.py <prompt.txt> --max-chars <当次上限> --per-shot --max-handles <当次上限>
```

文件指纹见 `../bundle-manifest.json`。
