# 步骤

1. **最短因果说明**：观察到什么 → 它影响哪个任务 → 可能来自哪些层 → 最小可比较修改是什么 → 哪些下游需要更新。
2. 不把所有问题下发为"再高级一点""再紧凑一点"——无法验证，且让各部门做出相互冲突的加强。
3. **记录不修改的理由**：明知局部代价但整体保留，不等于没发现问题；关键是代价是否被理解、是否在批准范围内、是否伤及事实或安全底线。
4. **争议处理**："太慢""太广告""太文艺""不够高级"先保留为观看反馈。追问发生区间及具体损失：等不到新信息，还是需要的信息来不及读？产品展示打断人物行动，还是原本就不接受商业表达？
5. 不同评审者使用不同目标时，他们可能都描述了真实体验却无法用同一改动满足。回到版本任务，明确这一版优先服务什么；不把意见最多的一方当普遍观众。
6. 有时保留两种候选而非反复折中（强调人物体验的完整片＋快速识别产品的投放短版）。项目只需一个版本时必须明确取舍，不把两个开头、两种结尾、两套音乐塞进同一条片。
7. **结束一个版本**：不要求再无其他可能，而要求当前版本的目的、重要选择、已知代价和交付范围足够明确。不因审美永远可争论就让当前任务无限延期。
