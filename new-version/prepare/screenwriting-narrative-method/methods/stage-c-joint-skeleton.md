# 要点

| 子任务 | 做什么 | 不做什么 |
|---|---|---|
| 人物与规则 | 检查任务、信念、资源、关系与后果；关键规则有适用范围，人物知识有获取路径 | 为了完整补无用小传 |
| 场景序列 | 每段说明为什么值得经历、进入与离开状态、段间连接；区分事件、信息、经验与视听变化 | 给所有场景强加冲突 |
| 信息 | 确定必须清楚、可延迟、可开放与可省略的内容；分别记录确立事实、人物误信、观众未知 | 以作者知道代替观众可获得 |
| 结构比较 | 先试重排、合并、删减、改载体，再做大规模润色；每项变化检查影响 | 让局部优秀掩盖整体断裂 |

## 交付

当前大纲、关键场景草稿、简化人物与规则说明、必要信息关系。不必四份独立文件：小项目可以合并，复杂项目再按使用者拆分。

# 适用边界 / 不应自动做什么

- 骨架服务于当前问题，不是设定仓库。
- 结构比较先于润色。
