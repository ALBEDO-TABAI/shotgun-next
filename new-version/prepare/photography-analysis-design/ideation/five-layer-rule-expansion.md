# 五层

| 层 | 内容 |
|---|---|
| 任务层 | 当前段落需要建立什么理解或体验 |
| 观看关系层 | 观众与对象的距离、信息开放与时间关系 |
| 形式规则层 | 机位、画框、清晰、光影、运动怎样配合，何时改变 |
| 实现层 | 当前器材、场景、动作或生成工具的候选设置 |
| 检查层 | 在何种材料和观看条件下，确认哪些关系 |

- 前几层比具体设备更适合跨项目迁移（对应 07 模块 [迁移什么](/transfer/what-to-transfer.md)）。
- 实现层可以改变，但必须重新检查是否保住关键关系。更换器材不必然改变命题；命题不变也不等于无需测试。

# 稳定项 · 变化项 · 触发条件

| 要素 | 例子 | 只写它的后果 |
|---|---|---|
| 稳定项 | 使用段落始终保留接触位置 | 作品被压成机械重复 |
| 变化项 | 包装完整程度 | 缺少整体组织 |
| 触发条件 | 动作从使用转入展示 | （缺失时）每个执行者自行判断何时改变 |

三者一起构成规则（02 模块 [规则设计](/work/six-kinds-of-photography-work.md) 的同一原理）。即兴或纪录拍摄中，触发条件可以是开放原则而非精确秒数，例如“当人物开始处理某件物品，先保持动作关系，不立即切入孤立特写”——这与要求人物按分镜表演不是一回事。

# 不要同时给出互斥的物理要求

若同时要求极近距离、全部前后对象清晰、背景完全不可辨和自然比例，先核查能否共同成立；可改变对象布局、分段任务、采用不同实现或明确取舍。03 模块的成像关系（[透视](/breakdown/viewpoint-focal-length-format-perspective.md)、[景深](/breakdown/clarity-focus-depth-of-field.md)）用于**限制错误承诺**，不是让数学代替创作 [1][2][3]。即使可通过合成实现，也应明确它已不是原先假设的单次物理拍摄。
