# 输入

实际作品或结果、当前阶段与版本、已确认要求、目标观看条件、现有测试记录。缺少任务时可做描述性评论，但避免宣布“适合／不适合客户”。

# 执行

1. 声明范围（[评价范围](/evaluation/evaluation-scope.md)）；
2. 分离硬条件与软目标（[先硬条件，再讨论取舍](/evaluation/hard-conditions-over-total-scores.md)）；
3. 按问题观察（[三轮评审观看](/evaluation/three-pass-review.md)、[六个评价维度](/evaluation/six-evaluation-dimensions.md)）；
4. 将反馈分类并关联任务（[六类问题分类](/evaluation/six-problem-categories.md)）；
5. 必要时**设计而非伪造**测试（[观看测试与 A/B 纪律](/evaluation/viewing-tests-and-ab-discipline.md)）；
6. 提出最小修改及保护项（[批评反馈卡](/evaluation/critique-feedback-card.md)），只对已检查范围给出状态。

# 输出

```text
评价范围／版本／观看条件：
采用的标准及来源：
已满足的关键关系：
问题与可复核证据：
问题类别和任务影响：
尚未确定的观众效果：
候选修改及其代价：
需要的测试或确认：
限定范围内的结论状态：
后续复核要求：
```

# 质量边界

- 不用个人偏好替代缺陷；不用自动分数替代作品任务（[指标与测量层级](/evaluation/metrics-and-levels.md)）；
- 不把注意、理解、情绪和购买连成无证据因果链；
- 不因器材高级、制作困难或出处知名而免于检查；也不因不遵循常见构图而自动否定；
- 没有运行的测量保持为空；没看的版本不宣称通过；没做目标人群测试不宣称所有观众都会有某种感受。

# 练习：让一条批评真正可以执行

1. 对“太平”“不够高级”“不够有电影感”各写出可能指向的三个不同问题，指出区分它们需要看什么。
2. 选两个各有优点的方案，先列硬条件，再写各自保护和牺牲的关系；不用总分作出与项目相连的选择理由。
3. 设计一次小规模探索性观看活动：明确只用于发现问题、不能估计总体偏好；写出不诱导的问题，保留反预期反馈。
