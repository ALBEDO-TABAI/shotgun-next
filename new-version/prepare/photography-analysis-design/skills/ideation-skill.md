# 输入

作品目标、内容与对象、必须遵守的约束、可用资源、交付条件、参考材料及其真实性范围。缺失内容先标为假设；**不把自己猜出的品牌偏好写成用户确认**。

# 执行

1. 输出经过分类的 brief（[拆 brief](/ideation/brief-decomposition.md)）；
2. 提出不含器材的观看命题（[感受词展开](/ideation/feeling-words-to-viewing-relations.md)、[摄影命题](/ideation/photographic-proposition.md)）；
3. 形成少量结构上不同的候选，说明各自优先与牺牲（[并行候选](/ideation/parallel-candidates.md)）；
4. 选定方向后展开条件规则与镜头状态（[五层规则展开](/ideation/five-layer-rule-expansion.md)、[镜头状态说明](/ideation/shot-state-description.md)）；
5. 给出按风险排序的测试（[测试阶梯](/ideation/test-ladder-and-test-card.md)、[失败代价排序](/ideation/risk-ordering-and-fallbacks.md)），而不是宣称未执行方案已经有效。

# 输出

```text
任务、约束、偏好与未知：
观看命题：
候选方案与关键差异：
当前选择及其依据：
稳定规则、变化项与触发条件：
镜头／系列的功能分配：
实现候选与暂未锁定参数：
最关键的测试、条件和判断依据：
允许调整范围与备用路径：
需要确认的事项：
已完成的工作／仍待执行的工作：
```

# 质量检查

- 每个重要参数都能追溯到一个关系或已知限制；每个重要风险有相应测试或明确接受理由；
- 候选必须有真实差异，不能只换形容词；
- 测试计划不写成测试结论，效果目标不写成观众保证；
- AI 工作流同样分开请求、生成结果与验收；“真实材质”“电影感”不构成完成证据。工具更换时先保留观看任务再更新实现层（[AI 工作流](/transfer/ai-intent-request-result.md)）。

# 练习

1. 拿一个抽象 brief 写两种互不相同的观看命题，禁止镜头型号和滤镜名，检查是否已产生不同的空间和信息安排。
2. 为一个方案设计三种不同精度的测试，说明各能回答什么、不能回答什么。
3. 模拟变更（产品必须更早出现，或增加竖版），沿任务—规则—镜头—测试查影响范围，只改必要部分并标明需重新确认的关系。
