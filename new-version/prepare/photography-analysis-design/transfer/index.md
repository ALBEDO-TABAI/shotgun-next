# 07 规则迁移：案例知识库与 Skill 化

把分析沉淀成可迁移的摄影规则，而不是参考图收藏。

# 定义
* [可迁移摄影知识的定义与四种保存对象](transferable-knowledge-definition.md) - 可迁移知识是在明确条件下关于观看关系的主张，连同来源、实现候选、适用边界、反例与检查办法；素材、案例、规则、原则四层须分开保存。
* [迁移什么：观看功能、关系结构、实现机制、表面特征、条件与代价](what-to-transfer.md) - 提炼前把参考拆成五种内容；同一功能可有不同实现，同一机制可承担不同功能，表面差异有时正是迁移失败的原因。

# 规则与映射
* [规则卡：一条可迁移规则至少包含什么](rule-card.md) - 规则卡字段、用关系句命名、状态带范围、容许变化有限度——把风格与案例分析沉淀为有边界的条件规则。
* [来源到目标的关系映射表与三种迁移结果](source-target-mapping.md) - 逐项映射来源案例的角色与关系到目标，标明值得保留与必须重解的部分；迁移结果可以是直接复用、保留关系改写实现，或拒绝适用。
* [按任务与条件检索，而非只按相似外观](task-based-retrieval.md) - 把检索问题改写为任务与关系；至少比较一个异形同构案例和一个反例；检索分数不等于适用置信度。
* [案例到规则的完整循环：检索、复用、修正、保留](case-rule-cycle.md) - 把案例推理的四阶段循环转译为摄影流程，保存成功、失败与未能区分的结果。

# 知识库与 AI 工作流
* [知识库三层事实分离：来源层、分析层、使用层](knowledge-base-three-layers.md) - 保持来源、分析、使用三层事实分离并用明确关系连接；轻量目录即可起步；版本记录解释变化；信息只保留到有消费者的程度。
* [AI 工作流：把意图、请求和结果分开](ai-intent-request-result.md) - 意图层、请求层、结果层不能互相证明；先传递可见要求再附实现语言；结果分技术与任务两层检查；改写提示不是唯一反馈动作。

# 验收
* [检验一个 skill：五项能力、测试集构成、验收题与错误分类](skill-capability-acceptance.md) - 用描述、证据、适配、验证、更新五项能力检验 skill；测试集须含不该迁移的案例；附七道假设验收题与八类错误。
