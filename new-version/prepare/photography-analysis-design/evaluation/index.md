# 06 评价：标准、取舍与验证方法

从“我喜不喜欢”，转向“它解决了什么，付出了什么”。

# 标准与范围
* [四种“好”：实现可靠、形式有效、任务适合、审美判断](four-kinds-of-good.md) - 评价前先分清要评哪一种“好”，四者相互影响但不能互相替代；核心是先声明对象、条件和标准，再用相匹配的证据判断。
* [先声明评价范围：版本、尺度，以及描述—解释—判断—建议分写](evaluation-scope.md) - 记录版本、画幅、声音、观看大小、阶段与任务；评价停在实际检查的尺度上；观察、功能解释、条件性评价、候选修改分别书写。
* [六个评价维度（不机械打分）](six-evaluation-dimensions.md) - 对象准确、技术适足、信息与时间组织、形式组织、项目适配与代价、审美与呈现责任六个维度，各有合适证据与不充分替代物。
* [六类问题分类：避免把所有不喜欢都叫缺陷](six-problem-categories.md) - 明确错误、任务失效、策略取舍、风格偏离、个人偏好、证据不足六类问题需要不同处理。
* [把指标放回它们真正测量的层级](metrics-and-levels.md) - 注意、理解、情绪、行为不能串成无证据的链；指标可诊断但不能替换目标；SSIM、NIMA、VBench 与主观质量评测各有对象边界。

# 评审与测试
* [三轮评审观看](three-pass-review.md) - 第一轮按作品预期方式完整观看，第二轮按问题诊断，第三轮回到整体检查修改代价。
* [观看测试与 A/B 比较的最小纪律](viewing-tests-and-ab-discipline.md) - 测试问题要具体不诱导，明确参与者与推广范围，A/B 设计处理顺序与干扰因素，并记录不支持预期的结果。

# 决策与反馈
* [决策不必用总分：先硬条件，再讨论可接受取舍](hard-conditions-over-total-scores.md) - 硬条件不被高分平均抵消也不能临时发明；不相互支配的方案需要明确价值选择；用决策状态代替伪精确综合分。
* [批评反馈卡：证据—任务—影响—修改—保护项](critique-feedback-card.md) - 把“太暗”“太慢”“AI 感太强”之类评语改写为包含范围、证据、任务、影响、最小修改与保护项的可执行反馈。
