# 1. 测试问题要具体

- 好问题：“你看到了哪些动作？顺序是什么？”“哪一处让你无法判断？”“你认为对象之间是什么关系？”——先收集未经提示的描述，再询问具体项。
- 坏问题：“是不是更高级、更梦幻了？”——预期答案已写进问题。若研究的就是这些词，要说明定义、询问方式与分析方法。
- 允许歧义的作品：观察解读分布和依据，而不只统计是否回答了作者预想的主题。

# 2. 谁参与，结论推广到哪里

| 参与者 | 适合回答 |
|---|---|
| 熟悉项目的制作人员 | 某些实现问题 |
| 不了解项目的人 | 暴露说明依赖 |
| 目标受众 | 另一类（受众理解／反应）问题 |

不能用内部团队的熟悉程度证明首次观看者已理解。样本数量没有万能值：探索性访谈能发现问题，不能估计总体偏好比例。

# 3. A/B 比较的最小纪律

依据 NIST 的实验设计与区组方法 [1][2]：

- 先固定测试目标与待比较版本，再安排呈示顺序、观看条件和记录方式；
- 避免所有人都先看 A 再看 B；
- 展示前不把某版称为“优化版”；
- 同一人重复观看要考虑熟悉与记忆影响；不同人观看要注意组间差异；
- 若 A、B 同时改变光线、剪辑和演员动作，只能比较整体方案，**不能归因于单一灯光因素**。

形式上叫 A/B 不等于因果成立。

# 4. 记录不支持预期的结果

- 测试前写清什么会支持、削弱或无法区分候选；结果不明确就报告不明确，不在观察后更换成功标准。
- 不把非预期反馈都归为观众“不懂”，也不让单一反馈立即推翻全部设计。
- 本包没有实际测试数据，因此**不给出效应量、显著性或通过率**；将来采集时保留样本、程序与原始记录。
