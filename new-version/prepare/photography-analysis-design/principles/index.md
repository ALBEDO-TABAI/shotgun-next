# 跨模块原则与证据纪律

贯穿全部模块的研究与表述纪律。

# 证据纪律（Evidence Policy）
* [原始来源与工作化综合分开](source-vs-working-synthesis.md) - 引用只支持旁边的具体理论、方法或事实；流程、表格、规则卡、测试安排与跨领域迁移均标为本包提案，不借文献把自己的框架包装成学界标准。
* [不把不同证据混成同一种“科学性”](evidence-types-not-interchangeable.md) - 光学模型、观看实验、实践案例、规范文档、理论模型各回答不同问题，不能互相替代；物理可实现≠艺术有效，被注意≠被理解。
* [核读范围逐条记录](record-reading-scope.md) - 逐条注明每个来源实际核读了正文、摘要、作者说明还是指定页面；不声称通读专著、复现算法或重算实验；本包是定向研究综合而非系统综述。
* [案例与测试的事实状态分开](case-and-test-factual-status.md) - 真实制作案例须给出来源，其余商业、纪录、艺术与 AI 示例均为虚构；测试表是待执行方案，验收题是测试设计，不是“已验证通过”的报告。

# 工作原则
* [最小输出原则：六件事比更多风格名与参数更重要](minimum-output-principle.md) - 无论使用哪个模块，输出都应区分看到了什么、作出了什么解释、依据什么、哪些未知、决定改变什么、用什么确认改变有效。
* [效果推断阶梯：形式突出→注意→理解→情绪→行为](effect-inference-ladder.md) - 五个层级是不同结论，每层需要自己的证据；不能从“产品很亮”跳到“观众会喜欢”再跳到“会促进购买”。
* [不建立固定的“技术—情绪”词典](no-fixed-emotion-dictionary.md) - 技法没有唯一情绪译码；低机位≠权威、低饱和≠忧郁、浅景深≠梦幻——情绪解释需结合其他关系与上下文，并作为待检验假设。
* [文档与字段只在有消费者时保留](documents-need-consumers.md) - 没有执行或检查环节使用的字段不设为必填；多份文档共用同一决策引用；单一当前版本不等于删除历史。
