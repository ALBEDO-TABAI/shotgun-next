> **事实状态：虚构模板**。

# 1. 候选规则（[规则卡](/transfer/rule-card.md)）

| 字段 | 内容 |
|---|---|
| 名称 | 接触先于身份显露 |
| 状态 | 候选，尚未进行本项目测试 |
| 任务 | 先建立一次接触经验，再完成对象识别 |
| 适用前提 | 项目允许稍后识别；局部仍保留理解动作所需线索；最终存在明确识别阶段 |
| 关键关系 | 局部化与清晰度共同保护接触；动作解除遮挡后，完整身份获得阅读机会 |
| 不变量 | 信息顺序与前后对象关系 |
| 可变项 | 材料、背景、色调、具体焦距与是否调焦 |
| 不适用条件 | 必须立即识别的任务；局部无法说明动作；没有足够后段完成识别 |
| 检查 | 在当前目标输出中分别检查动作理解、身份显露与连续性；情绪效果另行收集证据 |

# 2. 来源分析不能伪装成来源事实

假设规则来自某参考片，来源记录只说使用了特定镜头、没说明信息顺序目的：
- “先接触后识别”可以是从成片得出的**形式观察**；
- “为了强化触觉”仍是**解释假设**。

规则卡必须保留这种区别；迁移可基于有用的功能假设展开，但不能归给原作者作为确定自述。

# 3. 一次可能失败的迁移

新项目要求在极短展示中立即辨认不同型号，规则却把名称推迟到最后——即使画面漂亮也可能不适合。修正不是再延长一帧或提高锐度，而是先检查任务是否与延迟显露相容：可能改成先身份后接触，或把接触关系放入另一版本。记录**“不适用原因”**，而不是把规则扩大到什么顺序都算成功。

# 4. 一次可能成立但必须重测的迁移

换成不透明容器：信息顺序仍可能成立，但原来的透射和高光不适用。保留接触与显露关系，重新设计表面与反射，检查最终对象身份是否清楚。

→ 真正迁移的是**关系**，不是旧图外观；关系迁移仍依赖当前物理或生成条件（[迁移什么](/transfer/what-to-transfer.md)、[三种迁移结果](/transfer/source-target-mapping.md)）。
