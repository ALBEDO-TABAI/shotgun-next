# 三类事项（不混入同一个待办列表）

1. 必须修正的已确认问题；
2. 值得测试的风险；
3. 允许并存的偏好或解释。

# 每项修改的要素

对象、理由、范围、负责角色、复查方式。例如：“调整镜头03产品右侧高光；仅修改灯位关系；由摄影与美术共同核对；复查竖版裁切及包装识别。”具体职责以项目分工为准。

# 批准范围

- “概念通过”只代表概念层面的认可，不自动批准场景材质、制作成本和最终成片。
- “局部问题已修正”也不代表其他尚未验证项都完成。
- 反例测试：客户认可了概念 → 记录批准对象、版本与范围，不认为所有后续版本获批。

评价的终点不是每个人都说喜欢，而是当前阶段的问题得到足够清楚的回答，项目知道下一步做什么、保留什么，以及哪些结论仍然有限。
