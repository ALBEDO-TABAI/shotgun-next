# 适用触发

用户要求评价、比较、复盘、提出修改意见，或判断视觉方案是否满足任务时使用。只有风格识别任务时，不默认扩展为质量排名。

# 必要输入与缺失处理

至少需要可访问的作品或方案，以及明确的分析范围；目标、观看条件、受众、阶段、限制和已有测试可作补充。目标缺失不妨碍形式讨论，但保留条件性判断；没有成图时只能评概念描述；没有测试时不能宣布受众效果成立。

# 执行顺序

确认版本与阶段（[评价上下文](/frameworks/evaluation-context-five-items.md)）；区分描述、感受、评价和效果（[五种判断](/frameworks/five-judgment-types.md)）；选择相关标准（[七个维度](/frameworks/seven-evaluation-dimensions.md)）；逐项提供证据；检查反例与取舍；提出最小必要修改（[五段式反馈](/templates/five-part-feedback.md)）；安排与问题匹配的复查；输出完成边界。

# 完成条件

每个关键评价能定位对象并说明标准；事实与解释没有混写；没有将未知填成低分；修改建议能对应问题；有条件的优劣没有被包装成无条件真理；未实施的测试保持计划身份。

# 核心原则

评价是在明确对象、情境和价值标准后，说明哪些关系成立、哪些存在问题，以及证据能够支持到哪里。感受不等于判断，判断不等于受众结果，受众结果也不自动等于商业因果。
