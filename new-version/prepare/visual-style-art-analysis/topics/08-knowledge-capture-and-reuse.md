# 回答什么问题

怎样把一次分析转化为未来能重新找到、检查、反驳、迁移和使用的知识，而不只是保存一组风格标签、漂亮截图或长篇解释？

# 核心主张

**一次视觉分析的最好沉淀，不是最完整的形容词清单，而是一组能够回到证据、保留解释边界、指向设计选择的记录。** 资料告诉我们看过什么，决策卡解释哪些关系值得注意，规则卡说明可以怎样尝试，迁移与测试告诉我们条件改变后还剩下什么。

# 本篇概念

## Framework

- [把分析变成创作约束：核心不变量、允许变化项、有条件的例外](/frameworks/core-invariant-allowed-variation-exception.md) - 三类规则而非一长串同等禁令；下游能据此选择，规则也需要版本——概念从“玩具世界”改为“真实家居中的玩具异物”时应更新规则而非只换参考板标题。
- [从资料到知识的四种成熟度：资料保存、案例理解、条件性规则、迁移验证](/frameworks/four-knowledge-maturity-levels.md) - 工作状态而非文献规定的等级；一个条目可以暂时停留在保存阶段，不必为了填满字段编出尚不具备的深层意义。
- [八个模块怎样衔接：主要问题、核心产物、下游用途](/frameworks/eight-module-handoff-map.md) - 概念辨析→视觉观察→融合规则→美术工作→创作解释→方案构想→评价验证→沉淀复用；同一份观察不在每个模块重写成新事实，新解释引用旧观察但保留自己的判断身份。
- [规则的三个层次：表面配方、关系原则、条件性机制](/frameworks/rule-three-levels.md) - 蓝绿背景＋叶子＋水珠＋玻璃是配方；“主体与背景色接近时用反射、遮挡、明暗边界区分”是关系原则；加上任务条件、测试与失效时的调整就是条件性机制。
- [AI 参与时把四种操作分开：观察、外部核查、解释、创作](/frameworks/ai-four-operations.md) - 可以由同一工具完成，但输出身份必须清楚；分成多个 agent 也不自动解决问题——若都读同一份未核实总结，只会重复同一个错误。

## Term

- [可复用的视觉知识（工作定义）](/glossary/reusable-visual-knowledge-definition.md) - 具有证据与适用范围的设计判断，以及由该判断提炼出的有条件的行动原则；它不保证复制效果，而是帮助提出更好的问题和方案。

## Method

- [建立参考库而不是“审美回音室”](/methods/reference-library-building.md) - 收集理由进入条目；说明覆盖与偏向；不把转载次数当独立证据；为关键概念写编码说明并做多人独立试标；检索同时支持“像什么”和“解决什么”。
- [评价视觉模型时把任务拆开，并写清分母与抽样单位](/methods/evaluate-model-by-split-tasks.md) - 分别检查对象是否出现、属性是否有依据、关系定位是否正确、引用是否支持对应句子、未知是否保留、创作建议是否标为新提案；无法核查项不当正确也不悄悄丢掉。
- [知识维护：新增时判断是否真有新知识、更新保留理由、检查链接与权限、用新任务做回归测试](/methods/knowledge-maintenance.md) - 只有颜色不同可能只需加案例，新失效条件或新组织关系才值得新建规则；从新需求检索旧卡并提出外观不同的方案，只会产出原图变体说明仍停在表面配方。

## Principle

- [定位是证据的一部分：陈述必须绑定到对象](/principles/locator-is-part-of-evidence.md) - 借 W3C Web Annotation 的“内容与目标分离、片段定位”思想；纸上写“第三张图，产品左侧叶片”也有效，没有资源时不编造时间码或文件名。
- [解释是有人提出的主张：写清谁、基于什么材料；允许多重解释并存但不等量齐观](/principles/interpretation-is-an-authored-claim.md) - ICON 允许不同观察者对同一作品形成不相容解释；报告与知识库中保存“谁提出何种解释”，不把分析者解释改写成作品固有属性，也不把任意联想与有据解释当同等有效。
- [多个来源也可能只是同一条消息的回声](/principles/echo-sources-not-independent.md) - 同一采访被三个网站转载仍是一条来源链；保留最接近原始陈述的记录，转载作查找或版本线索；真正的相互印证是不同材料从不同角度限制解释。
- [团队没有义务拥有一套完全相同的内在解释](/principles/team-need-not-share-one-interpretation.md) - 导演、美术、摄影和剪辑可能各自从不同问题进入并在制作中形成共同结果；作品一致性不证明参与者从一开始共享同一套语言。
- [失败结果也要留下](/principles/keep-failed-results.md) - “叶片在小尺寸中显得厚重”可改变材料、比例或角度；“包装被水光遮住”可改变呈现时点；只保留成功图会让后续团队重走已失败路径。
- [来源记录的最小三问：依据什么材料、经过怎样的处理或判断、谁作出判断](/principles/provenance-minimal-three-questions.md) - 借 W3C PROV 的实体—活动—参与者；截图、原片和报告是不同对象，裁切调色描述是不同活动，主创自述、研究者解释、模型输出来自不同参与者；Markdown 也能承载最小来源链。
- [词语不是概念，相关也不是同义：检索可以宽，结论必须窄](/principles/words-not-concepts-related-not-synonym.md) - SKOS 将概念、词汇标签、语义关系与跨词表映射分开；“简约组织”与“极简主义艺术运动”不因含相同汉字合并；“留白”与简约组织相关但不是上下位或同义。
- [可复用不等于全部公开：记录来源、访问条件和用途限制](/principles/reusable-not-all-public.md) - FAIR 包含必要时的认证与授权访问；能在某处看见图片不代表已获所有使用许可；保存分析记录不必公开客户内部原始资产；本包不替代权限确认或法律判断。
- [资料库也应说明自己是怎样组成的：收录目的、范围、选择方式、排除规则、空缺](/principles/library-describes-its-composition.md) - 借 Datasheets for Datasets 的思路：案例为什么被选、偏向哪些媒介与预算、是否只含获奖作品、有无失败与反例；精心策划的案例库不等于具有统计代表性的样本。
- [语言流畅不保证视觉依据可靠](/principles/fluent-language-not-visual-grounding.md) - 图像描述与大型视觉语言模型的对象幻觉研究表明对象存在需要独立检查；这些研究有年代、模型与任务边界，不能给当前所有模型规定相同错误率，也不是风格理解的完整测试。
- [决策卡不等于“主创当时真的作了这个决定”；描述也不能为便于迁移而丢失原作](/principles/decision-card-not-production-fact.md) - “关键选择”可以是对成片形式的分析性重述，需标明是分析出的设计关系还是有资料证明的生产决定；过度抽象变成“通过对比突出主体”，过度具体只剩“右边放两片叶子”。
- [不变量应尽可能少，但足够维持概念](/principles/minimal-sufficient-invariants.md) - “产品进入放大的植物环境”可能需保留产品与植物的尺度关系，却不必固定某种叶片、绿值或石头；但具体植物若承担已确认的产品信息就不能随意替换。
- [反例比再找十张相似图更能修正规则](/principles/counterexamples-refine-rules.md) - 同一配方有的轻盈有的笨重时，比较尺度、支撑、遮挡、材质和动作，而不是删掉不符合预期的图；也找外观差异大却解决相近问题的作品；案例不足时标记探索性状态。
- [检索应同时支持“像什么”和“解决什么”；排序靠前不是质量证明](/principles/retrieval-wide-conclusion-narrow.md) - 风格词、题材、颜色、年代用于发现候选；任务、关系和失败条件更适合支持迁移——“同色环境中仍保持主体可辨的案例”比“找高级的绿色广告”更能连接设计决策。
- [原始资源与派生资源分开；定位精度跟随证据能力](/principles/original-vs-derived-resources.md) - 原片、压缩版、截图、裁切、调色参考和加注版本不用同一模糊名称；只拿到截图就以截图为对象；裁切后旧坐标、重剪后旧时间码要检查；不输出虚构的证据路径。
- [版本变化需要传播到依赖它的结论——精准作用于相关判断](/principles/version-change-propagates.md) - 悬浮水珠在新版中被删，基于它的“失重关系”解释要重查；后来发现材料是透明树脂而非玻璃，应更正制作事实，但“画面呈现透明光滑表面”的观察不一定失效。
- [先确认模型真正获得了什么：输出覆盖范围不应超过输入](/principles/ai-input-bounds-output.md) - 原图、低分辨率缩略图、关键帧、完整视频还是别人写的描述？没有图像时可制定观察问题、分析文字，但不能声称看到道具纹理；不能把抽样帧拼成确定的动作过程。
- [自我复述不能算独立验证](/principles/self-restatement-not-verification.md) - 让同一模型再解释一次可发现内部矛盾，但不能证明图像中确实存在所说对象；关键判断应重新绑定实际材料，由人工或独立证据检查过程核对。
- [生成候选不等于批准执行：记录批准的是概念、构图、材质还是终稿](/principles/candidate-is-not-approval.md) - 模型提出的场景、材料和动作还要经过原型问题与评价；某张概念图被选中不自动批准全部制作细节；后续工具不能因看见“通过”二字就跳过未完成检查。
- [信息写出来，还必须有人真正使用：每个重要字段应有消费目的](/principles/handoff-fields-need-consumers.md) - 卡片写“包装正面不允许遮挡”，生成阶段却只读“梦幻植物庭院”，评审再凭感觉重写目标——记录越多真相越分裂；交接缩小为几个明确问题；无人读取的字段不必长期维护。

## Checklist

- [第八篇对抗性测试：知识越可复用，越需要防止错误被放大](/checklists/p08-adversarial-tests.md) - 只有风格描述、只有一张关键帧、同源转引、陌生物件、两种合理解释、裁切调色、旧资料制作事实、单案例原则、候选被选中、模型流畅一致、旧论文错误率、字段很多、权限不明、遇到反例。

## Template

- [关键设计决策卡：十个栏目](/templates/key-design-decision-card.md) - 对象与范围、可见证据、关键选择、作用解释、证据身份、其他解释、可迁移部分、不变量与变量、失效条件、验证与版本；每件作品先挑三到五个真正决定呈现的选择（起点，不是固定数量）。
- [规则卡句式：带条件的提议](/templates/rule-card-sentence.md) - 当任务出现____问题时，可以尝试通过____关系，而不是只增加____元素，来形成____的候选效果；需要保留____；可以改变____；在____条件下可能失效，需用____检查。
- [关键概念的编码说明（含正例、反例、难判案例）](/templates/coding-note.md) - 以“主体隔离”为例：指位置、边界或注意层次上的分离而非物件少；可接受哪些证据、哪些相似情况不计入、局部与整体如何区分；一致性高不自动等于判断正确。
- [最小结构化知识记录（虚构教学模板）](/templates/structured-knowledge-record.md) - record_id/version/kind、source（asset_id/version/available_material/locator）、scope、observation、interpretations（含 author 与 alternatives）、production_fact、transfer_rule、validation、active_project_decision；未知保持 null。

## Case Study

- [虚构案例：“可以看见却无法进入的房间”艺术摄影系列](/cases/fictional-uninhabitable-room-photo-series.md) - 虚构教学推演（六、七、八篇共用）：关系句构思、测试问题随任务改变；含混不能直接扣分，但也不自动完成；尺度操作迁移后产生阻隔而非庭院。
- [虚构案例：从植物庭院决策卡到新任务的迁移链](/cases/fictional-plant-courtyard-transfer-chain.md) - 虚构教学推演：一张护肤概念图 → 决策卡（关键选择、依据、作用假设、替代解释、制作未知、迁移规则、失效条件）→ 迁移到时尚编辑摄影 → 再迁移到非商业空间作品 → 回写知识。

## Skill Interface

- [Skill：分析沉淀与知识复用](/skills/skill-analysis-knowledge-reuse.md) - 触发：保存拆片成果、整理参考库、形成可迁移方法、建立团队分析模板或为 AI 准备可靠知识；输出按个人练习／团队复盘／长期 AI 资料库分级；不默认上传外部服务。
