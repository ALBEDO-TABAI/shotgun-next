# 回答什么问题

怎样把“好看、不高级、太普通、很有感觉”等评价，转化为有对象、有标准、有证据、能支持修改或保留的判断，同时保留艺术讨论中的多种价值？

# 核心主张

**评价不是给作品贴好坏标签，而是在明确对象、情境和价值标准后，说明哪些关系成立、哪些存在问题，以及证据能支持到哪里。** 感受不等于判断，判断不等于受众结果，受众结果也不自动等于商业因果；把需要行动的问题写清楚：为什么改、改哪里、保留什么、怎样复查。

# 本篇概念

## Framework

- [经验美学：审美情绪与审美判断是两种输出](/frameworks/leder-emotion-vs-judgment.md) - Leder 等的模型把感知、分类、理解、评价联系起来并区分情绪与判断；体验报告、机制解释、条件性评价、综合判断四句话不能互相代替。
- [拆开“好”：五种判断类型](/frameworks/five-judgment-types.md) - 感受与偏好、形式判断、表达与艺术判断、项目适配判断、实际效果判断——判断对象不同，可以同时成立而不矛盾。
- [建立评价上下文：先写清五件事](/frameworks/evaluation-context-five-items.md) - 评的是哪个版本与范围、当前阶段应回答什么、用途与观看情境、哪些是硬要求哪些是可协商价值、谁在评价及其经验与利益位置。
- [不强求总分的七个评价维度](/frameworks/seven-evaluation-dimensions.md) - 目标适配、形式组织、概念具体性、表达与解释空间、完成与连续性、制作与交付适配、实际观看结果——按任务取用，各有应找证据与常见错误。
- [证据＋状态，而不是单一分数：成立、存在风险、未成立、证据不足、不适用](/frameworks/evidence-status-not-score.md) - 状态是工作判断不是校准测量；“证据不足”与“未成立”必须分开；艺术作品的购买指标是不适用而非低分；未做记忆测试不能填零。
- [观看结果要分变量取证](/frameworks/outcome-variables-separate.md) - 是否看到主体、是否识别产品、是否理解主题、产生什么感受、记住什么、是否知道品牌、是否点击或购买——互有关联但不是一件事，每项结论需要对应证据。
- [按问题选择证据方式：各自能回答什么、不能独自证明什么](/frameworks/evidence-methods-by-question.md) - 自查与专家评审、探索性访谈、有明确条件的任务测试、设计得当的比较研究、发布后表现记录——不是从低到高的固定阶梯。

## Method

- [必须评分时，先写项目专用锚点](/methods/scoring-anchors.md) - 如“产品识别”三级描述：目标尺寸下主要特征无法辨认／能辨认但受干扰／当前条件下能完成既定识别任务；有序类别不是等距测量；“高级感八分”无法支持修改。
- [比较时先确定：是选整体，还是解释原因](/methods/compare-whole-vs-explain-cause.md) - “两套方案哪套更适合继续”可比较整体但不能归因到某颜色或道具；“瓶身区分不足是否由背景纹理造成”需限制其他变化；随机分配不是按名单轮流，随机展示不是永远先A后B。
- [处理评审意见冲突：先判断冲突在哪里](/methods/resolve-review-conflicts.md) - “太空”与“很克制”可能是目标不同；对同一细节描述不同可能是观看尺寸不同；同条件仍有分歧则保留审美立场差异；先修事实错误，再明确决策权，记录未被选择的合理解释。
- [从评审意见走向修改与验收：三类事项与批准范围](/methods/review-to-revision-acceptance.md) - 必须修正的已确认问题、值得测试的风险、允许并存的偏好或解释分开列；每项修改有对象、理由、范围、负责角色、复查方式；“概念通过”不自动批准材质、成本和成片。

## Principle

- [观看任务影响扫描：画面不能独自决定所有人的观看顺序](/principles/viewing-task-shapes-scanpath.md) - 没有眼动记录时，“观众先看这里”应降格为“这里提供了较强的注意线索”或“我本次观看最先注意到这里”。
- [色彩与情绪有关联，但没有通用解码词典](/principles/color-emotion-not-decoding-dictionary.md) - 颜色—情绪关联既有共享模式也受语言地理塑造，且研究针对颜色词与情绪概念；“蓝绿色＝清爽”不能写入观察层。
- [视觉修辞：图像结构与受众反应是两个研究问题](/principles/visual-rhetoric-structure-vs-response.md) - 类比、并置、替代、尺度错置是描述候选机制的词汇，能帮助提出测试问题，但不能独自证明观众理解了隐喻、记住了品牌或更愿购买。
- [目标是判断的上下文，不是替作品免于批评的许可证；偏好是有效信息，不是质量结论](/principles/goal-is-context-not-exemption.md) - “先判断作品在解决什么”不意味着作者说要做什么就只能按那个目标评价：需求是否合理、作品是否打开了更有价值的问题、用途是否改变都可以进入评价。
- [评价不是给描述换一个带褒贬的词：写明对象、条件、标准与证据](/principles/evaluation-states-its-conditions.md) - “道具很多”是描述，“道具太多”隐含标准；快速识别产品时密集物件需检查，表现物品积累与记忆时删空反而破坏表达；不把“少”默认等同于“好”。
- [新颖与熟悉不是零和选择：说明保留了哪些惯例、改变了哪些关系](/principles/typicality-and-novelty-jointly.md) - Hekkert 等在消费产品研究中讨论典型性与新颖性的联合解释；不能推出“一切艺术必须既新又熟”或“七成常规三成创新”的固定比例。
- [比较反馈前先保存观看条件](/principles/viewing-conditions-must-be-recorded.md) - 看了什么版本、有无声音、尺寸多大、任务如何提问、观看前是否了解产品或创作解释；没有这些条件，比较两次反馈往往比较的不是同一件事。
- [批评指向作品和目标，而不是攻击创作者](/principles/critique-the-work-not-the-person.md) - d.school 反馈教学强调善意批评、讨论目标及作品与个人的区分；友好不是只说赞美，专业也不是用难懂术语；能让对方理解判断并检验修改才是反馈价值。
- [测试设计由问题决定，不由“A/B”这个名字决定](/principles/test-design-follows-question.md) - 研究目标、因素数量、资源与错误决策控制影响设计选择；内部讨论、访谈、随机比较和投放测试是不同层级证据，不应统一写成“用户验证通过”。
- [权重是价值选择，不是科学自动算出来的](/principles/weights-are-value-choices.md) - 把包装识别放在情绪陌生感之前是项目优先级，换成展览可能相反；先找不可妥协约束，严重内容错误不能被多个“质感不错”平均掉；改变合理优先级就改变选择时如实说明取舍。
- [证据可信度与作品质量是两根不同的轴](/principles/evidence-confidence-vs-quality.md) - 某判断证据弱不等于作品差；某评审十分确定也不等于判断正确；可同时记录“我倾向认为空间关系有效”与“目前只看到单张概念图，运动表现未知”。
- [提问不要预先塞入期待的答案；观看前的解释要如实记录](/principles/questions-without-leading-answers.md) - 先问“你看到了什么”“让你想到什么”，再问团队关心的问题；不要一开始就问“是否觉得清爽高级”；解释后理解与无解释理解分开记录。
- [没有开展研究，就写测试计划，不编造结果](/principles/no-study-write-a-test-plan.md) - 不为报告完整编造“八成用户觉得更清爽”；内部几位同事意见不扩大成目标人群调查；测试前写预期、测试后写观察，不只保留支持方案的回答。
- [反馈应包含“保留什么”，且问题与方案不要强行绑定](/principles/feedback-says-what-to-keep.md) - 只写需要改变的部分容易连有效关系一起破坏；“主体不清楚”是诊断，“换白底”只是候选方案之一，还可改明暗、反射、机位、遮挡或信息密度。
- [生成候选不等于批准执行：记录批准的是概念、构图、材质还是终稿](/principles/candidate-is-not-approval.md) - 模型提出的场景、材料和动作还要经过原型问题与评价；某张概念图被选中不自动批准全部制作细节；后续工具不能因看见“通过”二字就跳过未完成检查。

## Checklist

- [第七篇对抗性检查与常见假问题](/checklists/p07-adversarial-checks.md) - “高级吗”、表现压抑、一位专家不喜欢、完成度不同、无记忆研究、A/B改多项、内部讨论当市场验证、不同尺寸版本、技术错误被平均、多解释、局部问题全部重做、概念认可当全部获批。

## Template

- [五段式反馈：画面证据 → 可能影响 → 所依赖目标或条件 → 建议动作 → 复查方式](/templates/five-part-feedback.md) - 以瓶身右边缘与弧形高光重叠为例；“可能构成干扰”是基于关系的风险判断；局部问题不扩成“整套不高级，全部重做”。
- [最小评价记录（虚构模板）](/templates/evaluation-record.md) - work_version、scope、purpose、criterion（name/reason）、observation（statement/source）、judgment（status/statement/limitation）、preserve、candidate_change、verification、approval_scope。

## Case Study

- [虚构案例：“可以看见却无法进入的房间”艺术摄影系列](/cases/fictional-uninhabitable-room-photo-series.md) - 虚构教学推演（六、七、八篇共用）：关系句构思、测试问题随任务改变；含混不能直接扣分，但也不自动完成；尺度操作迁移后产生阻隔而非庭院。
- [虚构案例：两版护肤产品画面怎样比较（销售图 vs 品牌图）](/cases/fictional-skincare-ab-two-versions.md) - 虚构教学推演：方案A中央轮廓连续、方案B叶片交叠局部遮挡；不立即给总冠军，按任务分配下一步检查，写两个不同测试问题，结果只影响对应决策。

## Skill Interface

- [Skill：作品评价与反馈验证](/skills/skill-evaluation-feedback-validation.md) - 触发：评价、比较、复盘、提修改意见或判断方案是否满足任务；只有风格识别任务时不默认扩展为质量排名；确认版本阶段→区分描述感受评价效果→按标准取证→最小必要修改→匹配复查。
