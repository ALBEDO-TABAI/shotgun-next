# 失效模式

卡片写明“包装正面不允许遮挡”，生成阶段却只读取“梦幻植物庭院”；评审再凭个人感觉重写目标；最后所有文件都有自己的“最终方案”。**记录越多，真相反而越分裂。**

# 交接缩小为几个明确问题

1. 接收者必须读取哪些依据？
2. 要作什么决定或产出？
3. 哪些规则不可自行改变？
4. 缺少什么时需要停在候选状态？
5. 完成后如何回写实际使用的版本？

# 字段的消费目的

- 记录“失效条件”，是为了迁移前检查；
- 记录“证据身份”，是为了防止把假设当事实；
- 记录“允许变化”，是为了给执行保留空间。

若某个字段永远无人读取，也不影响判断，就不必为了完整而长期维护。轻量流程可以只用一个文件中的当前决策区和历史记录；复杂流程再拆为独立卡片或系统对象。反例测试：记录了很多字段 → 检查字段如何影响实际下一步，不默认流程已经消费它们。
