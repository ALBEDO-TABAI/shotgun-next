# 依据

Design Council 的双钻框架区分发现、定义、发展和交付，明确说明流程不是单向线性，早期制作和测试也可能帮助重新理解问题。

# 原则

- 不采用“需求先全部确定，然后禁止返回”的僵硬链条。
- 区分：哪些限制已经确认，哪些概念仍在探索，哪些测试结果需要我们重新描述任务。
- 这不意味着需求可以无限改变：每次改变要有**理由、影响范围和新的确认**，而不是让团队永远停留在没有判断标准的发散阶段。
