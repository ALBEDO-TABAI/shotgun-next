# 八、把它用于日常拆片、参考研究或 AI 分析时，最后应该留下什么？
## 设计决策卡、证据链、可迁移规则与知识维护：理论基础及 skill 规范

> **本篇任务：**将一次分析转化为未来能够重新找到、检查、反驳、迁移和使用的知识，而不只是保存一组风格标签、漂亮截图或长篇解释。
>
> **与第一篇衔接：**沿用分面描述、范围限定与证据身份。第二至第七篇产生观察、关系、工作判断、解释、方案与评价；本篇组织这些成果，保留它们之间的区别和可追溯连接。
>
> **研究与整合说明：**来源记录、语义组织、艺术解释建模及视觉模型评测提供依据。这里的卡片、检索策略、交接字段和检查流程为应用整合；交付的是知识与规范，不代表已经安装、接入或运行任何 agent 系统。检索与编订：2026年9月18日。

## 一、真正要保存的，不是“这张图很好”，而是一个能再次使用的判断

设想参考库里保存了几千张图片，每张都带有“高级、自然、极简、梦幻”的标签。下一次遇到“产品要轻盈，但不能失去体积感”的任务时，你仍然可能不知道该从哪里开始。

原因不是图太少，而是没有保存：某张图解决了什么问题，哪些关系产生了那个效果，哪些条件不可丢失，以及哪些部分只是偶然外观。

本篇采用的工作定义是：

> **可复用的视觉知识，是具有证据与适用范围的设计判断，以及由该判断提炼出的有条件的行动原则。**

它不保证复制效果。不同产品、人物、媒介和目标改变后，旧原则需要重新检验。可复用的意思是能帮助提出更好的问题和方案，而不是不经思考直接套用。

### 从资料到知识，可以有四种不同成熟度

**资料保存：**知道作品在哪里、是什么版本。

**案例理解：**能够解释某个具体关系，并指出证据和替代解释。

**条件性规则：**说明某类问题下可以尝试什么机制、需要保留什么、在哪些情形会失效。

**迁移验证：**把规则用到不同任务，记录新方案、测试和修订。

这些是本篇建议的工作状态，不是文献规定的统一等级。一个资料条目可以暂时停留在保存阶段，不必为了填满字段，编出它尚不具备的深层意义。

## 二、知识组织应从哪些理论与规范借力

### 1. 来源记录：结论是由谁、用什么、通过什么活动形成的

W3C 的 PROV 概览以实体、活动及相关参与者说明来源信息，并关注派生与版本等问题。该概览是工作组说明文件，不是 Recommendation 本身。[R27]

本篇借用的最小问题只有三个：当前结论依据什么材料？经过了怎样的处理或判断？谁作出了这一判断？

例如，截图、原始影片和分析报告是不同对象；裁切、调色与描述是不同活动；主创自述、研究者解释和模型输出来自不同参与者。知道这些差别，才能判断一句话能支持什么。

不需要为了理解这三件事，先部署复杂数据库。一个写清来源与修改历史的 Markdown 文件，也可以承载最小来源链。

### 2. 标注：评论必须绑定到明确的目标

W3C Web Annotation Data Model 区分标注内容与目标，并支持对特定资源片段的定位。[R28]

本篇据此要求：谈论“这个反射”时说明在哪张图、哪个区域；谈论“空间突然展开”时说明哪个版本、哪个时间区间。评论可以是描述，也可以是解释，但两者都应指向可检查的目标。

这里提供的是简化记录方法，不声称每张卡都实现了完整标准。没有精确坐标时可以先用清楚的位置描述；没有实际视频时，不可编造时间码使报告显得专业。

### 3. 概念组织：词语不是概念，相关也不是同义

SKOS 将概念、词汇标签、语义关系与跨词表映射分开组织。[R29]

应用到视觉库，“简约组织”可以有不同常用说法，但“极简主义艺术运动”不应因为含有相同汉字就与它合并。“留白”可能与简约组织相关，也可以出现在其他形式中，因此相关关系不等于上下位或同义关系。

本篇建议首先解决词义边界，不追求收录最多风格词。检索可以宽，结论必须窄：相似词帮助找到候选，最终描述仍回到具体含义和证据。

### 4. 艺术解释应作为可署名、可讨论的判断保存

ICON 的研究将艺术解释作为可以结构化表达的对象，并关注解释层次及多重解释。[R17]

本篇由此要求，不把一位分析者的解释直接改写成作品固有属性。例如“这张图表达疏离”可以保存为一个有作者、有证据的解释；另一位提出“它更像仪式性展示”，也可以并存。

多种解释并存，不意味着一切说法都同样成立。它们仍需比较证据、范围和替代解释；只是不能通过数据库的单选字段，提前消灭真正的讨论空间。

### 5. 可复用不等于全部公开

FAIR 原则讨论可发现、可访问、互操作和可复用，并允许必要的认证与授权访问。[R30]

对项目资料，本篇建议同时记录来源、访问条件和用途限制。能在某处看见一张图片，不代表项目已经获得所有使用方式的许可；保存分析记录，也不必把客户内部原始资产公开。

这里是资料管理建议，不替代具体权限确认或法律判断。资料无法公开时，仍可在授权范围内维护元数据和内部证据关系。

### 6. 一个资料库也应说明自己是怎样组成的

Datasheets for Datasets 提出记录数据集动机、组成、收集过程和推荐用途的思路。[R31]

本篇借用它来约束参考库的自我说明：这些案例为什么被选择，偏向哪些媒介与预算，是否只包含获奖作品，有没有失败或反例，哪些范围尚未覆盖。

精心策划的案例库不等于具有统计代表性的样本。若没有系统取样，不应声称它已经代表“当代广告的普遍风格”。

### 7. 语言流畅不保证视觉依据可靠

Rohrbach 等人的图像描述研究显示，对象幻觉需要独立检查，语言描述指标不能保证内容确实来自图像。[R32] 后续关于大型视觉语言模型的研究也针对对象幻觉提出专门评测方法。[R33]

这些研究针对特定年代、模型与任务，不能据此给当前所有模型规定相同错误率；对象幻觉评测也不是艺术风格或创作意图理解的完整测试。

对本篇的启发是：一段解释读起来连贯、专业，并不足以证明模型真的看到相关细节。观察、引用、推理和创作建议，应分别检查。

## 三、八篇内容最终怎样衔接，而不是重复生产八份报告

| 模块 | 主要问题 | 建议保留的核心产物 | 下游怎样使用 |
|---|---|---|---|
| 一：概念辨析 | 这个判断是什么性质、作用于哪里？ | 分面、范围、证据身份 | 限定其他模块的术语与边界 |
| 二：视觉观察 | 实际看见哪些要素和关系？ | 可定位的观察记录 | 为关系、解释和评价提供依据 |
| 三：融合规则 | 不同来源如何共处或冲突？ | 主导关系、局部引用、例外 | 提炼组织方式，避免标签相加 |
| 四：美术工作 | 哪些设计问题和实现决策值得拆解？ | 决策对象、职责与实现候选 | 支持生产讨论，不假装已知幕后 |
| 五：创作解释 | 哪些出发点受到什么证据支持？ | 竞争解释及其来源 | 区分历史理解与新创作假设 |
| 六：方案构想 | 当前需求怎样转为可执行关系？ | 概念、规则、原型问题 | 形成制作与测试候选 |
| 七：评价验证 | 在什么目标下成立，怎样复查？ | 条件性评价、改动与测试 | 决定保留、修改及范围 |
| 八：沉淀复用 | 哪些成果值得再次使用？ | 决策卡、规则卡及版本连接 | 支持下一次检索、比较和迁移 |

这不是要求每个问题都经过八个部门或生成八份文件。一张静物的快速分析，可以在一张卡里完成相关动作。只有任务复杂、多人协作或确有复用价值时，才扩展记录。

原则是：**同一份观察不必在每个模块重写成新的事实；新的解释可以引用旧观察，但必须保留自己的判断身份。**

## 四、优先保存“关键设计决策卡”

每件作品先挑三到五个真正决定其呈现的选择，是一个可操作的起点，不是固定数量标准。作品简单时可能更少；复杂段落可以更多，但每项都应说明重要性。

建议一张卡回答以下问题：

| 栏目 | 应写什么 | 不应写什么 |
|---|---|---|
| 对象与范围 | 哪张图、哪个镜头、哪个版本 | 模糊的“这部电影” |
| 可见证据 | 具体要素及关系，定位依据 | 只写“很高级” |
| 关键选择 | 相比其他可能处理，这里选择了什么 | 假装掌握未公开决策过程 |
| 作用解释 | 可能改变的空间、注意、动作或意义 | 无条件心理规律 |
| 证据身份 | 观察、文献事实、主创陈述、分析假设等 | 全部写成客观事实 |
| 其他解释 | 仍然合理的候选及差别 | 为了整齐删除分歧 |
| 可迁移部分 | 可以保存的组织关系 | 直接复制所有物件 |
| 不变量与变量 | 哪些必须保留，哪些允许变化 | 把所有细节都锁死 |
| 失效条件 | 什么变化可能破坏规则 | “适用于所有品牌” |
| 验证与版本 | 哪些检查已做、哪些未做 | 把计划当完成回执 |

### 决策卡不等于“主创当时真的作了这个决定”

在没有制作资料时，卡片中的“关键选择”可以指对成片形式的分析性重述，例如“主体与背景保持同色，但通过不同反射方式区分”。这不证明主创曾用相同语言提出它。

因此应明确：是从成片分析出的设计关系，还是有资料证明的真实生产决定。两类记录都可以有价值，但不可互换。

### 描述不能为了便于迁移而丢失原作

过度抽象会让任何案例都变成“通过对比突出主体”。应保留具体对比发生在哪里、通过什么属性实现、与其他关系怎样共同作用。

反过来，过度具体又会只剩“右边放两片叶子”。有效卡片需要在具体证据与有条件的关系描述之间建立连接。

## 五、从一张决策卡提炼“规则卡”

规则不是“这个做法总有效”，而是一个带条件的提议。

本篇建议使用以下表达：

> **当任务出现________问题时，可以尝试通过________关系，而不是只增加________元素，来形成________的候选效果。需要保留________；可以改变________；在________条件下可能失效，需用________检查。**

### 区分规则的三个层次

**表面配方：**蓝绿色背景、叶子、水珠、玻璃。这只是元素组合，适用性很难判断。

**关系原则：**当主体与背景色彩接近时，尝试通过表面反射、遮挡和明暗边界建立区分。它开始说明问题与办法，但需要具体条件。

**条件性机制：**在需要保持环境同色关联、又要求包装可辨的静态产品画面中，测试不同表面反射及轮廓区分；若目标尺寸压缩了这些细微差异，应调整信息层次或寻找更强的区分方式。

第三种并不是科学定律，而是更容易执行和反驳的设计建议。

### 不变量应尽可能少，但足够维持概念

“产品进入放大的植物环境”可能需要保留产品与植物的尺度关系，却不一定需要固定某种叶片、某个绿值或一块石头。

然而，如果具体植物承担已确认的产品信息，就不能随意替换。哪些是可变项取决于当前任务，不由风格词自动决定。

### 反例比再找十张相似图更能修正规则

若同一配方有的画面轻盈、有的笨重，应比较尺度、支撑、遮挡、材质和动作，而不是把不符合预期的图删掉。

也可以找外观差异很大却解决相近问题的作品。它们有助于判断我们学到的是某种视觉关系，还是仅仅熟悉了一套流行配色。

这是一种建议的比较策略，不要求每条规则拥有固定数量的案例才允许使用。案例不足时，明确记录探索性状态即可。

## 六、完整教学示例：从植物庭院到新的任务

**以下全部为虚构案例与迁移练习，不是已拍摄项目或已完成的测试。**

### 1. 初始案例的有限设定

一张护肤产品概念图：叶片明显大于包装，围成开敞空间；产品位于平缓的台面，背景没有具体室内边界；整体偏同色，但瓶身表面与环境反射不同。

分析范围只有这张概念图，不包括镜头运动、真实材料或受众反馈。

### 2. 可读的决策卡

**关键选择：**把植物从小型成分装饰放大为主体所处的环境。

**可见依据：**叶片与包装的比例、叶片形成的顶部及两侧边界、产品与前后景的遮挡关系。

**作用假设：**观看者可能由“产品旁边有植物”，转向“产品进入一个植物空间”。这是解释，需要实际图像和观看材料进一步支持，不是已测效果。

**替代解释：**也可能仅被看作巨型道具展示。区分两种解释，需要检查空间线索是否充分，以及观看者如何描述它。

**实际制作：**未知。不能因为出现非现实尺度，就认定全部由三维制作。

**迁移规则：**将原本用于说明属性的小元素提升为可进入、可遮挡、可组织前后关系的空间结构。

**失效条件：**元素放大后仍只贴在背景上；主体完全被环境吞没；尺度线索在裁切后消失；具体物件含义与新任务冲突。

### 3. 将规则迁移到时尚编辑摄影

新任务：表现人物与记忆空间的关系，不承担护肤产品信息。可以把日常书信、织物或家具局部发展为空间边界，但不能只把模特替换进原产品位置。

需要重新判断人物尺度、动作、服装、观看距离，以及材料是否与主题有关。原来必须保持的包装识别，在新任务中不再成立；新的身体动作与情绪关系则成为重要限制。

迁移保留的是“局部物件变成环境”的操作，而不是叶子、水珠和蓝绿色的整套外观。

### 4. 再迁移到非商业空间作品

任务改为“可看见但无法进入”。此时可以让放大的物件构成阻隔，而非保护主体的庭院。相同的尺度操作产生了不同观看关系，需要新解释、新构图和新评价标准。

不能把护肤案例里的清爽、轻盈自动复制成预期效果。保存原规则的目的，是帮助发现可改变的关系，不是把所有项目做成同一种审美。

### 5. 迁移后怎样回写知识

记录新任务、保留的关系、改变的条件、原型结果和规则修订。若新方案失败，也记录失败发生在哪个环节：尺度不成立、材料阻碍动作，还是规则根本不适合任务。

失败不必导致删除原卡，也不该被视为规则永远无效。更有价值的是收窄它的适用范围，或把原来混在一起的两个机制拆开。

## 七、怎样建立参考库，而不是建立“审美回音室”

### 1. 收集理由应进入条目

一张图可以因为空间关系、材料处理、道具使用、失败的遮挡或异常的观看顺序而被收录，不必所有条目都是“喜欢的作品”。

建议记录“为何收录”和“与什么问题有关”。这样，未来检索不会只得到外观相似的成功案例，也可以找到不同路径和反例。

### 2. 说明资料库的覆盖与偏向

如果主要来自品牌官网、获奖广告和大型电影，其内容可能偏向有公开材料的制作。应把这种选择记录下来，不把缺少资料的小型项目误认为缺少设计工作。

资料集说明可以包含：收录目的、媒介与年代范围、选择方式、排除规则、公开程度、已知空缺、维护者和更新日期。这是对 Datasheets 思路的应用，不是声称参考库具备统计代表性。[R31]

### 3. 不要把转载次数当成独立证据数量

五篇文章如果都转述同一位主创的采访，应该知道它们共享来源。二次整理可以帮助寻找材料，但不能自动把一个陈述变成五份独立证实。

资料链断裂时，保留“转引未核对原文”，不要把引号和作者姓名复制得越多就越确信。

### 4. 为关键概念编写简短编码说明

例如“主体隔离”至少应说明：指与其他对象在位置、边界或注意层次上的分离，不只是物件数量少；可接受哪些证据；哪些相似情况不计入；局部与整体怎样区分。

编码说明可以有正例、反例与难判案例。多人先独立分析一小组案例，再讨论差异，有助于发现词义或分析单位不清楚之处。

一致性高不自动等于判断正确：团队可能共同接受了错误定义。相反，解释性问题存在分歧也不自动意味着流程失败。要区分对象漏看、术语混淆与合理解释差异。

### 5. 检索应同时支持“像什么”和“解决什么”

风格词、题材、颜色、年代可以用于发现候选；任务、关系和失败条件则更适合支持迁移。

一个实用问题是：“有没有在同色环境中仍保持主体可辨的案例？”它比“找高级的绿色广告”更容易连接设计决策。

检索结果仍需回到原资料核对。被系统排在前面，只说明符合某种匹配过程，不是历史归属、质量或适用性的最终证明。

## 八、文件、片段与版本：证据定位需要多精确

### 原始资源与派生资源分开

原片、压缩版、截图、局部裁切、调色参考和加注版本，不应全用同一个模糊名称。派生图可以引用原资源，但要记录发生了什么变化。

若只拿到截图，就以截图为分析对象。不能通过一个宽画幅边框，猜测真实放映格式；不能根据截取图推断完整镜头的持续时间。

### 定位精度应跟随证据能力

文本可用段落或行号；图像可用相对位置、区域或坐标；视频可用版本和时间区间。W3C 标注模型提供了把内容绑定到片段的参考方法。[R28]

具体使用哪种方式取决于材料。图片已经重裁切后，旧坐标不能悄悄继续指向原区域；视频重新剪辑后，旧时间码应检查是否仍然有效。

没有对应资源时，不输出虚构的证据路径。`frame_123.jpg` 只是看起来像文件名，不代表文件实际存在。

### 版本变化需要传播到依赖它的结论

假设原图中的悬浮水珠被后续版本删除，基于水珠的“失重关系”解释需要重新检查。只改素材文件、不标记依赖结论，会让旧分析继续污染新方案。

同样，若后来发现原材料不是玻璃，而是透明树脂，应更正制作事实；但“画面呈现为透明光滑表面”的观察不一定同时失效。更新应精准作用于相关判断，而不是全盘重写。

## 九、AI 可以参与哪些工作，怎样避免把推测固化成事实

### 1. 先确认模型真正获得了什么

实际输入是原图、低分辨率缩略图、关键帧、完整视频，还是别人写的描述？模型输出的覆盖范围不应超过输入。

没有图像时，可以帮助制定观察问题或分析文字材料，但不能声称看到了道具纹理。没有完整片段时，不能把抽样帧拼成确定的动作过程。

### 2. 把四种操作分开

**观察：**记录能定位的对象、属性、关系和变化。

**外部核查：**寻找制作、历史或作者陈述，标注来源范围。

**解释：**基于已有证据提出关系与动机假设，保留替代解释。

**创作：**把当前需求和参考机制组合成新方案，明确这是提出而非发现。

这四种操作可以由同一工具完成，但输出身份必须清楚。分成多个 agent 也不会自动解决问题：若都读取同一份未经核实的总结，只会重复同一个错误。

### 3. 自我复述不能算独立验证

让同一个模型把结论再解释一次，可以用于发现内部矛盾，但不能证明图像中确实存在所说对象。应把关键判断重新绑定到实际材料，由人工或独立的证据检查过程核对。

2018年的图像描述研究和2023年的对象幻觉评测为这种风险检查提供参考，但不构成对当前任意系统效果的完整评测。[R32][R33]

### 4. 评价模型时，把任务拆开

建议分别检查对象是否出现、属性是否有依据、关系是否定位正确、引用是否支持对应句子、未知是否被保留、创作建议是否明确标为新提案。

这些是本篇提出的审查维度，不是现成的统一基准。不能用“文字很专业”的总分代替它们，也不能把对象识别正确等同于风格分析准确。

记录错误率时，应写清分母和抽样单位。例如，核查了哪些可见事实陈述，哪些无法核查；无法核查项不要当作正确，也不要悄悄丢掉。对开放解释问题，说明论证质量往往比强制二选一更合适。

### 5. 生成候选不等于批准执行

模型提出的场景、材料和动作还需要经过第六篇的原型问题与第七篇的评价。某张概念图被选中，也不自动批准全部制作细节。

工作记录要保存批准的是概念、构图、材质还是终稿，不能让后续工具因为看见“通过”两个字就跳过未完成检查。

## 十、生产交接：信息写出来，还必须有人真正使用

知识卡最容易失效的地方，是字段齐全却没有进入下一项行动。

例如，卡片写明“包装正面不允许遮挡”，生成阶段却只读取“梦幻植物庭院”；评审再凭个人感觉重写目标；最后所有文件都有自己的“最终方案”。记录越多，真相反而越分裂。

本篇建议把交接缩小为几个明确问题：接收者必须读取哪些依据？要作什么决定或产出？哪些规则不可自行改变？缺少什么时需要停在候选状态？完成后如何回写实际使用的版本？

### “同一依据”不等于“只有一种解释”

当前批准的产品信息、素材版本和制作任务应有明确依据，不能由每个环节重新猜测。艺术解释则可以保留多种观点，不需要为了所谓统一而删掉分歧。

需要统一的是正在执行的选择及其范围，不是消灭所有其他可能的看法。

### 每一项重要字段应有消费目的

记录“失效条件”，是为了迁移前检查；记录“证据身份”，是为了防止把假设当事实；记录“允许变化”，是为了给执行保留空间。若某个字段永远无人读取，也不影响判断，就不必为了完整而长期维护。

轻量流程可以只用一个文件中的当前决策区和历史记录。复杂流程再拆为独立卡片或系统对象，避免从一开始为简单问题建立庞大架构。

## 十一、一份最小的结构化示例

下面是**虚构教学模板**。没有真实图像资源，因此资源标识与定位保持空值，不制造不存在的文件或帧号。

```yaml
record_id: example_scale_environment_001
record_version: 1
record_kind: teaching_example
source:
  asset_id: null
  asset_version: null
  available_material: fictional_text_description
  locator: null
scope: single_concept_description
observation:
  statement: 描述设定中，叶片大于产品并形成前后遮挡
  evidence_kind: supplied_description
interpretations:
  - statement: 植物可能从成分陪衬转变为主体所处的环境
    kind: analytical_hypothesis
    author: knowledge_pack_example
    support: observation
    alternatives:
      - 仍可能只被理解为巨型道具展示
production_fact:
  actual_material: null
  actual_method: null
transfer_rule:
  problem: 小型象征元素没有参与空间表达
  operation: 将元素转化为可组织前后关系的空间结构
  preserve:
    - 能够辨认的尺度关系
    - 与新任务相关的主体和环境关系
  may_change:
    - 具体元素
    - 配色
    - 物理或数字实现方式
  failure_conditions:
    - 裁切删除了关键尺度线索
    - 元素仅被放大但没有构成空间关系
validation:
  performed: false
  required: 实际图像检查与符合任务的观看反馈
active_project_decision: null
```

这个结构不要求采用 YAML，更不要求所有系统照搬字段。可以转成自然语言、表格或实际应用的数据格式；关键是保留来源、身份、范围和使用条件。

### 一个真实项目至少要补齐什么

把教学设定替换成实际可访问材料；记录真实版本和定位；区分可见事实与文本转述；确定当前任务；说明谁作判断及哪些检查已完成；只有实际确认发生后，才写入批准范围。

如果某个值仍然未知，保持未知比填一个看起来合理的猜测更有用。

## 十二、怎样维护，而不是越存越难使用

### 1. 新增时检查是否真有新知识

与已有卡片只有颜色不同，可能只需增加一个案例；出现新的失效条件、新的组织关系或不同任务，则值得新建或修订规则。

不要用数量作为唯一进展指标。能否回答新的设计问题、能否找到原证据、能否避免重复犯错，更接近资料库的实际用途。

### 2. 更新时保留理由，不覆盖历史

修正错误事实时标记原结论被替代；增加解释时保留原解释；改变项目选择时说明谁在什么范围内确认了新决定。这三种更新不能混成一个“最新版”。

旧记录可以继续作为历史材料，但不应被默认当成当前执行要求。

### 3. 定期检查失效链接与权限

来源失效不一定立刻否定已经核对的笔记，但会降低再次验证的便利；应记录状态，并在权限允许范围内保留必要的来源信息。

公开可访问的研究链接与可直接商用的图片资产不是同一类东西。来源管理帮助识别问题，不替代具体使用许可确认。

### 4. 用新任务做回归测试

从新需求出发检索旧卡，尝试提出与原案例外观不同的方案，再检查是否仍保留了正确的关系。若只会产出原图变体，说明知识可能仍停留在表面配方。

这里的“回归测试”是工作类比：检查修订后的方法是否仍能处理既有问题，不宣称艺术创作具有唯一标准答案。

## 十三、可直接转写为 skill 的执行规范

### 适用触发

当用户需要保存拆片成果、整理参考库、形成可迁移方法、建立团队分析模板或为 AI 准备可靠知识时使用。

不自动把所有历史作品解释升级为通用创作规则，也不默认把用户资料上传到任何外部服务。

### 执行过程

确认实际材料与用途；选取关键决策；定位观察证据；分离资料事实与分析解释；记录竞争解释；提炼有条件的迁移规则；加入反例和失效条件；确认权限与版本；把记录连接到实际检索、创作或评审任务。

有新测试结果时，更新相应规则或适用范围，不只把结果附在末尾。

### 输出的轻重分级

个人练习可以只交一张决策卡和一句迁移规则；团队复盘增加版本、职责、交接和修改依据；长期 AI 资料库再增加编码说明、来源链、质量抽查与维护记录。

这些是扩展选择，不是每次都必须完成的三重审批。

### 完成条件

关键结论能找到对应来源；不同证据身份没有混写；规则说明适用与失效条件；记录没有虚构精确定位；未知没有被自动填满；下游知道哪些内容可以使用、需要检查或不能继承。

## 十四、对抗性测试：知识越可复用，越需要防止错误被放大

| 测试情形 | 应避免的行为 | 合格反应 |
|---|---|---|
| 没有实际图片，只提供风格描述 | 声称看见具体反射和道具 | 只分析文字，列待观察问题 |
| 只有一张关键帧 | 编写全片变化规律 | 限定单帧或已有片段范围 |
| 多篇文章转引同一采访 | 计成多份独立证据 | 连接到共同来源 |
| 作品出现陌生物件 | 按常见场景补全身份 | 保留不确定并检查原图 |
| 两种解释都有合理依据 | 强制存成唯一事实 | 分别记录作者、证据和范围 |
| 参考图被裁切或调色 | 继续沿用旧定位与颜色判断 | 检查派生版本及受影响结论 |
| 旧资料确认了制作事实 | 用其覆盖当前作品的未知项 | 核对对象和版本是否相同 |
| 原则只在一个案例提出 | 宣称普遍有效 | 标记探索性，补迁移测试 |
| 候选图被选中 | 推定所有制作环节已批准 | 记录批准维度与剩余检查 |
| 模型解释流畅且重复一致 | 当作已独立验证 | 回到实际证据逐项核对 |
| 旧论文报告模型错误 | 直接预测所有当前模型表现 | 保留年代、模型与任务边界 |
| 记录了很多字段 | 默认流程已经消费它们 | 检查字段如何影响实际下一步 |
| 某案例权限不明确 | 因能检索到就直接复用资产 | 区分知识参考与具体资产使用 |
| 规则遇到反例 | 删除反例以保持体系完整 | 收窄、拆分或修正规则 |

## 核心原则

> **一次视觉分析的最好沉淀，不是最完整的形容词清单，而是一组能够回到证据、保留解释边界、指向设计选择的记录。资料告诉我们看过什么，决策卡解释哪些关系值得注意，规则卡说明可以怎样尝试，迁移与测试则告诉我们条件改变后还剩下什么。让每个结论知道自己的来源、范围和用途，才能把作品研究变成创作能力，而不是把一次猜测变成长期重复的事实。**


## 文献与来源：核对范围及适用边界

下列编号与正文相连。研究／理论、专业资料和主创陈述承担不同证据角色；可检索到摘要不代表已通读全文。所有网页于2026年9月18日本轮调研中检索或核对。

### R27｜W3C Provenance Working Group（2013）

[PROV-Overview](https://www.w3.org/TR/prov-overview/)。**资料性质：**W3C工作组说明文件。

**本次核对：**摘要、文档家族及实体—活动—参与者的来源概念。**用于：**记录结论由什么材料、哪些活动和参与者形成。**限制：**该概览是Working Group Note，不把它误称为Recommendation；不要求项目必须用RDF实现。

### R28｜W3C Web Annotation Working Group（2017）

[Web Annotation Data Model](https://www.w3.org/TR/annotation-model/)。**资料性质：**W3C Recommendation。

**本次核对：**主体、目标、特定资源、片段选择器相关章节。**用于：**把观察或解释绑定到具体图像区域、文本或时间区间。**限制：**本文简化记录不是对完整标准兼容性的声明。

### R29｜W3C Semantic Web Deployment Working Group（2009）

[SKOS Simple Knowledge Organization System Reference](https://www.w3.org/TR/skos-reference/)。**资料性质：**W3C Recommendation。

**本次核对：**词汇标签、概念关系、映射关系相关章节。**用于：**把概念身份、名称和上下位／相关关系分开。**限制：**语义相近不自动等于严格同义，标签系统也不是唯一正确的艺术史分类。

### R17｜Bruno Sartini、Sofia Baroncini 等（2023）

[ICON: An Ontology for Comprehensive Artistic Interpretations](https://cris.unibo.it/retrieve/9c8fdd2b-0841-4c22-b68e-215e57b4d86c/ICON.pdf)。**资料性质：**同行评议本体研究。

**本次核对：**摘要、引言及第2节理论范围；核对PDF第3页图像。**用于：**区分对象识别与解释，并容纳解释者及多重解释。**限制：**不是作者意图探测器，不是视觉识别准确性保证；Panofsky部分通过该论文而非本次通读其原著核对。DOI: 10.1145/3594724。

### R30｜Mark D. Wilkinson 等（2016）

[The FAIR Guiding Principles for scientific data management and stewardship](https://www.nature.com/articles/sdata201618)。**资料性质：**原始原则论文。

**本次核对：**正文原则表与可访问、复用说明。**用于：**可发现、可访问、互操作、可复用，包含必要时的授权访问。**限制：**FAIR不等于必须公开所有原始资产，也不能替代权限或质量检查。

### R31｜Timnit Gebru 等（2021；预印本首版2018）

[Datasheets for Datasets](https://arxiv.org/abs/1803.09010)。**资料性质：**作者预印本记录；已发表于CACM。

**本次核对：**v8摘要、版本历史、出版信息。**用于：**记录资料集的动机、组成、收集过程及适用用途。**限制：**仅借用资料说明思想；不是宣称自建参考库已完成正式数据集评估。

### R32｜Anna Rohrbach、Lisa Anne Hendricks、Kaylee Burns、Trevor Darrell、Kate Saenko（2018）

[Object Hallucination in Image Captioning](https://aclanthology.org/D18-1437/)。**资料性质：**原始同行评议研究。

**本次核对：**ACL官方摘要、书目信息。**用于：**语言流畅或描述相似指标不保证对象确实存在于图像。**限制：**研究针对其时代的图像描述模型与MSCOCO；不可据此给当前所有模型相同错误率。

### R33｜Yifan Li 等（2023）

[Evaluating Object Hallucination in Large Vision-Language Models](https://arxiv.org/abs/2305.10355)。**资料性质：**原始研究；EMNLP接收论文的作者记录。

**本次核对：**摘要、出版说明与版本信息。**用于：**对象幻觉需单独评测，输入措辞与评价方式值得检查。**限制：**仅作风险与评测方法启发；未将POPE直接当作美术风格理解基准。
