# 路由

| 路径 | 场景 | 顺序 |
|---|---|---|
| A | 建立完整理解 | 从第一篇开始，依次读第二至第八篇；案例先区分“有来源的制作陈述”和“虚构教学推演”；末尾反例测试检验是否掌握边界 |
| B | 正在拆一张图或一条影片 | 第一篇限定词义和范围 → 第二篇观察 → 需要解释融合进第三篇、研究美术工作进第四篇、谈出发点进第五篇 → 第七篇条件性评价 → 第八篇保存关键决策 |
| C | 正在形成新方案 | 以第六篇为入口拆任务与限制 → 参考迁移回第三篇 → 生产展开读第四篇 → 第七篇设计原型评审与测试 → 第八篇保存实际采用的规则；第五篇提醒新提案不是对旧作品真实意图的发现 |
| D | 准备团队模板或 AI 知识 | 先读第八篇理解该保存什么 → 从各篇 skill 规范选取真正需要的输入、步骤和检查；理论解释规则为什么存在，反例测试是否被执行 |

# 各篇应带走的能力

第二篇写出比“高级、梦幻”更可检查的描述；第三篇说明混合来源之间的组织关系；第四篇辨认美术决策对象而不冒认幕后事实；第五篇保留并比较解释；第六篇形成方案与原型问题；第七篇给出条件清楚的判断与修改；第八篇保存未来真正用得上的关系与边界。

# 禁止

- 不在尚未观察时先套第五篇的动机解释；不用第七篇的偏好判断反过来决定第二篇“看见”什么。
- 不只抽取关键词列表或 YAML 字段就称为知识迁移：字段需要被下游使用，未知项保持未知。
- 不要求每次完整执行八篇——它们是可组合的方法模块，不是强制的八重审批。

# 交付边界

原始材料是研究型 Markdown 知识文档；结构化示例可转成应用数据结构，但**没有部署插件、修改现有系统或运行真实用户项目**。外部链接不代表相关图片、字体、影片等资产已获项目使用许可。
