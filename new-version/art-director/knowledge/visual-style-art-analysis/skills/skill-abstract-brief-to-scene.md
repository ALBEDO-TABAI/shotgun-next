# 输入

需求、媒介与观看条件、必要产品或叙事信息、限制、已有素材和未决问题。

# 执行过程

区分任务、限制、目标、偏好和假设（[brief 五种信息](/frameworks/brief-five-information-types.md)）；提出不同机制的概念路线（[路线与变体](/frameworks/concept-routes-vs-variants.md)）；选择并写出关系命题（[概念三层次](/frameworks/concept-three-levels.md)）；组织有明确借用理由的参考；展开空间、道具、材料、光和时间（[七个层面](/methods/concept-to-scene-seven-layers.md)）；识别高影响未知；制作能回答问题的原型；依结果修改或确认；输出下游能消费的方案。

# 输出

需求判断、概念路线、选定视觉命题、核心规则、场景与动作关系、参考使用说明、原型计划、确认范围和剩余风险（[最小方案卡](/templates/visual-scene-concept-card.md)）。

# 完成条件

概念不只是形容词；至少比较过不同机制；核心关系能指导场景与道具取舍；原型有问题和下一决定；未知没有被生成图片的完成度掩盖；交接者知道哪些已确认、哪些仍需验证。

# 核心原则

把抽象要求转译成能生成选择的关系命题，再通过空间、物件、材料、光和时间共同实现。参考用于借方法，原型用于回答问题，确认必须说明范围。好的流程允许返回，但每次返回都应减少不确定性。
