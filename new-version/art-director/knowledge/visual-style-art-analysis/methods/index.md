# 方法 · Methods

可执行的步骤与流程：六步分面描述、四次观看、融合诊断、过程追踪、转译链、参考板、反馈与维护等。


# 一 风格概念辨析与分面分析

* [视觉风格分面描述：六步核心流程](six-step-facet-description.md) - 限定对象与证据范围 → 不带风格名描述 → 拆解每个标签 → 从特征推导组织模式 → 比较并核查（含替代解释）→ 输出有条件的概括。

# 二 视觉观察与形式证据

* [把大词改写成可分别核查的中层问题](big-words-to-mid-level-questions.md) - “冷峻的现代视觉”→空间是否常空置？人物是否被门框分隔？构图是否保持正面？规则何时被打破？每问需要自己的材料。
* [分析开头的材料说明：先检查你到底拿到了什么](material-version-statement.md) - 原始照片、压缩截图、网页预览、重剪视频、局部裁切还是最终发布版？有无声音、完整镜头起止、画幅、播放速度、显示尺寸？让未知继续存在。
* [四次观看：替代“一眼定风格”](four-pass-viewing.md) - 第一遍保留自然观看 → 第二遍不带风格名的分段描述 → 第三遍提取组织规则和局部反例 → 第四遍拿着反对意见回看；可按任务压缩。
* [视频抽帧：基本覆盖＋事件补充](video-sampling-coverage-plus-events.md) - 只抽开头中间结尾会漏掉短暂关键变化，只挑最漂亮帧会伪装出统一风格；先覆盖，再为遮挡、动作、场景切换补样，判断时长回到连续播放。
* [多人与 AI 协作：先定位分歧发生在哪里，再比较用词](locate-disagreement-before-words.md) - 分歧可能是对象边界、词义、观察材料、机制解释或价值判断不同；先比较定位与证据；观察阶段可先不提供想要的风格名以减少诱导。

# 三 混合风格与融合规则

* [判断融合是否成立的五类诊断](five-fusion-diagnostics.md) - 去标签测试、去元素测试、换材料测试、跨镜头与跨版式测试、陌生参照测试——发现问题的工具，不是统一审美分数。

# 四 美术工作与设计决策

* [空间设计：先问行动，再问装饰](action-first-space-design.md) - 人在这里能做什么、物体从哪进入、转身看见哪些区域、门窗台面通道如何限制动作、摄影机有无观察位置；静物也有倾倒、滴落、转动、开启的行动逻辑。
* [以镜头检验空间，而不是让概念图替代空间](test-space-with-camera.md) - 关键视觉只说明一个观看位置，不证明横移、低机位或反打成立；用低成本空间模型或简化预演检查关键观察位置，再决定制作到什么程度。
* [“拿掉会损失什么”比“为什么放这个”更容易暴露空泛理由](what-is-lost-if-removed.md) - 回答只有“更有氛围”时继续追问通过哪条关系；叶片遮出光斑、杯子迫使停顿、镜子显露画外都是具体作用；但这不是极端删减原则。
* [先明确完成条件，再决定制作精度](completion-condition-before-precision.md) - 只在固定正面镜头出现的背景不一定需要四面制作；会被绕拍、触摸、破坏或浸湿的物件不能只凭一张关键视觉决定完成度；分开“镜头需要的精度”与“工艺默认精度”。
* [预算下降时：先保护作用关系，再调整实现路径](budget-cut-protect-relations.md) - 区分核心不变量与可替换实现；可以换材料、缩小可见范围、调整镜头或简化重复结构，但检查哪种变化会破坏主要关系；“全部降一级”无法回答这个问题。

# 五 创作出发点与解释边界

* [过程追踪：从漂亮的终点故事回到实际决策](process-tracing.md) - 起初的具体问题、第一次可定位方案、触发修改的材料或反馈、保留与放弃、最后版本、后来如何解释；每项都可能未知；不同时间的陈述可能都真实却回答不同问题。
* [从解释走向创作时显式换轨：三种句式](explicit-track-switch-three-sentences.md) - “该资料记录了作者……”（陈述事实）／“依据这些画面，我提出……”（分析解释）／“在当前项目中，可以尝试……”（新方案建议）；防止 AI 编出的意图被存成“已验证大师方法”。

# 六 从抽象需求到场景方案

* [至少澄清四个关系问题，优先澄清会改变概念选择的问题](four-relationship-clarification-questions.md) - 谁在什么条件下看？希望改变哪种理解或感受？什么信息必须出现、何时出现？哪些宁可不做也不能误表达？不必一开始问完二十个表格。
* [把感受词变成候选机制：任务 → 观看关系 → 候选机制 → 可见事件 → 场景与材料 → 测试问题](feeling-word-to-mechanism-chain.md) - 同一个“轻盈”可来自悬浮、薄片、少接触、稀疏布局、缓慢摆动、开放空间或人物卸下重物的动作——不是同义词，而是不同设计路线。
* [防止概念空转的两项检查](concept-idle-checks.md) - 拿着概念面对两个不同道具能否说明为何选一个？拿掉关键关系后概念是否仍能原封不动套用？任何方案都符合→过宽；只允许复制一张参考→只是外观别名。
* [参考板：每张图写“借什么、不借什么、如何进入当前方案”](reference-board-borrow-exclude-enter.md) - 按问题组织（空间关系、材料与光、人物与物件互动、时间揭示、历史资料）；主动保留反参考与边界案例；不让一张高完成度图替代所有答案。
* [把概念展开为联动方案：场景、置景、道具、材料、光影、时间、部门接口](concept-to-scene-seven-layers.md) - 先定关系骨架，再让每个构件有角色；道具区分看见、使用和变化；材料先定所需性质；光参与场景关系；设计观众什么时候得到什么；声音等只记录接口不越权。
* [AI 辅助构思：拆成“当前要探索的关系”与“不得破坏的条件”](ai-ideation-relations-and-constraints.md) - 一轮只研究叶片与产品相对尺度、一轮研究光透过叶片、一轮研究竖版空间开口；生成数量≠概念探索；明确一张图通过了哪一维；规则改变后同步检查提示词与参考。

# 七 作品评价与反馈验证

* [必须评分时，先写项目专用锚点](scoring-anchors.md) - 如“产品识别”三级描述：目标尺寸下主要特征无法辨认／能辨认但受干扰／当前条件下能完成既定识别任务；有序类别不是等距测量；“高级感八分”无法支持修改。
* [比较时先确定：是选整体，还是解释原因](compare-whole-vs-explain-cause.md) - “两套方案哪套更适合继续”可比较整体但不能归因到某颜色或道具；“瓶身区分不足是否由背景纹理造成”需限制其他变化；随机分配不是按名单轮流，随机展示不是永远先A后B。
* [处理评审意见冲突：先判断冲突在哪里](resolve-review-conflicts.md) - “太空”与“很克制”可能是目标不同；对同一细节描述不同可能是观看尺寸不同；同条件仍有分歧则保留审美立场差异；先修事实错误，再明确决策权，记录未被选择的合理解释。
* [从评审意见走向修改与验收：三类事项与批准范围](review-to-revision-acceptance.md) - 必须修正的已确认问题、值得测试的风险、允许并存的偏好或解释分开列；每项修改有对象、理由、范围、负责角色、复查方式；“概念通过”不自动批准材质、成本和成片。

# 八 分析沉淀与知识复用

* [建立参考库而不是“审美回音室”](reference-library-building.md) - 收集理由进入条目；说明覆盖与偏向；不把转载次数当独立证据；为关键概念写编码说明并做多人独立试标；检索同时支持“像什么”和“解决什么”。
* [评价视觉模型时把任务拆开，并写清分母与抽样单位](evaluate-model-by-split-tasks.md) - 分别检查对象是否出现、属性是否有依据、关系定位是否正确、引用是否支持对应句子、未知是否保留、创作建议是否标为新提案；无法核查项不当正确也不悄悄丢掉。
* [知识维护：新增时判断是否真有新知识、更新保留理由、检查链接与权限、用新任务做回归测试](knowledge-maintenance.md) - 只有颜色不同可能只需加案例，新失效条件或新组织关系才值得新建规则；从新需求检索旧卡并提出外观不同的方案，只会产出原图变体说明仍停在表面配方。

# 09 研究来源与适用边界

* [本轮研究怎样组织：从七个问题出发找资料，按实际核对范围使用](research-and-source-organization.md) - 优先研究原文或作者机构记录、方法提出机构、专业协会与主创访谈；能访问全文只用相关段落，PDF 按相关页核对，付费论文仅摘要时保持摘要范围。
* [后续补充资料的原则：先说明哪个判断需要更多证据](adding-sources.md) - 讨论实际材料找制作记录或主创信息；讨论观看效果找匹配目标人群、任务和媒介的研究；讨论历史引用比较形式并核对历史联系；发现更正或反例要修改受影响判断而非只加链接。
