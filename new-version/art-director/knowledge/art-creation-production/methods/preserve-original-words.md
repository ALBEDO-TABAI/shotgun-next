# 做法

1. 原样保存需求方的句子（含来源、时间）。
2. 旁边分列：**暂时解释**、**依据**、**可试操作**。
3. 用 [原话中的六种信息：任务／硬条件／感受目标／形式偏好／实现建议／未验证判断](/frameworks/six-information-kinds.md) 给每句定性。
4. 反馈到来时对照原句更新解释，而不是改写原句。

# 为什么

当解释出错，团队可以返回真实需求，而不是在不断加工过的转述之间争论。
