# 证据核验、冲突处理与内容综合

## 1. 分开三个判断

**来源是否可识别？材料是否实际获得？它是否支持这条结论？** 三者不能互相代替。

同一个来源可能在不同主张上价值完全不同：官方网页能直接证明它公布的功能或声明；对真实效果、群体行为、因果机制仍要检查材料与方法。无法访问是访问状态，不自动说明来源低劣；名气大也不能补上未读部分。

本版移除原版全局 A/B/C/D 身份等级及“一个 A 或两个 B 即稳定”的公式，改成来源记录与结论判断分离。这里不提供自动真实性判定器。

## 2. 来源最小记录

| 项目 | 记录内容 | 用来防止 |
|---|---|---|
| 来源定位 | 标题、URL/文件标识、必要的作者/发布者 | 凭空引用与无法回溯 |
| 阅读范围 | full / partial / abstract / snippet / unavailable | 摘要冒充全文 |
| 实际定位 | 页码、章节、段落、时间码或数据字段 | 用整篇文档掩盖无关引用 |
| 时间语境 | 发布/更新/事件/检索日期，未知则写未知 | 新旧状态混淆 |
| 原始出处 | 自有观察、研究、数据、转载源头 | 假独立、循环引用 |
| 方法与边界 | 样本、条件、适用域、利益关系 | 过度推广与宣传结论 |
| 用途 | 支持、部分支持、反驳、背景、线索 | 所有资料都被当成佐证 |

`full` 只在确实获取并阅读完整材料时使用；查看了足以支持窄事实的章节应写 `partial`，这不等于证据必然弱。`abstract` 只能承载摘要实际说明的内容，并标明未核对方法和细节。`snippet` 和 `unavailable` 只能作为线索或访问限制，不承载已核实事实。

## 3. 最小结论卡

> **结论：** 一条可核验的主张。  
> **类型：** 事实 / 分析推断 / 建议 / 待验证假设。  
> **依据：** 来源与具体位置，简短转述。  
> **支持关系：** 直接、部分、仅背景或相反。  
> **范围与限制：** 适用条件、未控制因素、尚未知道什么。  
> **信心与理由：** 较强 / 中等 / 较弱 / 未知，说明为什么。  
> **对用户的意义：** 它改变哪个判断或操作。

不要把包含三个事实、一个解释和一个效果承诺的长句当一个结论。拆到引用能对应的粒度，但不用把常识或纯逻辑推导拆成几十张卡。

### 判断引用是否支持

- 来源只说“可以导出”，不能写“无需额外费用且所有地区都能导出”。
- 来源展示一个作品有对称构图，不能写“该作者所有作品都采用对称构图”。
- 来源说受访者喜欢某体验，不能写“大多数消费者偏好这种体验”。
- 两来源分别证明 A 与 B 存在，不能直接拼成“A 导致 B”。连接关系本身也需要证据或明确标为推断。

引用质量与回答正确性应分开检查；ALCE 研究为这一区分提供依据，见 M05。它的评测结果不能作为本 skill 的质量评分。

## 4. 不同主张需要不同证据

| 主张 | 适合的证据 | 通常不足以独立支持的材料 |
|---|---|---|
| 官方公布了某规格 | 当前官方文档的相应内容 | 旧缓存、无版本教程 |
| 某作品具有可见特征 | 已核验的原作品/清晰图像或连续片段 | 无源缩略图、文字简介 |
| 主创意图或制作选择 | 可追溯主创陈述、制作记录 | 观众仅凭外观猜测 |
| 方法在某条件下有效 | 与条件相符的方法和结果材料 | 单独成功故事、销售文案 |
| 某方法普遍优于另一种 | 可比任务、样本、评价指标和限制 | 不同设置排行榜、两个各自宣传页 |
| 某现象普遍流行 | 说明范围的分布/趋势数据 | 个性化推荐页、少数热门帖子 |
| 用户应采用某方案 | 事实证据 + 用户目标/约束 + 权衡 | 仅有一个漂亮案例或一项性能数据 |

领域已有更严格证据标准时遵守它。医学、法律、金融等高风险研究要使用适配来源、明确情境并遵守宿主限制；不能把这张通用表当专业规范替代。

## 5. 信心与状态

结论状态：

- **supported**：现有材料直接支持所写范围；不意味着永远正确。
- **qualified**：只有条件化或较窄支持，必须保留限定。
- **contested**：可读材料存在实质冲突；说明不同口径与未消解部分。
- **unverified**：尚不能确认；可用于指出未知，不得包装成事实。

信心是定性判断而非概率。可依据直接性、方法质量、独立性、一致性、时间与场景适配解释；不要给每项随意打分再算“93%可信”。多个同源来源不能提高独立性。一个直接的一手来源可足够回答窄事实，但单个一手案例不能证明普遍规律。

建议不是事实：其合理性来自证据与目标的组合。纯创作提议或待验证方向不需要伪造参考文献，需明确它尚未被验证。

## 6. 冲突处理流程

1. 明确两个来源实际冲突的具体陈述，不把侧重点不同当相反。
2. 对齐实体、版本、地区、时间、样本、指标定义和使用条件。
3. 查原始出处；识别转述误差、更新、纠正或撤回。未查到撤回不等于证明永无撤回。
4. 分辨可观察事实冲突、价值标准差异、因果解释竞争。
5. 能解释则写出条件化结论；不能解释就保留分歧并说明对用户决策的影响。

不得按网址数投票；不得把两个不兼容数字平均；不得因为用户喜好其中一方就降低另一方的相关证据。

### 冲突结论模板

> A 的说法适用于……；B 的说法采用……条件。两者目前不能直接比较。对本次用途，最重要的缺口是……。现有材料足以支持……，还不足以选定……。

## 7. 数字、比较与负证据

数字保留单位、分母、时间范围、地区、样本与来源；计算结果标明计算方法，且确认输入口径一致。不用小数位制造准确感。

找不到证据有多种解释。限定为“本次检索未找到”时，应说明检索渠道或范围；不能从搜索失败推出不存在。数据缺失、页面失效和没有研究结果要分别写。

“没有发现显著差异”不直接写成“完全一样”；“作者未报告某指标”不写成“该能力为零”。统计或方法解释不确定时查原始方法及领域资料，不靠术语印象判断。

## 8. 从资料到综合

**弱综合**：官网说了 A，媒体说了 B，论坛说了 C。

**强综合**：围绕问题写哪些结论被共同支持、哪些条件导致分歧、哪些仅是信号、对用户如何取舍、还有什么不能确定。来源作为证据进入论证，而不是网站名的串联。

遵循：

> 已观察到什么 → 可以解释到哪一步 → 不能推出什么 → 对当前用途意味着什么。

特别检查两个“跳跃”：从他人说法到客观事实，从局部事实到总体结论。STORM 论文指出的来源偏见传递与无关事实过度关联，正是本版设置关系审查的原因之一；本版具体门槛是设计选择，不是该论文已验证结论，见 M04。

## 9. 知识包的可执行转化

每个重点知识单元尽量有：

- 清晰概念与近似概念区别；
- 机制或理论，不确定时标为解释框架；
- 方法步骤与选择条件；
- 对照案例、失败模式和不适用条件；
- 实施检查或验证方法；
- 支撑来源及实际阅读范围。

不要求所有单元同字数、同来源数。理论薄弱的环节标注实践性启发，实证不足处不能虚构学术背书。构造例子必须明确“教学假设”，不可伪装成真实客户案例或试验。

## 10. 引用与文件输出

聊天使用宿主可解析的来源引用；离线报告采用稳定 URL、文件名称/路径加页码或时间码，并用 S001 等 ID 对应来源表。不能把聊天内部的临时引用 token 原样作为离线唯一证据。

准确引用支持的位置，翻译引语注明译文与来源；不要引文拼接改变原意。引用与摘录遵守宿主版权限制。默认保存必要的简短摘录、摘要及定位，而不是整站、整书、全部歌词或全部口号。

报告是研究记录的阅读视图；需要机读交接时，来源和结论 ID 以一份记录为准，修订后同步关联段落。模板不创造事实，校验脚本不替代阅读与语义判断。
