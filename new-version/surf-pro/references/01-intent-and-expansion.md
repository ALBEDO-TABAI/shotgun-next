# 需求理解与适度延展

## 目标：补足信息需求，而不是替用户决定目标

用户说出的检索词，可能只是入口。例如“帮我找高级感广告”，既可能是找片单，也可能是理解视觉机制、做提案、写提示词或判断已有方案。它们的来源、研究单位和交付方式不同。先判断**资料将被拿去做什么**，但不能只凭一个词就认定用户的隐藏意图。

Bates 的 evolving search / berrypicking 模型说明了需求与检索方向可能随接触资料而演化；本模块把这一思路转成可撤回的工作假设，不把初始问题当成永不可调整的关键词。方法来源与适用边界见 `references/08-methodology-sources.md` 的 M03。本模块的分类、门槛与示例是本 skill 的设计，不是已经验证的心理测量模型。

## 1. 最小需求画像

在工作记录中保留以下内容；通常不需要全部展示给用户。

| 字段 | 要判断什么 | 会改变什么 |
|---|---|---|
| 原始请求 | 用户到底说了什么，包括“只要”“不要” | 防止改题和漏答 |
| 使用目的 | 了解、比较、决策、创作、执行、建立知识包 | 研究深度与报告形态 |
| 对象与单位 | 一个作品、一个品牌、一类技术、一段历史 | 检索实体及比较单位 |
| 成功标准 | 用户读完后应该知道或能做什么 | 停止条件和内容筛选 |
| 硬约束 | 地区、时间、预算、语言、素材/数据边界 | 排除不适用信息 |
| 已有材料 | 链接、附件、历史版本、已确认偏好 | 防止重复工作 |
| 不确定项 | 已确认、工作假设、待验证可能性 | 表述与澄清方式 |

不要自动把用户所在位置当研究地区，把中文当来源语言限制，把历史行业背景当本次需求，把“多找一些”理解为“无上限”。也不要为了完善画像索取无关个人信息。

### 用途导向的改写

弱：“调研高级感。”

强：“在用户未限定具体品牌的情况下，暂按用于一条商业短片的参考研究处理：识别几种可区分的表达路径，说明它们各自适合什么需求、如何实现、何时会失败；不先假定高级感只有一种外观。”

这里“用于商业短片”若没有上下文依据，应作为暂定解释并可被用户纠正；不能写成用户已明确要求。

## 2. 模糊性分类及动作

| 模糊类型 | 示例 | 首选动作 |
|---|---|---|
| 指代缺失 | “搜一下这个效果”但没有图或名称 | 检查现有附件；确实没有时指出缺失，仍给可行识别方向 |
| 多义/同名 | “Apple 方案”“某某风” | 根据上下文与小范围搜索消歧；保留仍合理的分支 |
| 名称或版本可疑 | 产品/论文拼写疑似错误 | 检索原词与候选，明确哪些找到、哪些没找到；不宣布不存在 |
| 概念混合 | 风格、媒介、流派、技术混为一谈 | 先分层定义，再分别搜索；避免把不同层级排成同一排行榜 |
| 用途缺失 | “找案例”未说明做提案还是训练 | 采用低风险默认用途，必要时只问最影响输出的区别 |
| 尺度缺失 | “全面”“最近”“最好” | 明确范围、截止日、评价维度；不假装已有公认最优 |
| 约束冲突 | “只要国内”又“全面覆盖全球” | 指出冲突，优先保留明确排除条件，条件化交付 |
| 前提可疑 | “帮我证明这种方法一定有效” | 核查前提、适用条件和反例；不做选择性证据搜集 |

## 3. 何时问、何时先做

使用四个问题作定性判断：不同回答是否会显著改变检索方向？猜错的代价是否高？用户是否能轻松回答？现有资料是否已经能解决？这不是要求计算数字分数。

**先做：**材料可自行消歧；缺失项低风险可逆；几种解释共享大量有用研究；用户明确不希望被追问。

**问一个关键问题：**两种解释对应几乎不同的研究；关键管辖区、对象身份或使用条件影响结论；缺少必须由用户授权的访问或操作。

**边做边问：**先查共同基础、公开信息和不依赖缺失项的部分，保留分支；不得把问题当作逃避任务的终点。

用户说“随便”“你定”允许采用工作假设，不等于允许付费、泄密、改变安全约束。高风险场景不能用“默认”掩盖决定性缺失信息。

## 4. 三层问题图

### 核心问题

用户明确需要的答案。例如“比较两种视频制作方案”中的质量、成本、可执行性。每项核心需求必须有落点；不能只回答容易找到资料的部分。

### 必要前提

没有它会误导答案的条件。例如比较计价时的分辨率、片段长度、重试计费、地区与版本；分析视觉效果时区分静帧观感与运动表现；研究趋势时说明观察样本不是总体。

必要前提必须进入核心论证。即便用户关闭可选延展，也不能删掉决定正确性的限制。

### 增益延展

不是回答字面问题所必需，但可能使结果更有用：替代方案、反例、相邻概念、实施检查表、迁移条件、风险与后续验证。

新增研究问题不是新的用户命令。用户未授权的下载、购买、外发、账户连接或自动化设置，不因“延展有帮助”就可以执行。

## 5. 发现潜在需求的六条路径

只选能贡献新问题的视角，不机械扮演一圈角色。

| 路径 | 核心提问 | 适用情况 | 越界风险 |
|---|---|---|---|
| 上游原因 | 用户描述的是症状，还是原因？ | 流程低效、反复返工、效果差 | 把局部任务变成组织咨询 |
| 下游用途 | 用户拿到信息后还缺哪一步？ | 案例库、技术选型、知识包 | 自动代替用户采购或创作 |
| 关键反例 | 哪些相似做法会失败，为什么？ | 方法论、风格、经验规则 | 为反对而反对 |
| 相邻概念 | 哪个近似词最容易混淆？ | 专业术语、艺术风格、模型能力 | 泛百科式扩写 |
| 条件与迁移 | 对象/场景变了，结论还能成立吗？ | 跨行业、跨地区、跨媒介应用 | 用类比冒充目标域证据 |
| 评价与验证 | 用户如何知道自己用对了？ | 实践教程、提示词、工作流 | 凭空规定分数和“最佳”标准 |

STORM 的多视角提问为这一设计提供启发；这里只采用提问方式，不声称实现其多 agent 系统或复现论文效果，也不把模拟专家说法当来源。见 M04。

## 6. 延展准入与预算

一个延展项必须写得出：

> 它连接到哪个原问题？忽略它会少知道什么？现有证据或明确的工作假设是什么？这是否值得本次增加的搜索与阅读负担？

用三种处理决定，不需要生成复杂评分器：

- **纳入**：与目标直接相关、证据充分或明确属于建议，能改变判断/执行；先搜最小必要资料。
- **暂存**：有潜力，但关键证据不足或本轮成本不值；只说明有价值的待验证方向，不塞进结论。
- **排除**：仅共享词语、只是趣闻、违背约束、重复已有内容、价值无法解释。

**优先顺序：核心缺口 → 必要前提 → 高价值延展。** 不设“必须用 20% 篇幅延展”的比例。简单事实题可能零延展；知识包可有更多，仍要有明确边界。通常只沿核心问题走一层；只有发现决定性前提或用户要求深入时才继续展开，避免相邻主题不断递归。

### 范围升级

延展若发现直接影响答案的限制，应改列必要前提，更新问题图与报告相关部分。例如原本比较视觉效果，发现两方案输出并非同一种时间长度或处理链路，先纠正比较口径，而不是把它放在末尾“补充阅读”。记录调整原因，不静默改变用户目标。

## 7. 对用户如何表达

推荐：

> 我先按“用于实际创作的参考研究”理解，而不只是列片名。主线会回答你明确提出的内容；另补充两类容易影响落地的因素，并单独说明它们为什么相关。

> 除了你问的 X，我补查了 Y，因为它会影响 X 在当前场景是否成立。现有材料只能支持……，还不能证明……。

避免：

> 你真正需要的是一整套品牌战略。

> 我猜你潜意识里更想了解……。

> 我为全面性加了十几个相关领域。

“可能有用”不是事实证据，“可能是用户目的”也不是已确认需求。对外展示有用的假设与边界，不输出内部逐步推演。

## 8. 用户纠偏后的最小修改

“太泛”：收缩到具体用途、一个对象或一类决策，增加选择条件和可执行细节。

“太窄”：找出缺失的问题层级，而不只是同义扩写；补理论、方法、反例、边界中真正不足的层。

“跑偏”：回到原话和硬约束，撤回不成立的工作假设；移除依赖该假设的延展。

“多找点”：先判断是来源独立性不足、案例差异不足、材料不够深还是解释不完整；不要直接翻倍网址数。

原证据仍适用就保留。只刷新受影响的研究问题、结论与输出视图，避免每轮重新搜一遍并制造矛盾版本。
