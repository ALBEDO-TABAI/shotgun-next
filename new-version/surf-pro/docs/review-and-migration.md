## 1. 原版值得保留的部分

原版并非只做关键词搜索。它强调先定义要证明/观察的机制，再找权威与原始资料、反向追溯、补缺；要求实际查看图像证据、记录出处和不确定性；注意把结果整理为可复用研究档案。视觉模块也提醒不要把风格简化为形容词或只找单个好看案例。这些基础继续保留，但改为按任务需要启用。

## 3. 最重要的设计改变：延展是受约束的研究，不是替用户读心

先答核心，再补不可缺前提；只有能直接关联原问题、说明收益、具备证据或明确待验证标签、符合约束且负担合理的候选才纳入增益延展。

例如用户要“镜头衔接知识包”，声音和运动连续性可能影响核心答案，应判断是否为必要前提；选择时机、失败诊断和分镜写法直接帮助使用，可合理补充。电影工业史虽然相关，却未必有助本次用途，不能自动加入。

用户只要一个发布日期时，没有必要展示延展。用户要求开放研究时，可以扩大覆盖，但延展仍要直接锚定核心/前提，不能一路从广告跳到融资再跳到宏观经济。

本版没有设置“延展必占 20%”或固定来源数，没有把主观关联度写成伪精确数学评分。普通简报通常 0–3 项只是呈现建议，可以没有，也可以根据明确需求调整。

## 4. 结构设计与维护取舍

入口 `SKILL.md` 负责真正的执行路线和最关键边界。8 个参考模块按需读取，3 个模板按交付需要使用。视觉模块是通用调研 skill 的领域补充，不改变其他研究任务的目标。

机读记录和校验器只服务需要审计/交接的任务，不是每次搜索前必须填的表。唯一记录存来源与结论状态；报告按其形成阅读视图。校验器检查显式字段关系，但不能自动查真伪、判断语义或保证报告一致，仍需人/agent 检查。

没有加入第三方检索 SDK、多 agent 调度框架、付费服务、后台服务、云端状态库、插件清单或未验证的 API。避免为一个研究 skill 构建第二套运行平台。

## 5. 安装与旧版迁移

新版仍叫 surf-pro，但目录统一为 surf-pro。替换旧版时先移除/停用旧入口或旧目录，再只保留一个版本；不要让 surf-pro-ready 内的旧 name: surf-pro 和新版同时被发现。同名 skill 不应被当作会自动合并。

按目标宿主当前官方说明添加本地技能；常见位置为仓库 `.agents/skills/surf-pro/` 或用户 `~/.agents/skills/surf-pro/`。完整说明见 [README](../README.md)。这是单 skill 包，不是已经上架或完成桌面端导入实测的插件。

旧研究档案无需全部重写。旧 A/B/C/D 等级保留为历史记录，不直接映射成 strong/moderate。旧图像的路径、出处和可用证据可以复用，但重新标明实际阅读/查看范围和许可状态。只有继续本次研究时才更新受影响的资料与结论。

实际检查结果见 [验证报告](validation-report.md)。离线测试针对脚本结构规则和异常输入，不是对真实研究答案的准确率测试。

行为案例尚未运行；没有用户桌面端安装测试、真实开放检索对照、多模型实验、用户盲评或省时统计。能确认的是交付文件、引用路径和脚本规则经过本机检查；不能据此承诺不同宿主稳定产生同等效果。
