# 四小节 MIDI：把“怎么改”变成具体音符差异

这是主文第 3.3、3.4 节的原创教学材料，重点不是预设它“清爽”或“高级”，而是把作曲／编配的操作变成可编辑对象。它不是已试听通过的配乐。

## 文件

| 文件 | 只改变什么 | 比较问题 |
|---|---|---|
| [01_motif_base.mid](01_motif_base.mid) | 基础四小节旋律、和声与低音 | 认识原句与休止位置 |
| [02_motif_vo_space.mid](02_motif_vo_space.mid) | 删除第 2、3 小节的领奏，其他保持不变 | 不依靠整条音乐降音量，是否能获得可供人声使用的空间？ |
| [03_motif_open_ending.mid](03_motif_open_ending.mid) | 仅把最后的 D5 改为 E5 | 在相同和声与音色下，句末音改变了怎样的结束感？ |

第三个文件名表示待测试的方向，不保证听众必然感到“开放”。第二个文件并未加入旁白，因此单听音乐不能代替带人声的验证。

## 符号规格

四小节 4/4，总计 16 个四分音符拍；目标速度 118 BPM。科学音高记法使用 C4=MIDI 60；部分软件显示的八度名称可能不同，比较时以 MIDI 音高编号为准。

MIDI 为 format 1，分辨率 480 ticks/quarter，共四轨：一条速度／拍号等元数据轨，三条乐音轨。每个声部在三个版本中的程序号和力度都相同；本轮没有加入随机时差、表情控制器或音频处理。

| 轨道 | 通道（从 1 计） | GM 程序号（从 0 计） | 固定力度 |
|---|---:|---:|---:|
| Melody | 1 | 0，钢琴占位 | 70 |
| Harmony | 2 | 4，电钢琴占位 | 48 |
| Bass | 3 | 32，低音占位 | 58 |

这些程序号只是播放占位。接收软件可以忽略或重新映射它们；比较三个版本时，需自行保持相同的音源与设置。文件没有附带采样库或软件乐器，不应期待所有播放器发出相同声音。

MIDI 速度以整数微秒／四分音符编码，本文件为 508475；因此实际编码速度约为 117.999901667 BPM，四小节时长为 **8.135600 秒**。按理想 118 BPM 计算为 8.135593220 秒，相差约 6.78 微秒。所有轨道的最终事件均位于 tick 7680。这里只是 MIDI 事件长度，不含软件音源随后产生的释放尾音。

## 如何使用这个练习

将三个文件放在同一个音频工作站工程中比较，并确认其拍速及音源一致；部分软件导入时需要选择是否采用文件的速度信息。

先听基础版，观察第 1、2 小节保留了什么共同材料。再比较第二版的中段留白；随后加上自己的旁白或节奏相近的临时话语，检查是否仍然太密或变得失去连贯性。最后比较基础版与第三版，不能先把“开放”告诉试听者再把回答当成独立验证。

这个练习没有设置混音总线处理。可以在完成音符对照后，再尝试移调、换音色、改变发音和演奏表情，每次明确目前比较的变量。不要同时换音色、升高音量、改变旋律，再将所有差异归因于一个音符。

## 可复算代码与验证

[generate_midi.py](generate_midi.py) 只使用 Python 3.10+ 标准库，可重新生成相同文件：

```bash
python generate_midi.py --output-dir ./midi_output
```

[validation.json](validation.json) 记录本次实际的 MIDI 格式、音符数、时间与文件哈希检查。基础版与句末变化版各 33 个音符事件，留白版 26 个；伴奏完全相同。写出后进行了重新解析，检查 note-on/off 配对、轨道终点和两个变体的精确差异。

验证不包括真实 DAW 导入、音频渲染、监听设备或审美试听，也没有把“符号写对”当作“音乐好听”。
