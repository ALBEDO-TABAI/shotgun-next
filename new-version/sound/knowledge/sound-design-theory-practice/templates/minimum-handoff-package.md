# Schema
| # | 字段 | 说明 |
|---|---|---|
| 1 | 当前目标及阶段 | 方向／原型／制作／整合／验收 |
| 2 | 需消费的版本与素材 | 权威依据的具体版本 |
| 3 | 本次具体修改 | 只改什么 |
| 4 | 必须保持不变的条件 | 已批准、不可动的部分 |
| 5 | 需要返回的产物 | 形式与版本对应 |
| 6 | 验收和批准范围 | 谁批准、批准什么 |

交接**不需要**再次发送研究全文与聊天历史；需要的是完成当前任务必需的权威依据，并能追溯背景。

# Examples
交给混音的不是"音乐轻一点"，而是：
> C04 的信息前景已经批准；本轮只调整旁白窗口的声音关系；保留已选音乐材料和整体入点；检查关键词附近是否有新的音效事件竞争；返回对应画面版本的候选混音与修改记录，艺术批准仍由既定负责人完成。

# 接收方规则
- 可反向确认理解的输入与产出，但不必重写声音命题。
- 发现矛盾时指出**冲突字段及来源**，不在下游静默重判整个项目。

# 质量检查
> 另一个合格执行者接手后，是能直接开始限定任务，还是还要重新猜测此前做了什么决定？
