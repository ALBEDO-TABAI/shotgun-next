# 触发
需要判断声音方案是否"合适""做得好"；组织试听或评审；设计对照测试；做技术或交付验收；把反馈转成返修。

# 最小输入
- 本轮决策问题（[本轮决策句](/templates/review-round-decision-sentence.md)）；
- 获批目标、待比较版本、时间线版本、播放条件；
- 权利与技术约束；
- 涉及实际听觉评价时：**可访问的音视频**，而非只有描述。

# 处理步骤
1. 区分事实、感知、审美和业务问题 → [六个评价面向](/frameworks/six-evaluation-facets.md)
2. 确定主要判断对象 → [评价链](/frameworks/evaluation-chain-goal-to-decision.md)、[模糊目标拆分](/frameworks/vague-goal-concept-decomposition.md)
3. 选择专业评审／探索反馈／受控对照／技术测量 → [四类方法](/frameworks/four-evaluation-methods-scope.md)
4. 定义控制与允许变化 → [对照测试设计](/methods/controlled-comparison-design.md)、[响度匹配](/principles/loudness-matching-in-comparisons.md)
5. 按预定任务收集证据 → [三步提问](/methods/feedback-question-sequence.md)
6. 保留异常与替代解释 → [操作化与有效性](/principles/operationalization-validity.md)
7. 提出最小修改并在适用版本上复验 → [反馈记录](/templates/feedback-evidence-impact-action-retest.md)

# 输出
带证据范围的结论、未解决问题、修改记录、批准范围与条件（[验收报告四段式](/templates/acceptance-report-four-parts.md)、[批准绑定版本](/principles/approval-bound-to-version-scope.md)）。**不能只输出一个没有构成说明的综合分数。**

# 质量门禁（失败条件）
- 没有音频却宣称试听通过；
- 把少量偏好当总体规律（[结论强度](/principles/small-sample-claim-strength.md)）；
- 以峰值代替可理解性；
- 以技术标准名义给创意背书；
- 没有权利依据却标记可发布；
- 把尚未执行的测试写成已完成结果；
- "无法判断""未执行""有条件接受"被混为同一状态。

# 核心知识段（精炼）
先区分表达适配、形式审美、感知理解、技术播放、事实权利与项目目标，再为当前决策选择证据；表达的情绪、听者情绪、人物归因与偏好是不同对象；四类方法不能互相冒充；对照须控制无关因素并记录播放条件、响度处理、顺序与重复观看；少量反馈能发现问题但不支持总体比例或因果；结果落实到具体版本、使用范围、最小修改和复验记录。
