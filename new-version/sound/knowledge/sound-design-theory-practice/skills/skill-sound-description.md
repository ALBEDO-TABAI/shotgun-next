# 触发
- 需求／反馈里只有形容词、流派词或情绪词（"清爽""高级""梦幻""太厚"）。
- 需要为作曲、声音设计或生成工具写 brief。
- 团队对同一个词理解不一。

# 最小输入
- 对象／段落与当前版本；表达目标。
- 已有声音事实（若有）或待生成材料说明。
- 工具实际能力（已确认／未确认）；交付约束（若有）。

# 处理步骤
1. 按 [五层描述](/frameworks/five-layer-sound-description.md) 拆开目的、现象、参数、时间、验收。
2. 分别描述时间（[速度／拍点／节奏／密度／律动](/frameworks/time-language-tempo-pulse-rhythm-density-groove.md)）、[音高组织](/frameworks/melody-motif-contour-description.md)、[和声稳定感](/frameworks/harmony-stability-description.md)、[音色形态](/frameworks/timbre-four-questions.md)、[发音](/frameworks/articulation-performance-behavior.md)、[配器活动](/frameworks/density-orchestration-activity-roles.md)、[空间](/frameworks/spatial-language-distance-size-clarity-width.md)、[动态](/frameworks/dynamics-loudness-peak-distinction.md)。
3. 音效用 [事件描述句式](/templates/sfx-event-description-sentence.md)；变化用 [五种变化关系](/frameworks/describing-change-five-relations.md)。
4. 对模糊词给出项目内解释（[改写表](/checklists/vague-sound-words-rewrite-table.md)＋[校准](/methods/description-calibration-process.md)），写正向特征与排除项。
5. 返修时走 [操作假设链](/methods/perception-to-parameter-operational-hypothesis.md)。
6. 按读者输出 [三种 brief](/templates/three-audience-sound-briefs.md)。

# 输出
- [声音描述卡](/templates/sound-description-field-card.md)（每段一张）
- 三种 brief（共享同一任务与版本）
- 项目词条（已校准的解释）

# 质量门禁
- 每句描述能产生至少一种可听操作并说明成功标准（[质量标准](/principles/good-description-allows-making-and-judging.md)）。
- 研究结论只作条件性依据（[不是固定配方](/principles/music-cue-research-not-fixed-recipe.md)、[复杂度无最优值](/principles/rhythm-complexity-no-optimal-value.md)）。
- 提示词只记录请求（[原则](/principles/prompt-records-request-not-result.md)）；技术测量只回答技术问题。
- 无听音或测量依据时保留"未判定"；建议参数与原片事实分开。

# 核心知识段（精炼）
声音描述把体验目标翻译为可听特征、可操作参数、时间关系与验收条件，不堆叠情绪词、流派词或技术术语；分开描述速度、拍点、节奏、密度与律动，以及音高组织、音色、发音、配器活动、空间与动态；音效以事件、动作、接触关系与起势—持续—转化—终止描述；为"轻、暖、通透、梦幻、高级"给项目内解释并用正向特征与排除项校准。
