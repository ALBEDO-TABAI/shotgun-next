# 分工、交接与长任务续编

单人小任务不必启用这些字段。跨工种、跨会话或连续改稿时，明确谁决定了什么、后面使用的是哪一版。

## 最小交接

`project_id` 项目；`artifact_id` 工件；`revision` 本版；`based_on` 上游工件及版本；`owner` 当前内容负责角色；`status` draft/ready/superseded；正文；`open_questions` 仍影响下游的问题；`changes` 改了哪些ID、谁受影响。这是本包约定，非行业标准。

ready 只表示该角色完成了本次文案检查，不代表用户批准、历史事实核实、媒体生成或真实拍摄完成。上下文已经清楚时可用自然语言表达这些信息，无须强制JSON。

## 谁对什么负责

| 角色 | 负责产物/决定 | 下游要真正使用的内容 |
|---|---|---|
| 编剧 | 事实、因果、场次、角色动机、台词及可改范围 | 导演以它决定可视化，不能暗改事实 |
| 导演 | 观看任务、视点、场面调度、镜头目的、总体风格 | 各工种将选择实现，不各自发明不同故事 |
| 美术 | 场景、道具、材料、空间与视觉世界 | 摄影/角色/制作使用同一空间与材质版本 |
| 角色与服化 | 身份锚点、服装、妆发及状态变化 | 镜头/资产保留身份，动作仍由镜头设计 |
| 摄影 | 取景、光、成像、机位与实现条件 | 制作/后期使用确认的画幅、运动与光色意图 |
| 制片 | 资源、成本假设、排期、限制、试验与取舍 | 导演据约束调整；不把估算写成承诺 |
| 剪辑 | 成片时间、选择/衔接、信息节奏、版本 | 声音和交付跟随实际时间轴 |
| 声音 | 听觉视点、对白/环境/效果/音乐关系 | 剪辑保留同步与可移动范围 |
| 场记/连续性 | 镜间入口/出口状态、Take 结论、提示词版本、可复用经验 | 各岗按同一状态与版本工作；硬连续性问题可拦下批量生成 |
| 提示词编译 | 把已确认设计转成目标工具表达；属导演的交付格式 | 只编译已裁决内容，无创作终审权；未解决冲突显式列出 |

岗位可由同一个人/agent承担。用户明确委托多岗时一次完成；仅委托一岗时提出有依据的修改建议，不能暗中改上游定稿。冲突由对应负责角色解决，涉及用户明确锁定项才请用户决定。写冲突时按“冲突是什么 → 各自保护什么 → 最小兼容方案 → 谁裁决”四句，不提前删掉看似重复的意见。

各角色的边界：表演建议可指出调度妨碍真实行动并给备选，不重写剧情；环境与群演可以丰富世界，不抢走关键表演与构图重点；摄影决定怎么拍，不用炫技改变场次重点；场记可阻止无法剪接的方案进入批量生成，但不能为整齐抹掉真实表演。

## 改动如何传播

每次改稿先找原因属于事实、导演选择、视觉实现还是执行条件；回到有权改变它的位置修复。不要在各岗位复制一份“更正真相”。

上游版本变化后检查依赖是否真的受影响：剧情换结局可能影响多个部门；镜头备注错字未必让全部作废。依赖旧版的产物标明需复核的具体段，不把整套作品一律推倒。

例：场景从白昼改成夜晚 → 导演 S04–S08 时间意图 → 摄影光源/窗口 → 美术可见灯具 → 服化是否仍适合温度与剧情 → 剪辑/声音夜景环境；品牌文案如果没变无须重写。谁改了什么、谁已使用都要可见。

## 多岗逐镜审稿（可选）

只在用户点名各岗意见，或一版提示词即将进入批量生成时启用；默认不打印。参与角色对镜头 1 到 N 逐条写一行：

| 角色 | 镜头 | 结论 | 观察/问题 | 具体建议 | 验收条件 |
|---|---:|---|---|---|---|

没问题也写“通过 / 没问题 / 保持”，这样漏检可见；有问题写可观察症状、只属本岗职责的改法和可复核的验收。导演合并裁决，编译者只改被反馈的字段。参与角色按实际分工选，不强制六岗齐全。

## 上下文胶囊

完成一个阶段或长场景后，保留足以继续的短记录：

```text
当前目标与范围：
已采用工件和版本：
锁定事实/对白/视觉关系：
角色、道具、空间进入和退出状态：
完成的镜头ID；下一段起点：
尚未回收的线索/覆盖项：
本轮改变及受影响内容：
未定问题和下一步：
```

记录只保存决定和可核对状态，不存冗长分析。继续时读取胶囊＋当前场＋必要的上游条目，不能把未读原文摘要当完整事实。需要源证据再定向回读。

## 交接验收

让接手者仅凭交付物说明：做什么、不变什么、从哪一状态开始、结束要是什么、缺少什么。如果回答要靠回看全部聊天，补最小缺项。检查不只是字段写了，还要能指导下一步，避免“有身份表但镜头仍凭记忆写人”。
